# ADR-0002 调度器安装形态（Windows 任务计划 + yaml 派生）

- **状态**：已采纳（427516b / e2bc5f1，2026-09-27 收口）
- **动因**：计划任务长期空跑——`Last Run Time=1999-11-30`、`Last Result=267011`
  （SCHED_S_TASK_HAS_NOT_RUN，从未运行）。

## 决策

`tools/install_schedule.py` 生成的 Windows 任务计划 XML：

1. `<DisallowStartIfOnBatteries>` 置 **false**（原 true 使笔记本在电池上任务从不启动）；
2. 补 `WakeToRun=true` / `RunOnlyIfNetworkAvailable=false`；
3. `<Command>` 用**显式 `sys.executable`**（原写 `<仓根>/cli.py` 依赖 .py 文件关联，
   关联解释器缺依赖 → rc=3 ENV）；
4. `_WEEK_MAP` DayOfWeek 首字母大写（Windows XML 要求 `<Monday/>`，全大写不识别）；
5. **解析外部命令输出优先选语言无关接口**：`schedule verify` 解析 `/xml` 的
   `<Arguments>` 而非 LIST 的本地化标签（zh-CN 输出为 GBK，按 utf-8 解码曾致
   全量假 FAIL——假 FAIL 与真漂移必须分清）。

调度唯一事实源 = `config/schedule.yaml`（P3-1）；手册定时表由
`tools/gen_schedule_doc.py` 反向生成（手改即判据 S4 FAIL）；IDE automation
（automations.db）功能被 schedule.yaml 的 refresh/nfra_weekly 完全覆盖后停用。

## 后果

- 修复后手动触发实测：完整全链 18 步全 rc=0，`Last Result=0`；
- 「zh-CN 外部命令输出按编码探测解码（utf-8 严格 → gbk/cp936 → replace）」成为
  工具链纪律（批 60 固化）。
