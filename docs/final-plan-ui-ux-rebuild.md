# 工作台 UI/UX 复刻 GitHub：最终方案

> 2026-11-05 定稿。基于 13 轮改造（批 160–201）的实测与事故复盘。
> 一句话结论：**过去的问题不是"某处样式没调好"，而是缺一条把基线变成约束的流水线。**
> 本方案的核心，是把「采集 → 规格 → 实现 → 验收」接成闭环，并规定：**没进规格的改动不算完成。**

---

## 1. 十三轮里踩过的坑（按性质分四类）

### A. 方法论（根因，四条）

| # | 坑 | 证据 | 后果 |
|---|---|---|---|
| A1 | **无规格开工** | 13 页 = 1 个模板 × 13；laws/rules/search/release 的 HTML 结构逐字节相同 | 页面里没有 pulls 的筛选组/label/头像，因为模板里从来没有 |
| A2 | **自定验收标准** | `pages_smoke` 断言行高 32 / 边框 #d1d9e0 / 58 项 | 门禁越绿，越只说明离**我的**标准近 |
| A3 | **采集当终点** | `styles-*.json` 除工具自身外零引用；`spec-*.json` 不存在 | 基线与实现之间靠"我的记忆"转述 |
| A4 | **单点测量外推** | 68px 来自登出态 `<header>` 元素；而同一份 `chrome.json` 里记的是 100 | 顶栏做错，且两个数字冲突时我没停下重测 |

### B. 术语与判据（一条，但贯穿全程）

| # | 坑 | 证据 |
|---|---|---|
| B1 | 把「**值取自令牌**」当成「**没有写视觉**」 | 44 条含视觉声明，含硬编码 `font-size:14px`、`font-weight:600`、`font-family`、图表 `palette()` 的 hex |

### C. 平台与依赖（四条）

| # | 坑 | 证据 | 修复方式 |
|---|---|---|---|
| C1 | **类名不存在** | `.Box` / `.Box-row` / `.Truncate` / `.Label` / `.gap-2` / `.color-fg-muted` 在 primer.css 22.3.3 里全部没有（那是 `@primer/react` 组件名） | 先查类名清单再写；页面全部改 `.border/.rounded-2/.border-bottom/.IssueLabel` |
| C2 | **主题属性缺失** | primitives 令牌挂在 `[data-color-mode=light][data-light-theme=light]` 上；缺属性 → 所有 `var()` 落空（边框 0px、颜色黑） | 页面根统一带两个属性 |
| C3 | **安全头自锁** | `X-Frame-Options: DENY` 让新壳的 iframe 全白；58 项断言全绿照样白屏 | 改 `SAMEORIGIN` |
| C4 | **升级引入回归** | octicons 19.42.0 的 `heights[*].path` 是完整 `<path>` 元素，我塞进 `d="…"` → 全站图标乱码 | 生成脚本改为拼整段 `<path>`；重生成 408 个图标 |

### D. 改动治理与测量（四条）

| # | 坑 | 证据 |
|---|---|---|
| D1 | **`!important` 链 + 内联样式** | `.lv-scroll` 先加 `border:1px!important`、再加 `border:0!important`；工具条高度用 `bar.style.height='auto'` 钉死 → 后续 CSS 改不动 |
| D2 | **跨组件批量改** | 为让卡片长出边框，拆掉全局 `.grid > * { border:0!important }` → 所有栅格子元素都开始画边 |
| D3 | **测量假阴性/假阳性** | ① 合成 `dispatchEvent` 不触发搜索（改用 CDP `Input.insertText` 后 319→0）；② 没设 `Emulation.setDeviceMetrics` → 页面只有 477 宽，误判行高 71；③ 截图缩放让我误判"按钮没样式"（实测 24px/1px 边框是有的） |
| D4 | **环境与工具误用** | 探针端口写死 9333 vs 实际 9334；端口无实例时自动 spawn headless（另一 profile）→ 三次"已登录"判成未登录；`.bat` 用 LF 导致 cmd 报错；提交信息含引号触发 pathspec 错误；误建 `tools/edgeprofile` 480 MB |

## 2. 五条硬纪律（不可协商，违者返工）

1. **没有 spec 不动手**——每页先有 `spec-<page>.json`（元素清单 + 尺寸 + 状态 + 断点），才允许写第一行 HTML/CSS。
2. **门禁断言必须来自 spec**——禁止手写"我觉得应该是 32px"；断言值由 spec 提供，失败时打印「基线值 vs 当前值」。
3. **一次一页，禁止跨页复制后不核对**——复制模板可以，但必须逐项跑该页的 spec 比对。
4. **视觉声明只允许 `var(--token)` 或 Primer 类**——禁用字面色值、禁用 `font-size/font-weight/font-family` 字面量；布局属性白名单制。
5. **任何"一致"结论必须附三件事**：测了什么、没测什么、怎么测的。缺一不得宣称完成。

## 3. 流水线（五环，每环有产物与工具）

```
① harvest   采集      gh_ui_harvest / gh_ui_styles / gh_ui_states / gh_ui_overlays / gh_ui_chrome
               ↓     产物：reports/github-baseline/*.json（页面 / 组件 / 状态 / 展开态 / 顶侧栏 / 全量样式）
② spec      派生规格  【待建】tools/gh_spec.py
               ↓     产物：reports/github-baseline/spec-<page>.json（机器可读，进版本库）
③ build     实现      按 spec 写页面，一次一页
               ↓
④ gate      门禁      【改造】gates/gate_pages_spec.py 读 spec 逐项比对
               ↓     失败输出：缺哪个元素 / 基线 32px vs 当前 40px
⑤ visual    视觉回归  tools/gh_ui_visual（同视口截图 → 像素差 + 差异带）
                     产物：并排截图 + 差异率，作为"像不像"的证据
```

**关键约束**：② 由脚本生成，**不由人转述**；④ 只读 spec，**不允许内联常量**；⑤ 每页保存一张并排图，进版本库。

## 4. 阶段计划

| 阶段 | 内容 | 退出标准（可测） | 预估 |
|---|---|---|---|
| **P0 规格基建** | ① `gh_spec.py`：从 harvest + styles 派生 spec（元素/尺寸/状态/断点）② `gate_pages_spec`：读 spec 比对 ③ 并排截图流程 | 一页跑通：spec 生成成功、门禁能报"缺 3 个元素 / 2 处超差"、并排图落盘 | 1–2 批 |
| **P1 一页打样** | `pulls ↔ 政策法规`：按 spec 重建（筛选组、行内 label/头像、相对时间、行菜单、空态/错误态、页码分页） | spec 覆盖率 100%；像素差 ≤ 15%（首屏）；交互元素数 ≥ 基线 80% | 3–4 批 |
| **P2 逐页** | 公司制度 / 文档检索 / 待办 / 留言板 / 监管统计 / 治理审计 / 发布事件 / 指标 / 总览 / 树 / 桑基 / 图谱 | 每页同 P1 口径 | 10–12 批 |
| **P3 壳层** | 顶栏 / 页签行 / 侧栏：**登录态实测**后按数据重做（含选中态、分组、断点折叠） | 三项尺寸与 GitHub 实测误差 ≤2px；与 baseline 截图并排一致 | 2 批 |
| **P4 收口** | 删 legacy、清 `.lv-*`、文档与守卫同步 | 门禁 32+、页面 spec 全覆盖、`legacy.html` 下线 | 1 批 |

## 5. 架构决策：iframe 要不要留（**需你确认**）

| 方案 | 优点 | 缺点 | 判断 |
|---|---|---|---|
| **A. 保留 iframe**（现状） | 隔离好、单页可独立回退、改造快 | **全局交互层被拆散**：筛选面板、行菜单、快捷键、通知无法跨页共享；同源可行但实现别扭 | 只适合过渡 |
| **B. 单页框架**（共享壳 + 模块渲染） | 与 GitHub 同构：一处实现筛选面板/菜单/快捷键；样式与状态统一 | 需要重构 13 页的渲染入口，工作量 ≈ 2–3 批 | **推荐 P2 期间逐步切** |

建议：**P1 打样阶段用 B 的形态**（政策法规页直接做成模块，不再包 iframe），验证后再推广。

## 6. 顶栏 / 页签 / 侧栏：最终规格（**数据待登录态实测**）

已确认的事实与待办：

| 元素 | 已知 | 待实测 |
|---|---|---|
| 全局条 | 登出态 `<header>` 68px；**下面还有 100px 的另一块**（顶部实际 168px） | **登录态**的真实层数与高度（不得沿用 68） |
| 仓库导航条（页签行） | 登出态 52px（`prc-Stack`） | 登录态高度、字号、间距、选中态样式（下划线颜色/粗细） |
| 侧栏 | 宽 256、条目 223×32（早先 `chrome.json`） | 登录态分组结构（分组标题、组间距、折叠行为） |
| 搜索 | 191×32；≤1012 收成 32×32 图标 | 登录态占位文案与快捷键提示 |

> 纪律：**这些数只能来自登录态实测**，不接受"记忆值"和"外推值"。

## 7. 风险与回退

- 旧工作台保留在 `index.html`（`/legacy.html`），切换入口只需改 `_INDEX` 一行；
- 每页独立文件，单页回退不影响其他页；
- 门禁环境缺失时 PASS + skipped（避免"没浏览器就全红"），但需在报告里显式标注 skipped，不得算作通过；
- 视觉回归阈值：首屏 ≤8%（顶栏带豁免，因两侧信息架构不同）。

---

## 8. 需要你先确认的三件事

1. **架构 A/B**：P1 打样是否直接做 B（单页框架，不包 iframe）？
2. **页签选中态**：GitHub 现在用的是哪种指示（下划线颜色/粗细、是否圆角上沿）——我会按登录态实测取，但需要你确认"以实测为准、不按记忆"。
3. **登录窗口**：现在打开的调试实例用的是独立 profile（`reports/_tmp/edgeprofile`），请确认窗口是否可见；不可见则改用桌面启动方式。
