# 列表列宽规范（弹性表格）

> 适用：工作台全部 `.lv-gtable` / `.lv-table` 列表。
> 目的：把"列宽按内容自动分配"从口号变成**可计算、可验收**的规则；
> 三条补充（最大宽度取值、短列双闸、极端长串）写死在这里，避免每次实现各写一套。

---

## 0. 三条硬性补充（2026-11-04 确认）

### 0.1 「整表最大宽度」取值

```
表宽 W = min(容器可用宽度, 1200px)
```

- **1200px 是上限**，超过就居中留白，不随屏幕无限铺满（2K/4K 屏不允许把"说明"列拉到 900px）。
- 容器可用宽度 = 内容区宽度 − 左右各 16px 内边距（`padding: 0 16px`）。
- 屏幕 < 1200 时按容器宽度收缩，此时**不出现横向滚动**：所有列按 §2/§3 重新分配。
- 例外：表格内存在 `word-break: break-all` 的极端长串列时，也不允许撑破 W —— 该列按 §3 固定上限。

### 0.2 短列判定：字符数阈值 **与** 像素上限「双闸」

只有**同时满足**才判为短列：

| 闸门 | 阈值 | 为什么需要 |
|---|---|---|
| 字符数 | 该列**最长内容**的全角当量 ≤ **12**（半角按 0.5 计：ASCII 1 字符 = 0.5 全角） | 防止"一行 30 个 `i`"这类窄字母骗过像素闸 |
| 像素 | 该列**最长内容实测宽度** ≤ **160px**（14px 字号下） | 防止"12 个汉字"被判为短列（12×14=168 > 160） |

- 全角当量：`full = Σ(汉字/全角标点 ? 1 : 0.5)`；阈值 12 全角 ≈ 6 个汉字宽。
- 实测宽度用 `canvas.measureText` 或临时 span 量，**不按字符数估算**（字体不同差很多）。
- 任一闸不通过 → 归为长列，走 §3。

### 0.3 极端长串（hash / URL / 无空格 ID）不参与权重

判定：单行连续字符 ≥ **24 半角** 或 ≥ **12 全角** **且** 不含空格。

处理：

```
列宽 = 固定上限 200px（不按权重分配）
text: word-break: break-all; white-space: normal;
该列**不计入** §3 的权重分母
```

理由：sha256（64 个半角）会把"平均字符长度"整体拉高，导致相邻列被无理由压窄；
把它从权重里摘出去，其余列按真实语义分配。

---

## 1. 列的分类

| 类别 | 判定 | 处理 |
|---|---|---|
| **短列** | §0.2 双闸都通过 | 按内容自适应，居中，有上限 |
| **长列** | 双闸任一不通过 | 瓜分剩余空间，按权重 |
| **极端串列** | §0.3 | 固定 200px 上限 + `break-all`，不参与权重 |

## 2. 短列宽度

```
need = max(表头文字宽, 该列最长内容实测宽) + 24（左右各 12 内边距）
w_short = clamp(need, 64, 220)
```

- 下限 64：再短也要能放下 8 个半角字符 + 内边距；
- 上限 220：防止个别超长短文本（如 20 个汉字的"类型"）把列撑爆；
- 超过上限时**该列自动转为长列**（不截断），避免"上限 + 省略号"造成看不全。

## 3. 长列宽度（按平均长度加权）

```
W_remain = W − Σ w_short − gap × (n − 1)
weight_i = avgChars_i（全角当量，去掉 §0.3 的极端串列）
w_long_i = max(160, W_remain × weight_i / Σ weight)
```

- `gap = 8px`（列间距，与 `.lv-row{column-gap:8px}` 一致）；
- `min 160`：低于 160 会把文字挤成一条线；触底后剩余空间再按权重二次分配；
- 长列 `white-space: normal; word-break: break-word`，**允许换行、禁止省略号**；
- 短列 `white-space: nowrap; text-overflow: ellipsis`（短列超限已转长列，正常不会触发）。

## 4. 行高与密度

- 宽松：`min-height: 65px`；紧凑：`min-height: 38px`（沿用现有 `lv-compact`）；
- 换行导致的行高增长由内容决定，**不设 max-height**（不裁剪）。

## 5. 验收方法（可执行）

对比器已能给出每列实际宽度；规范验收看三条：

1. 表宽 ≤ 1200，且左右留白相等（居中）；
2. 任一列的 `实际宽 − 规范宽` 的绝对值 ≤ 24px；
3. 不存在 `scrollWidth > clientWidth` 的单元格（即无截断）。

```bash
python -m tools.gh_ui_compare --mode full --target "http://127.0.0.1:8765/#worklist"
# 或直接量列宽：
python -m tools.gh_ui_states     # 已采集的列宽/字号基线可作对照
```

| 反例 | 现状 | 规范要求 |
|---|---|---|
| 6 列等宽 `1fr × 6` | 附件表 177/177/177/177/177/177 | 按 §2/§3 分配（短列 66–120，长列 380+） |

| 64 字 hash 参与权重 | sha256 列与"文件名"等分 | 按 §0.3 固定 200、不参与权重 |
