## 2. 五条硬纪律

1. **没有 spec 不动手**：每页先有 `spec-<page>.json`（元素 + 尺寸 + 状态 + 断点）。
2. **门禁断言来自 spec**：禁止"我觉得应该 32px"；失败输出「基线值 vs 当前值」。
3. **一次一页**：复制模板可以，但必须逐项跑该页 spec 比对，不跑不算完成。
4. **视觉只许令牌或 Primer 类**：禁字面色值、禁 `font-size/font-weight/font-family` 字面量。
5. **"一致"必须附三件事**：测了什么、没测什么、怎么测的。

### 3.2 间距

`4 / 8 / 12 / 16 / 24 / 32`（4 的倍数）。栅格 gap **16**；卡片 padding **16**；表格单元格横向 **8**。

### 3.3 圆角

`6`（按钮/卡片/输入）、`12`（面板/弹层）、`2em`（标签）。

### 3.4 字体、字号与行高【实测 2026-11-05】

**字体族（此前完全未采，是观感差异的主因）**：

```

我们  : -apple-system, BlinkMacSystemFont, "Segoe UI", ...
```

同一段 14px 文字，两者字宽相差 5~10%——这直接解释了"数字对齐、观感不对"。

| 用途 | 字号 / 行高 | 备注 |
|---|---|---|
| 正文 / 表格 / 控件 | **14 / 21** | 比例 1.5，**不是 20** |
| 次要信息 | 12 / 18 | — |
| 页面标题 h1 | **24 / 36** | 实测 "Commits" 94×44 |
| 区块标题 | 14 / 21 | padding `4 0` |
| KPI 数字 | 22 / 28 | 【推断】 |

`box-sizing: border-box` **全局**（实测 body 与所有采样元素均为 border-box）。

### 3.5 阴影

面板：`box-shadow: 0 0 0 1px rgba(31,35,40,.08), 0 8px 24px rgba(66,74,83,.12)`【推断，需与基线核对】。

## 4. 全站骨架与断点

### 4.1 结构

```
┌──────────────────────────────────────────────────────────────────────┐
│ [logo 28] 合规工作台   [搜索 191×32]                旧版  [头像 32]   │ 全局条
├──────────────────────────────────────────────────────────────────────┤
│ 总览 项目结构 数据流转 指标 待办闭环 政策法规 公司制度 关系图谱 …     │ 仓库条（13）
├──────────┬───────────────────────────────────────────────────────────┤
│ 本页导航 │ 内容区                                                     │
│ 256      │  ┌ 搜索行（整行）                                        │
│          │  ├ 工具条（左状态 / 右筛选+密度）                        │
│          │  ├ 表格（无外框，行分隔）                                │
│          │  └ 分页（表格外）                                        │

```

### 4.2 尺寸【实测/待实测】

| 项 | 现行 | GitHub（**登录态实测 2026-11-05**） | 差额 |
|---|---|---|---|
| 顶部总高 | 108（68+40） | **100**（52 + 48） | +8 |
| 全局条 | 68 | **52** | +16 |
| 仓库条 | 40 | **48** | −8 |
| 页签项 | 32 高 / padding 0 10 | **32 高 / padding 6 8 / 字号 14 / radius 6 / 间距 8** | 内距差 |
| 页签选中 | 2px `#0969da` 下划线 + 600 | **`::after` 2px `#fd8c73`（橙）× 字重仍 400** | 颜色与字重都错 |
| 侧栏 | 256 / 条目 240×32 | 256 / 条目 223×32（Code 页文件树） | 条目 +17 |
| 内容宽 | 1200 居中 | 页面级 1280 | 保持 1200 |

> **此前"68px 全局条"是外推误差**：68 是登出态 `<header>` 元素盒，登录态顶区实为 52 + 48 = 100。
> 该错误已修正；本表数值全部来自 2026-11-05 登录态实测（见 §4.4）。

### 4.3 断点【实测自基线 responsive.json，需复核】

| 宽度 | 行为 |
|---|---|
| ≥1200 | 侧栏 256 + 三列卡片 + 表宽 ≤1200 |
| 1012–1199 | 侧栏 256 + 两列卡片 |
| 768–1011 | 侧栏收 64 图标条；顶栏搜索收图标；卡片单列 |
| <768 | 侧栏抽屉；表格降级为卡片行 |

**硬约束**：任何宽度不出横向滚动；768 以下搜索**不隐藏只收图标**。

### 4.4 登录态实测记录（2026-11-05，1440×900）

采集方式：Edge 156 `--remote-debugging-port=9334`，已登录账号，页 `notepad-plus-plus/issues`。

| 元素 | 实测 |
|---|---|
| `header-wrapper` 总高 | **100**（0..100） |
| 全局条 `prc-Stack` | **52**（0..52） |
| ├ 菜单按钮 | 32×32 @ x=16 |
| ├ logo / home | 32×32 @ x=60 |
| ├ 仓库面包屑 | 126×32 @ x=100；125×32 @ x=241 |
| ├ **快速搜索** | **191×32** @ x=849 |
| └ 右侧（Copilot/通知等） | 26~50×**32**，间距 8 |
| 仓库条 `nav` | **48**（52..100） |
| ├ 页签项 | **高 32**，top=60（上内距 8） |
| ├ 页签内距/字号/圆角/间距 | `padding 6px 8px` / **14** / 6 / **8** |
| ├ 页签宽（Code/Issues/Pull requests…） | 73 / 122 / 157 / 85 / 87 / 90 / 68 / 201 / 90 |
| └ **选中态** | `::after` **高 2px、色 `#fd8c73`（橙）**、贴底 0；**字重仍 400**，无 boxShadow、无 borderBottom |

**结论（施工口径）**：顶栏 52 + 仓库条 48 = 100；页签 32 高、`padding 6 8`、字号 14、间距 8、选中为**橙色 2px 下划线**且不加粗。

### 4.5 登录态「完整样式链」实测（2026-11-05，补上缺失的 90%）

> 采集工具：`tools/gh_ui_full.py`（按语义角色取代表元素，每元素抓**全部 computed style + 6 层祖先链 + 文本宽度**）。
> 产物：`reports/github-baseline/full-{issues,pulls,commits,contributors}.json`。

**① 字体与行高（此前完全没采，是"数字对、观感不对"的主因之一）**

| 项 | GitHub 实测 | 我们现行 | 影响 |
|---|---|---|---|
| font-family | **`"Mona Sans VF", -apple-system, BlinkMacSystemFont, …`** | `-apple-system, BlinkMacSystemFont, "Segoe UI", …` | 字形、字宽不同 → 同样 14px 文字宽度差 5~10% |
| font-size / line-height | **14 / 21**（比例 1.5） | 14 / 20 | 行高少 1px，累加到 30 行差 30px |
| box-sizing | **border-box**（全局） | 混用 | 同 32px 高，内容区差 2~4px |
| 根字号 | 16 | 16 | 一致 |

**② 搜索框的真实构成（难点：视觉在外层，输入框本身是裸的）**

```
外层 DIV.Box_2 (1047×30, 边框与圆角在此)
  └ INPUT (1047×30, padding 0, border 0, bg 透明, font 14/21)
```

实测：`input` 的 `padding/border/background` 全为 0/透明，**高度 30 由外层 Box 决定**。
→ 我们要复刻时必须把 padding 与边框放在**包装层**，否则 30 会变成 30+2。

**③ 按钮构成（公式已用真实元素验证）**

| 类型 | 实测 | 构成 |
|---|---|---|
| 文字按钮（Author） | **89×32** | padding `0 12` + border 1px（**颜色透明**）+ 文字 |
| 文字按钮（Labels） | 85×32 | 同上 |
| 搜索按钮 | 191×32 | padding `0 12` + border 1px `#d1d9e0` + radius 6 |
| 图标按钮 | **32×32** | padding 0 + border 1px + radius 6 |
| 小图标按钮 | **20×32** | padding `4 6` |
| 徽标 Counter | **37×18**「2.9k」 | 文字 22.6 + `12` + `2` = 36.6 ≈ 37 ✅ |

> 结论：**宽 = 文字 + 24 + 2**（padding 12×2 + border 1×2），高固定 32；徽标高 18、padding `2 6`、radius 20。
> 另：筛选按钮（Author/Labels…）**边框颜色是透明的**——看起来无边框，但占据 2px 宽度。

**④ 侧栏条目 / 行 / 标题**

| 元素 | 实测 | 构成 |
|---|---|---|
| 侧栏 ActionList 项 | **223×32** | padding `6 8` + radius 6 + font 14/21 |
| commits 行 | 1237×71 | `display:grid` + border-bottom 1px + radius 6 |
| 页面标题 h1 | 94×44（"Commits"） | font **24/36** |
| 区块标题 | 1239×29 | padding `4 0` + font 14/21 |

**⑤ 这条数据解决了什么问题**

用户指出的"采集粒度不够"——此前每控件 8 个属性，导致：
- 只知道按钮 90 宽，不知道 90 = 文字 64 + 24 + 2 → 抄了 90 却做出 88/92；
- 只知道行高 32，不知道 32 = 6+21+... → 自己排成 30 或 34；
- 不知道字体族不同 → 文字宽度天然差 5~10%。

现在这五项（font-family / line-height / box-sizing / padding+border 归属层 / 祖先背景）全部有实测值，可直接施工。

## 5. 通用组件规格

### 5.1 搜索行

| 属性 | 规格（登录态实测） |
|---|---|
| 位置 | 列表上方独占一行，宽 = 内容宽 |
| 高 | **30**（1047×30；现行 1088×32） |
| **结构** | 外层容器承载边框/圆角/高度；**内层 `input` 的 padding/border/bg 全为 0/透明**（实测） |
| 图标区 | 右侧独立 **28×28**，底色 `--bgColor-muted`，左 1px 分隔线，圆角 `0 6 6 0`（我 30×30 / 容器 1090，差 2） |
| 字体 | 14 / 21，`border-box` |
| 聚焦 | 单层 `outline: 2px solid #0969da`，无 shadow |
| 行为 | 输入即筛（前端）+ 回车应用（服务端）；二者取**交集**；筛选后搜索词保留 |
| 状态 | default / 聚焦 / 有值 / 禁用（只读模式） |

> 复刻要点：把 padding 与边框放在**包装层**。若加在 input 上，30 会变成 32——这是"同一尺寸观感不同"的典型来源。

### 5.2 工具条

| 属性 | 规格 |
|---|---|
| 分组 | 左：状态开关；右：筛选按钮组 + 密度 |
| 布局 | flex；`.sp{flex:1}` 占位；允许 `wrap`；**不裁切** |
| 高 | 自适应（最小 48） |
| 与搜索关系 | 搜索独占第一行（`flex:0 0 100%`） |

### 5.3 表格

| 项 | 规格 |
|---|---|
| 外框 | 无（`table`/容器 0px） |
| 表头 | 上 1px + 下 1px `#d1d9e0`；无底色；字重 600；字号 12 |
| 行 | 每行 1px 底边，末行 0；行高 32（行内有按钮时 34） |
| 列宽 | 短列 `clamp(need+24, 64, 220)`；长列按平均长度加权 min160；极端串（无空格 ASCII ≥24）固定 200 且不计入权重；总宽 ≤1200 |
| 末列 | 动作列保底 72（图标组 148） |
| 排序 | 列头可点，显示 ↑/↓；同时仅一列生效 |

### 5.4 分页

| 项 | 规格 |
|---|---|
| 位置 | 表格容器**之外**，下方 16 |
| 形态 | `[上一页] 1 / N [下一页]`（GitHub 为页码组 + 每页条数，差异登记） |
| 状态 | 首页禁用「上一页」；末页禁用「下一页」；加载中禁用两者 |

### 5.5 按钮

| 项 | 规格（登录态实测） |
|---|---|
| 尺寸 | 宽 = **文字 + 24 + 2**；高 **32**（行内 24/28） |
| padding | `0 12px`；`min-width: 0` |
| 边框 | 1px；**筛选类按钮边框色透明**（Author 89×32 / Labels 85×32，看起来无边框但占 2px） |
| 图标按钮 | **32×32**（padding 0）；小图标 **20×32**（padding `4 6`） |
| 徽标 Counter | 高 **18**、padding `2 6`、radius **20**（37×18「2.9k」= 22.6+12+2） |
| 字体 | 14 / 21 |
| 变体 | default（白底 1px 边）/ primary（绿底白字）/ danger / invisible |
| 状态 | hover 底色 `#f3f4f6`；active 下沉；disabled 50% + `not-allowed` |

> 验证方式：用 Range 量文字宽，再用 `按钮宽 − 文字 − padding×2 − border×2` 求残差；实测残差 0.4px（四舍五入），公式成立。

### 5.6 筛选面板

| 项 | 规格 |
|---|---|
| 尺寸 | 宽 320；行高 32；padding 8；圆角 12；边框 0 + 环阴影 |

## 6. 逐页规格

> 每页固定八段：**定位与对标 / 数据源 / 列定义 / 控件与动作 / 交互流程 / 状态与异常 / 设计图 / 验收清单**。

### 6.1 总览 `overview` ↔ `graphs/contributors`

**定位**：一屏看清"系统现在健康吗、卡在哪、数据新不新"。

**数据源**：`GET /api/overview` → `run_health` `gate_status` `worklist` `freshness` `storage` `alerts`。

**区块与列**

| 区块 | 内容 | 字段 |
|---|---|---|
| KPI 行 | 4 格：门禁通过 / 待办未处置 / 链步成功 / 存储占用 | `gate_status.passed,total` / `worklist.open_total` / `run_health.counts.ok` / `storage.total_bytes` |
| 运行健康 | 键值表 4 行 | `run_id` `steps` `total_elapsed_s` `run_at` |
| 链步状态分布 | 环形图 | `run_health.counts`（为空时用 `step_statuses[].rc` 兜底） |
| 门禁与待办 | 键值表 3 行 | `passed/total`、`failed[].descr`、`open_total` |
| 数据新鲜度 | 键值表 2 行 | `stale_count`、`by_status` |
| 存储 | 键值表 2 行 | `total_bytes`、`ratio{raw,cleaned,clauses,governance_db,external_models}` |
| 告警 | 有/无两种呈现 | `alerts[]` |

**控件与动作**

| 控件 | 动作 | 说明 |
|---|---|---|
| kind 跳转按钮（6 个） | `act:open-worklist?kind=` | 文案含计数，如「relevance_boundary 217」 |
| 卡片标题区 | 无交互 | — |

**交互流程**：进入 → 拉 `/api/overview` → 渲染 7 区块 → 点 kind → 跳 `#worklist` 并带 kind 过滤。

**状态与异常**
- `available=false` → 整页空态 + 原因文案；
- `counts` 只有 `unknown` → 用 `step_statuses[].rc` 统计（已实测：35 OK / 7 其他）；
- `storage.ratio` 是对象 → 渲染为 `raw 3.9% · cleaned 10.28% · …`（不能直接 String）。

**设计图**

```
┌─────────────────────────────────────────────────────────────┐
│ 总览                                  最近运行 2026-11-05 06:44│
├─────────────────────────────────────────────────────────────┤
│ [门禁 29/31] [待办 319] [链步成功 35] [存储 4.2 GB]          │ 通栏
├──────────────┬──────────────┬───────────────────────────────┤
│ 运行健康      │ 链步状态分布  │ 门禁与待办                    │
├──────────────┼──────────────┼───────────────────────────────┤
│ 数据新鲜度    │ 存储          │ 告警                          │
└──────────────┴──────────────┴───────────────────────────────┘
```

**验收清单**
1. 7 个区块全部有数据或明确空态；
2. KPI 4 格数值与接口一致（抽样 1 个）；
3. `counts` 为空时不出现「—」（走 `rc` 兜底）；
4. 三列栅格 gap=16、卡片 border 1px `#d1d9e0`、radius 6；
5. 点 kind 按钮跳转并生效过滤。
