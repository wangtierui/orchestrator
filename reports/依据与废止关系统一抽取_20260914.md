## 2. 三类关系（用户要求明确列明）

| # | 类别 | 筛选口径 | 实测（2026-09-14 全量） |
| :-- | :--- | :--- | ---: |
| 1 | **监管文件的依据关系与废止关系** | `src_kind=regulatory` | **2007** |
| 2 | **内部制度的依据关系与废止关系** | `src_kind=internal ∧ dst_kind=internal` | **19** |
| 3 | **内部制度与监管文件之间的依据关系** | `src_kind=internal ∧ dst_kind=regulatory` | **126**（其中纯依据边 **79** → `cross_basis.jsonl`） |

## 3. 设计要点（相对参照实现的适配，逐条可审计）

1. **七层结构保留**：`RelationConfig`（词表全外置，换领域只换配置）→ 工具函数 → 三个 dataclass →
   `RelationExtractor`（六类主模式 + 三类辅助）→ `AliasResolver` → `RelationPipeline` → CLI/自检。
2. **归一收口到项目 SSOT**：名称归一用 `norm_title_strict`（保守层，与归属表精确匹配同语义）、
   文号归一用 `norm_docno`；**不另造归一**（参照实现自带一份）。
3. **枚举收口**：`basis_type` 由中文「实体法律依据/程序批准依据」改为受控英文
   `substantive`/`procedural`（项目纪律：受控值统一小写英文），`scope`→`whole/partial/attachment`、
   `action`→`repeal/invalidate/cease/inapplicable/cancel`。
4. **文号形态扩展**：支持法规库形态（`中华人民共和国国务院令第262号`、`令2011年第N号`）与
   半角方括号（`[2019]19号`）。
5. **否定/未生效排除（新增）**：`拟废止/建议废止/征求意见/草案/待废止` 语境不计废止关系
   （真实语料中 `replacement_document` 邻近文本常含"拟"，参照实现无此防护 → 会误报）。
6. **来源偏移 `offset`**：每条关系记录正文命中位置（参照实现只有片段），便于审计定位。
7. **未解析不臆造**：目标无法定位时保留原文名称 + `matched_by="unresolved"` + `confidence=0`，
   与 drafter `verify_regulatory_citations` 的"禁止臆造"同纪律。
8. **程序性依据收紧（实测反例驱动）**：参照实现用 `经[\u4e00-\u9fa5]{2,20}?同意/批准` 最短匹配，
   实测产出 `批准或者未按照`、`依法`、`部门负责人` 等非机关噪声；现要求**法定机关后缀**结尾
   且**不含连接虚词**（全量关系数因此由 82（30 份样本）降噪到 38）。

## 4. 实体解析：两级口径（这是数据可信度的核心）

关系目标的解析分两级，**字段显式区分**，避免"解析率"歧义：

| 字段 | 语义 | 用途 |
| :--- | :--- | :--- |
| `dst_ref` | **强实体**：`RFN`（归属表 1060 条）/ `IPN`（内部主索引 878 条） | 可直接 join 归属表、底座、发布件、门禁 |
| `dst_key` | **弱引用**：cleaned `dedup_key`（4043 份采集全集） | "已采集但未登记 RFN"的补登记线索 |
| （皆空） | `unresolved` | 名称未在语料中定位（多为《民法典》等未入库法规）→ 保留原文供人工/法规库补全 |

**匹配顺序**（严 → 宽）：`docno_exact` → `docno_sig` → `title` → `title_contains`；
**跨域（内部→监管/内部）一律 `strict`（禁 `title_contains`）**——实测
`中华人民共和国发票管理办法`（法规）会被 contains 误配到内部制度 `…发票管理办法`，把法规当制度。

实测结果（全量 2152 条）：

| 口径 | 值 |
| :--- | ---: |
| 强实体（`dst_ref` 非空） | **25.7%** |
| 语料定位（含弱引用） | **52.7%** |
| 未解析 | 1018（47.3%） |

> 未解析者集中在"被依据的是法律/行政法规"（如《中华人民共和国银行业监督管理法》《民法典》），
> 而归属表只覆盖 **1060 份与人寿保险业务相关的文件**——这是**客观交集限制**，不是抽取缺陷。
> 该部分数据对下游仍有价值（名称 + 出处片段 + 源实体），并可经法宝库/人工补登后自动升级为强关联。

| `internal_policy_drafter` | `build_draft_clause_view.py` 新增「§2 依据与废止关系」段：本制度作为**源**（依据/废止了他文，含跨域）+ 作为**目标**（谁废止了本制度 → 修订起草时须核对） | 素材增强 |

> 说明：`merged_view.associated_rfns`（**引用**面，制度引用了哪些监管文件）与本次**依据/废止关系**

> 两者关系：依据/废止关系 ⊂ 引用关系（前者要求"触发词 + 动作词/废止动作"成立）。

## 8. 局限与后续

1. **未解析率 47%**：受归属表覆盖范围限制（非抽取缺陷）。提升路径：① 目标命中 cleaned 全集时
   补登 RFN（现已有 `dst_key` 线索）；② 接入法宝库补全法律/行政法规实体。
2. **附件内清单**：`见附件` 的废止清单未解析（当前只发 `warnings`）。已提供
   `--with-attachments` 开关把附件正文并入抽取，但清单条目的结构化仍在附件对象轨，建议后续专项。
3. **条款级关系**：本文档级关系不含"第 X 条依据第 Y 条"的条款级引用（由 `build_clause_graph` 承担）。
4. **收敛未完**：上表 §6 三处旧实现待分批收敛。
5. **analysis 交付库**：新报告暂未登记进 `tools/gen_analysis_deliveries.py`（该生成器为内联 15 份报告的写法，
   改动风险高）；如需纳入 2.1.x 体系，建议单独立项。
