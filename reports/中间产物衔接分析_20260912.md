## 一、全链路产物地图与检查方法

```
[阶段一采集] raw 五源 json ──▶ [阶段二清洗] cleaned csv+jsonl ──▶ clean_index ──▶ clauses jsonl/md
                                      │                                              │
                                      ▼                                              ▼
[阶段三分类] 归属表/主题表 ──▶ base ──▶ final ──▶ matched ──▶ citerefs ──▶ 明细表 ──▶ upper/clause_graph/报告
                                      │                        ▲
[阶段四制度] processed(IPN) ──▶ index/align ──▶ merged_view ──┘（gate_citations/draft 素材）
                                      │
[阶段五内控] (待建) 监管要求清单 × 制度条款 × EAST 统计 ──▶ 检视表/缺口/整改
         跨链路：时效字段族(state→归属表→base→cleaned→bridge→mirror) · 状态文件族 · 连接键
```

**检查六维度**：① 数据结构 ② 接口定义 ③ 字段完整性 ④ 格式规范 ⑤ 依赖关系 ⑥ 传递方式。
**判定口径**：对每个产物比对「生产者输出」与「消费者实际读取」，不匹配即立项；目标态为**全链路唯一事实源（SSOT）**。

**实测基线**：clean_index latest：gov/mof/pbc/supp=20260909、nfra=20260910，全源 `sha256=null`；归属表 1059 行；state 2975 条（09-11 23:46 写入）；mirror 仍为 08-29 版（滞后 13 天）；bridge 09-10 17:41。

## 五、核实说明与结论

**本轮二次核实**：M-02（正则实测）、M-05（签名比对）、M-06（index primary_theme 0/107 实测）、M-07（目录不存在）、M-08（零调用实测）、B-04（index sha=null 实测）、J5（mirror 滞后 13 天实测）。

**结论（5 行）**
1. 全链路"声明层"基本对齐（39 列/8 键/CLAUSE_* 逐字一致），但"**传递层**"存在三类系统性断裂：同步动作缺失（state→归属表→base→cleaned 皆需人工或半自动）、覆盖/新鲜度无信号（matched 缺 39、merged 陈旧、mirror 滞后皆无告警）、键与格式多义（5 套归一、4 种日期、2 套空值约定）。
2. 高价值产物"生产即损坏"点集中：OCR 校正丢弃、index 主题列剔除、upper 统计失效、supp 登记静默失败——均可使下游静默消费劣质数据。
3. 规划 2.1/3.2 交付（14+6 项）当前按结构产出率 ≈0-30%，根因是"底座→报告→制度"三段不在编排内（登记无 CLI、classify 断链、报告手工）。
4. 第四步内控 4.1 已有 ~30% 可用底座（条款 JSON+RFN 关联）；4.2 依赖的 EAST/统信"监管统计"在仓内不存在，属规划级待建。
5. 目标态：以本报告 §三 SSOT 矩阵为收敛基准——**state=核验过程 SSOT / 归属表=业务权威 / 各投影只读+单写口+投影后重建索引**，配合六维度逐项修复（P0 11 项先行）。
