## 四、W-N 补口：一处**真实的静默缺口**（批 52 遗留）

**发现（途中新识别的缺陷）**：批 52 的补丁脚本对 `table_recovery.py` 同时下发两条规则（③⑧ 注入 + ⑮ 复用），
其中 ⑮ 规则因**缩进**导致整文件 `ast.parse` 失败 ⇒ 脚本按纪律**跳过写盘** ⇒ **③⑧ 的 meta 注入随之被整体丢弃**
（`excel_matrix` 侧的备注登记在、但**从未被读出写进记录** ⇒ ③⑧ 实际处于"半接线"状态，且单测未覆盖该接线）。

**修复**：以稳健锚点（`wb_struct = process_workbook_bytes(`）重新注入，并把 ⑦ 一并纳入：
`meta.truncated`（矩阵截断）／`meta.header_capped`（表头上限）／`meta.formula_cells` + `formula_values="cached"`（公式缓存依赖）。

**实证**（真实调用链 `structured_table_fields`，含公式的工作簿）：
```
实测 meta = {"formula_cells": 1, "formula_values": "cached"}   ⇒ ⑧ 生效 ✓
```
**教训（已写入记忆）**：批量补丁脚本"一条规则失败即跳过整个文件写盘"的策略是**正确**的（避免半成品），
但**必须回读核对**"报告 ok 的规则是否真的落盘"——批 52 的 ⑮ 失败掩盖了同文件 ③⑧ 的丢失。
