## 二、变更摘要

### ① D1 · 实际部署（含决定性约束）

- **已安装**：`umap-learn 0.5.12`、`hdbscan 0.8.44`（P1-5 依赖；无 torch）→ 探测 `available: ["hdbscan", "umap"]` ✓
- **受带宽限制未安装**：`hanlp` / `text2vec` / `bertopic`（均依赖 torch）。

> **实测约束**：pip 自报 `llvmlite 41.9MB 耗时 14m22s ≈ 48.7 kB/s`。据此，torch CPU wheel
> （≥200MB）需 **≥75 分钟**，hanlp 首用模型（1.2GB）需 **≥7 小时** → 在本次会话**不可行**。
> 结论：**P1-1/P1-2/P1-3（text2vec/bertopic/hanlp）的部署受网络带宽阻塞**；`preflight` 的
> `deps` 闸门因此**客观不过**（未装 hanlp/ltp）。此为环境约束，**如实登记而非绕过**。

### ② D3 · 遗留④：许可**自动核验取证**（10 项）

新增 `semantic_tools --verify-licenses`（现查 **PyPI / GitHub 权威元数据**，取证与拍板分离：
只读取证，`--apply` 才写清单；每次可重复执行，防空口登记随版本静默过时）。

| 工具 | SPDX | 来源 |
|---|---|---|
| aprcoie / bertopic / signalgraph | **MIT** | GitHub |
| hanlp / text2vec | **Apache-2.0** | GitHub |
| hdbscan / umap | **BSD-3-Clause** | GitHub |
| **paradedb** | **AGPL-3.0** ⚠️ | GitHub |
| ltp | **未声明**（license=null） | GitHub |
| weknora_docreader | **自定义**（NOASSERTION/Other） | GitHub |

- **`paradedb` 风险注记**：AGPL-3.0 是**强 copyleft（含网络服务条款）** → 除与"单机零服务依赖"
  冲突外还带**许可传染**风险；登记 `risk_notes` 并**不建议随仓分发**。
- **`ltp` / `weknora_docreader` 保持 pending 并带 `pending_reason`**（未声明 / 须读原文）；
  判据 U 新增强制：**pending 须有原因**、`pending_reason` 不得指向非 pending 项、
  `risk_notes` 须指向已定义工具（三向校验，防"待核"长期悬挂）。

### ③ D4 · 遗留③：`--preflight` 入链（统一调度）

- **用途分离**：`--preflight`（判定，rc 反映可否启用）/ `--preflight-report`（**披露，恒 rc=0**）。
  理由：P1 **未启用是合法状态**，披露步骤若因"不可启用"而 FAIL，会把"尚未启用"误报为"链路故障"。
- 新增 `semantic:preflight` 步骤（`run_production_refresh` 阶段 6.6b），`STEP_ORDER` 25 → **27**
  （此前 N-114 已把 quarantine:triage 计入为 26）；判据 R `declared=wired=27`；步骤守卫测试 27。

### ④ D5 · 遗留②：`rivals` 细分 —— **发现维度无信息量，改判为不变式**

实测：418 行"仅窗口"命中**全部 `rivals = 0`**。**根因**：`rivals` 统计的是"目标条款表内**其他**候选"，
而"唯一命中才填"本就要求目标表内**唯一** → `rivals` **结构上恒为 0**。
**正确处置**：把该维度改判为**不变式校验**（`rivals > 0` 即"唯一性守卫被破坏"→ 报警，应为 0）；
弱证据的真实分档**仍以距离**（≤40 / 40–80 / >80）为准。已同步基准渲染。

### ⑤ D2/D6 · 离线预置与端点（按部署现状登记）

- 无外部权重的工具（hdbscan/umap）`offline_ready=None`；torch 系的离线预置方案已在清单
  `offline_env`（`HANLP_HOME`/`SENTENCE_TRANSFORMERS_HOME` 等），待其可安装后经 `--preflight`
  自动校验。
- 服务型端点（docreader `localhost:50051` / ParadeDB DSN）三态探测已就绪，部署后即显现。

## 三、规范对齐

| 规范 | 落实 |
|---|---|
| 不重复造轮子 | 许可核验复用 `_http_json` 单一网络入口；互证复用 `dst_article_candidates` |
| 唯一事实源 | 许可状态**唯一**于 `license_registry`（取证工具只写它）；工具清单仍是探测/核验的**唯一数据源** |
| 数据一致性 | 许可"取证"与"拍板"分离（只读 → `--apply`）；pending 必须带原因 |
| 统一调度 | `semantic:preflight` **入链**（披露步骤），`STEP_ORDER` 与判据 R 同步 |
| 元数据管理 | 许可从"人工待办"升为**可重复执行的取证**（含来源 URL 可追溯） |
| 数据处理节点入链 | 新步骤为**只读披露**（不动数据），符合既有 `retention:plan` 同款口径 |
