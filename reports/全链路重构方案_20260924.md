# 全链路重构方案（完整版）

> 基于 `https://github.com/wangtierui/orchestrator` 仓库实际代码，经多轮论证后固化。所有内容来自已获取的源码事实，不臆断。

# 第一部分：现状诊断

## 1.1 架构总览

当前项目为**脚本编排型工程**（无常驻服务、无 Web 框架），核心入口为 `tools/run_production_refresh.py`（唯一主链编排器），命令门面为 `cli.py`（12 个顶层子命令）。主链严格按阶段顺序执行，覆盖从五源采集到分析交付的 22 个阶段。

## 1.2 三大结构性缺陷

**缺陷 1：水位声明的结构性恒 FAIL 风险**

`run_production_refresh.py` 的 `GOV_ARTIFACTS` 中，`analysis:manifest` 只观察、不声明依赖——因它在阶段 6.8 生成而门禁在阶段 6 运行。若声明 `inputs`，从第二次运行起阶段 6 处的“声明版本”必然是上一轮的。

**缺陷 2：cleaned 水位的瞬时版本作废**

`clauses:{src}` 不声明 `cleaned:{src}` 上游，因 `apply_timeliness_to_cleaned` 会在阶段 2 双轨回写 cleaned，届时阶段 1 的 cleaned 版本作废。

**缺陷 3：链外节点与主链的衔接缺乏统一契约**

`supp` 本地摄取、`internal index/align/reocr`、`RFN 补登`、`wiki/llm_wiki 同步` 等链外节点，没有统一的“条件触发 + 失败降级 + 人工断点显式化”契约。

## 1.3 目录分类问题

| 问题 | 表现 |
|---|---|
| `tools/` 混杂 | 常规流程脚本（`extract_relations.py`/`governance_sync.py`/`gen_analysis_deliveries.py`）与特殊工具（`gen_benchmark.py`/`normalize_internal_naming.py`/`rfn_backlog.py`）混放 |
| `reports/` 混杂 | 正式资产（`端到端联动流程图.mermaid`）与临时脚本（`_tmp/_inventory.py`）混放 |
| `graphify-out/` 属性不清 | 派生产物位于仓库根目录，与 `data/`、`exports/` 同级 |

## 1.4 共享层问题

| 问题 | 表现 |
|---|---|
| 日期归一化 | 四处实现（`scraper_std.cleaner.normalize_date` 唯一 + 三处豁免） |
| 文号提取 | 两套实现（`doc_number.extract_doc_number` + `relations.iter_docno_signatures`） |
| 归一化函数 | 三套实现（`norm_docno` / `norm_title` / `norm_title_strict`），下游调用不一致 |
| 豁免标记 | `# norm-specialization` 分散在各文件，无集中审计 |

## 1.5 模型侧灰区与调度层二义

| 问题 | 表现 |
|---|---|
| `.codebuddy/` 灰区 | 被 `.gitignore:78` 忽略 + 被 `gate_hardcoded_paths.py:46` 的 `EXCLUDE_DIRS` 排除扫描（排除即盲区） |
| 助手侧记忆两处并存 | `d:\WorkBuddy\.codebuddy\memory`（16 文件/319 KB）与 `<repo>\.codebuddy\memory`（10 文件/14 KB），权威性不明 |
| 调度层口径二义 | automation 记忆（周任务 01:30 采集 + refresh + gates + pytest；日任务 06:00 门禁）与运行手册（周二 01:00 nfra_weekly；每日 06:30 refresh）不一致 |
| 定时任务可靠性无机器校验 | automation 记忆自述「09-16/09-17 执行历史缺口，疑为未回写」 |

# 第二部分：重构目标

## 2.1 唯一事实源（10 个数据域）

| 数据域 | 唯一事实源 | 写入者 | 消费者 |
|---|---|---|---|
| 五源原始数据 | `data/raw/{src}_laws.json` | collectors | clean |
| 清洗数据 | `data/cleaned/{src}_cleaned_{date}.{csv,jsonl}` | clean | clean_index / clause_index / classify / base_publish |
| 快照索引 | `clean_index/index.json` | build_clean_index | 全部下游（经 `interfaces.clean_index_api`） |
| 条文结构 | `data/clauses/{src}_clauses_{date}.{jsonl,md}` | clause_index | base_publish / classify / drafter |
| 时效 SSOT | `verification_state.json` | verification_state / verify_missing | consolidate / apply / gate_timeliness_ssot |
| RFN 权威台账 | `人身保险公司-文件归属表.csv` | rfn/registry（唯一写口） | classify / reconcile / merged / base_publish |
| 关系 SSOT | `relations_index.jsonl` | extract_relations | classifier / merged / drafter / analysis |
| 内部制度索引 | `internal_policy_index.json` | indexer | merged / drafter / base_publish |
| 对齐视图 | `merged_view.json` | merged | drafter / base_publish / gate_citations |
| 治理库 | `data/governance.db` | governance_store（唯一写口） | governance_api / gate_watermark |

## 2.2 数据一致性原则

- **单向依赖**：`scraper → classifier → internal_base → drafter → analysis`
- **跨模块仅经 interfaces**：`gate_no_cross_module_import` 守卫
- **水位的声明式依赖边**：`watermark` 表记录「产物 ← 依赖」的隐式时序约束
- **门禁验证一致性**：18 道门禁覆盖契约/枚举/漂移/时效/血缘/水位

## 4.3 归一化统一入口

在 `common_lib/norm.py` 中：

```python
NORM_ROUTER = {
    "docno": norm_docno,           # 唯一键/匹配比对
    "title": norm_title,           # 去噪全文匹配
    "title_strict": norm_title_strict,  # 归属表/索引精确匹配
}

def norm(kind: str, value: str) -> str:
    """归一化统一入口"""
    return NORM_ROUTER[kind](value)
```

下游一律经 `norm("docno", v)` / `norm("title_strict", v)` 调用，**禁止直接导入具体函数**。

# 第六部分：链外节点嵌入设计

## 6.1 时效网络核验（阶段 6.5）

| 维度 | 内容 |
|---|---|
| 触发条件 | `token 存在` + `距上次核验 > N 天` |
| 执行内容 | `verify_missing.py --source all` + `authority_backfill_verify.py` + `classifier_pkulaw_verify.py` |
| 降级 | token 缺失 → 跳过；遇 `90001` → 停止；连续 15 次认证失败 → 停止 |
| 人工断点 | 无 |

## 6.2 RFN 补登（阶段 2.6 后 + 阶段 4 后 + 独立命令）

**候选来源**：
- `relations gen` 后：`relations_index.jsonl` 的 `dst_class=corpus`
- `recall` 后：`scan_records.csv` 的 `in_attr=false` + `边界案例清单.csv`

**独立命令**：
```bash
python cli.py rfn-backlog apply --yes
```

**重跑链**（不含 recall，设计上无循环）：
```
classify --all → relations gen → reconcile → governance sync
  → internal merged → base publish --base internal → gates
```

**为什么重跑链含 `internal merged`**：`merged.py` 的 RFN 解析直接依赖 classifier 归属表（文号引用 → classifier 发文字号精确命中 → RFN）。归属表变了，`merged_view.json` 必须重跑。

## 6.3 内部制度 index/align/reocr（阶段 7.5）

| 维度 | 内容 |
|---|---|
| 触发条件 | `originals/` 有新文件（对比 `_ingest_state.json` 的 sha256 集合） |

| 安全门 | dry-run 前置；`--apply` 前备份 |

## 6.4 supp 本地摄取（阶段 0）

|---|---|
| 嵌入位置 | 阶段 0，与 gov/mof/nfra/pbc 四源并列 |

# 第七部分：自动执行契约

## 7.1 三层契约

**第一层：前置条件检测** → `_evaluate_triggers()` 返回触发决策表

**第二层：条件触发执行** → 按决策表执行

**第三层：人工断点重跑链** → `rfn-backlog apply` 内部固化重跑链

## 7.2 触发决策表

```python
def _evaluate_triggers() -> dict:
    return {
        "timeliness_verify": {
            "enabled": token_exists and days_since_verify > N,
            "script": "cli.py timeliness verify --source all",
            "timeout": 7200,
        },
        "supp_ingest": {
            "enabled": has_new_files("supp_input"),
            "script": "supp_ingest_batch.py",
            "timeout": 1800,
        },
        "internal_update": {
            "enabled": has_new_files("originals"),
            "script": "normalize_internal_naming --apply → internal index → align → reocr",
            "timeout": 3600,
        },
        "wiki_sync": {
            "enabled": publish_manifest_changed,
            "script": "sync_wiki_sources → gen_theme_moc → check_upstream",
            "timeout": 600,
        },
    }
```

# 第八部分：数据治理基础设施

## 8.1 契约版本管理

| 层次 | 契约 | 版本号 |
|---|---|---|
| 枚举 | `SOURCE_SET` / `TIMELINESS_STATUS` 等 | `ENUMS_VERSION = "1.0"` |
| 字段 | `CSV_COLUMNS` / `REGISTRY_CSV_FIELDS` 等 | `CSV_COLUMNS_VERSION = "1.1"` |
| 契约清单 | `contract_manifest.json` | 顶层 `version` 字段 |
| 治理库 | `SCHEMA_VERSION = "1.1"` / `_SCHEMA_INT = 2` | 已有版本号 |

## 8.2 数据生命周期管理

| 数据类型 | 保留策略 | 清理策略 | 归档策略 |
|---|---|---|---|
| 活跃数据（cleaned/raw 最新版） | 永久 | 不清理 | 不归档 |
| 历史快照（`*.bak_*`） | 保留最近 N 份 | 超过 N 份的移入 `archive/` | 按年度归档 |
| 事故备份（`incident_*`） | 保留 1 年 | 超期后移入 `archive/` | 按年度归档 |
| 临时日志（`tmp/*.err`） | 保留 7 天 | 超期删除 | 不归档 |
| 临时脚本（`tmp/*.py`） | 保留至任务完成 | 任务完成后删除 | 不归档 |
| 图谱产物（`graphify-out/`） | 覆盖式 | 不清理 | 不入库 |

## 8.3 数据质量度量框架

| 维度 | 度量指标 | 度量点 | 门禁 |
|---|---|---|---|
| 完整性 | 五源覆盖度 / 核心字段空值率 | clean 后 | `gate_contract` |
| 准确性 | 时效核验覆盖率 / 权威源交叉验证率 | timeliness 后 | `gate_timeliness_ssot` |
| 时效性 | 数据新鲜度（距上次刷新天数） | 全链 | `gate_watermark` |
| 一致性 | 跨源文号一致性 / 归属表与底座一致性 | classify 后 | `gate_rfn_sync` |
| 唯一性 | 重复记录率 / 硬链接去重率 | 全链 | `gate_no_duplicate_libs` |
| 有效性 | 枚举值合规率 / 格式校验通过率 | clean 后 | `gate_enum_values` |

## 8.4 扩展性设计

### 新增数据源检查清单（8 步）

| 步骤 | 操作 | 影响面 |
|---|---|---|
| 1 | `config/enums.py` 的 `SOURCE_SET` 新增源标识 | 受控枚举变更 |
| 2 | `config/sources.yaml` 新增源条目（含 `collector` / `clean_project`） | 源配置变更 |
| 3 | 新增 `collectors/{src}_collector.py` | 采集器 |
| 4 | `clean/run_clean_pipeline.py` 的 `RAW_MASTER_NAMES` 新增映射 | 清洗路由 |
| 5 | `clean_index/__init__.py` 的 `SOURCE_CONFIG` 新增条目 | 索引配置 |
| 6 | 契约不变（39 列统一） | 契约不变 |
| 7 | 跑 `gate_sources_config` + `gate_enum_values` + `gate_contract` | 门禁验证 |
| 8 | 跑全链刷新 | 数据刷新 |

### 数据源撤销检查清单（5 步）

| 步骤 | 操作 |
|---|---|
| 1 | `config/sources.yaml` 的源设为 `enabled=false`（带 `disabled_reasons`） |
| 2 | 子源撤销时 `SOURCE_SET` 保留主源 |
| 3 | 清理采集器相关代码 |
| 4 | 历史数据保留（不删除） |
| 5 | 跑门禁验证 |

### 清洗契约变更管理

| 场景 | 应对 |
|---|---|
| 字段新增 | 契约版本升级 + 向后兼容窗口 |
| 字段删除 | 契约版本升级 + 向前兼容检查 |
| 字段语义变更 | 契约版本升级 + 数据回填 |
| 清洗逻辑变更 | 全链刷新（幂等） |
