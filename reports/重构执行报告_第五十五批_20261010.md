## 二、mof 续采检查与**时长归因**（三份证据）

### 2.1 续采任务本身：**异常终止**（非正常完成）
| 证据 | 实测 |
|---|---|
| stdout | 仅 **12 行 / 1.7KB**，止于 `[step:collect:mof] python.exe mof_collector.py --out-dir raw`（**无 rc 汇总行**） |
| stderr | **0 字节 / 0 行** |
| 进程 | `tasklist` 复核 PID 32976 ⇒ **已退出**（日志末次写入 134 分钟前） |
| 判定 | ⚠️ **异常终止**（不是超时、也不是正常完成）⇒ 已**重启**（PID 2164，见 §三） |

### 2.2 上一轮全链的 mof 步骤：**用尽超时上限被强杀**
来自唯一事实源 `reports/_tmp/生产刷新汇总_20261010_025225.json`：
```json
{"step": "collect:mof", "cmd": "python.exe mof_collector.py --outdir raw",
 "rc": -1, "elapsed_s": 7200.3, "tail": "WARNING *** file size (1191479) ..."}
```
⇒ `elapsed_s = 7200.3s` **恰等于** `COLLECT_TIMEOUT.get(src, 7200)` 上限 ⇒ **TIMEOUT 强杀**（rc=-1）。

### 2.3 归因（按贡献排序，均带证据）
| # | 成因 | 证据 | 性质 |
|---|---|---|---|
| **①** | **单步超时上限（7200s）本身** | `elapsed=7200.3s` 精确触顶 | 直接原因 |
| **②** | **限流 + 退避重试**（主耗时） | `RateLimiter(args.delay_min, args.delay_max)` 每请求延迟；429/500 退避 **≤60s**；502/503 连续 8 次**熔断**（`_MAX_ATT_502_STREAK=8`）；链路 stderr 大量 502 与读取告警 | 站点侧 + 客户端策略 |
| **③** | **legacy 附件的 LibreOffice 转换**（次因） | mof 附件 246 条中 **legacy（doc_legacy 37 + ole2 15）= 52 条**，其中 **15 条已产出** `table_structured` ⇒ 确实走了转换；每次约 **6.5s**（两次启动 soffice）⇒ ≈5.6 分钟 | **一致性缺口**：gov 早已默认跳过（`enrich_legacy=False` + `LEGACY_KINDS`），**mof 未对齐** |
| **④** | **续采二次尝试异常终止** | §2.1 | 需可观测性（本轮已改进监控口径） |
