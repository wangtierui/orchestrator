# 数据恢复演练手册（2026-09-12，审查 P3）

> 定位：本仓为**文件管道型工程**（数据不入 git，`data/` 全 ignore），恢复能力 = 重建能力。
> 原则：**能重建的优先重建**（代码+配置+外部源→数据）；不可重建的（人工判定/核验结论）必须有副本。
> 演练周期建议：**每季度一次**（或重大数据批后），登记演练结论到本文件"演练记录"节。

---

## 一、数据资产分类与恢复策略

| 资产 | 位置 | 可否重建 | 恢复策略 |
|---|---|---|---|
| A. 外部五源 cleaned/快照 | `modules/regulatory_scrapers/data/cleaned/` + `clean_index` | ✅ 可（重抓+重清洗） | 采集→`run_clean_pipeline`（长时；常规首选） |
| B. RFN 归属表 | `modules/regulatory_classifier/data/人身保险公司-文件归属表.csv` | ⚠️ **半可**（重建=base 派生，但**人工判定列**会丢） | **必须有副本**（见 §二备份清单） |
| C. 时效核验 state | `timeliness_review/verification_state.json` | ⚠️ 半可（重核验需 token+时间） | 副本 + 可经 `timeliness verify` 重核 |
| D. 底座/明细/桥/图 | classifier `data/_t*`、`T*明细表.csv`、`rfn_clean_bridge.csv` | ✅ 可（`classify --all` + reconcile） | 重建（分钟级） |
| E. 内部制度 IPB | `internal_policy_base/data/`（processed/originals/merged） | ✅ 可（磁盘 `dept_policies` 仍在→`internal index --source-dir`） | 重建（~30 分钟，见追加九记录） |
| F. 发布件/交付库 | `published/`、`docs/reports/`、`BENCHMARK.md` | ✅ 可（`base publish` / `analysis gen` / `gen_benchmark`） | 重建（分钟级） |
| G. OCR 大仓库 | `data/corpus/dept_policies`（原始制度文件，1.5 GB 级） | ❌ **不可重建**（外部来源） | **必须有副本** |
| H. 备份快照 | `modules/**/backups/`（生成器级） | 辅助 | 保留最近 3 份 |

**判定**：**G（原始语料）与 B（归属表人工列）是全仓最不可再生资产**——恢复策略的重心在这两项。

## 三、恢复演练标准流程（RTO 目标：≤ 2 小时）

### 场景 A：误删/损坏「派生数据」（D/F 类）——最常见
```powershell
# 1) 快照一致性（若 cleaned 有变，先 reconcile）
%PY% modules\regulatory_classifier\scripts\reconcile_clean_drift.py --apply
# 2) 底座全链重建
%PY% cli.py classify --all
# 3) 发布件 + 交付库 + 基准（一条命令含 analysis）
%PY% cli.py base publish --base all
%PY% cli.py analysis gen
%PY% python tools\gen_benchmark.py
# 4) 验证
%PY% tools\ci_check.py        # ruff+pytest+gates 一键
```
预期：全绿；`BENCHMARK.md` 数值与最近一次登记一致（差异=数据确实变了，非恢复事故）。

### 场景 B：归属表丢失（B 类——有副本）
1. 从备份恢复 `人身保险公司-文件归属表.csv`（人工列完整版）；
2. `reconcile_clean_drift.py --apply`（桥对齐）→ `classify --all` → 场景 A 第 3–4 步。
3. **对账**：`cli.py rfn lookup` 抽查 5 个 RFN；`pytest` 断言 IPN/RFN 唯一性。

### 场景 C：整套环境重建（新机器，RTO ≤ 半天）
1. clone 仓库（代码+reports+docs 全在 git）；
2. `pip install -e ".[dev]"`（依赖已补全声明，2026-09-12 起可装齐）+ `.[ocr]`（如做 OCR）；
3. 恢复备份 1–4；外部 OCR 引擎按 README §6 装（PaddleOCR/Tesseract + 引擎 junction）；
4. 场景 A 验证链。

### 场景 D：原始语料（G 类）损坏——无副本则**不可恢复**
- 只能重新收集（来源分散、耗时长）→ 因此 §二-1 是**强制定期备份项**。
