## 一、勘误清单（v1 错误描述 / 逻辑偏差 / 技术不当）

### E-1 🔴 **第②项主张不成立：条文号 vs 引用的判别"已实现"**

| | 内容 |
|---|---|
| **v1 原文** | "`document_structure.extract_structure` 是**纯正则**，**无法识别**…**无法区分'第 X 条'作条文号 vs 作引用**"；增强点 = 引入依存句法做该判别 |
| **代码事实** | `std_lib/scraper_std/document_structure.py`（**1542 行**）已有成套判别机制：`_prev_allows_head(text, i, kind)`（`:192`，**否定清单**：`、，；：` 后的「第X条」判为交叉引用；要求前文为句末标点或章标题）→ `segment_body()`（`:215`，"内嵌引用**不断行**"，文档串明示 `本法第五十三条、第五十四条规定的行为` 保持同条正文）→ `_heading_shaped`/`_law_title_side_ok`（`:284`/`:296`）→ `resplit_embedded_anchors()`（`:333`，**否证规则**：标记后紧接 `项/款/目/条/章/节/个/是/、/，` 即判内联引用**不切**）；另有 `parse_score`（解析质量分）、`is_fallback`、受控值 `CLAUSE_ISSUE_SEVERITY`/`CLAUSE_PARSE_MODES` |
| **修正** | 删除"无法区分…"这一**缺口描述**；该项真实缺口**仅为「但书」**（全文件检索 `但书` **零命中**）。**技术方向改为**：在既有**否定清单**机制上**局部扩展**（正则/枚举即可），**不引入**依存句法整体替换——否则会与既有 1542 行并存出**两套条号切分**，并直接影响 `clause_index`→`external_clauses`→`gate_clean_schema`（条文契约自检）的条号形态判据 |

## 二、v1 遗漏的关键问题（依项目实际状态）

### M-1 🔴 **项目已有评测设施，v1 却要"新建度量框架"（重复造轮子）**

| 既有资产 | 事实 | 应用 |
|---|---|---|
| `tools/gen_benchmark.py` → **`BENCHMARK.md`** | **已在链内**（`STEP_ORDER` 含 `gen_benchmark`），自动生成"门禁清单 / pytest 用例数 / 数据计数"，自述 **"数值漂移即回归信号"** | **承载"引入模型前后对比"的现成机制**——v1 的质量度量框架应**增强它**，而非另建 |
| `modules/regulatory_classifier/recall_audit/` | 已产出 **12 个评测产物**：`重跑执行报告.json`、`_stats.json`、`关键词库扩充建议.csv`、`召回复核报告.md`、`疑似漏提取文件清单.csv`、`边界案例清单.csv`、`归属表无全文清单.csv`…；且带阈值门禁 `COVERAGE_MIN_RATIO`、`matched_coverage` **>5% 阻断** | **召回/覆盖率的现成抓手**——v1 未提一字 |

### M-2 🔴 **现成"金标准"未被识别：主题归属表 1162 条**

`人身保险公司-主题归属表.csv` = **1162 条**已判定主题（分布 T1:196 / T2:150 / T10:143 / T5:142 / T4:109 / T0:89 / T8:78 / T9:78 / **T3:76** / T6:66 / T7:35），**含"判定依据"列**（823 条"正文语义验证一致"、103 条"registry自动登记"、44 条"无正文"、9 条"上位法锚点"、其余"精读裁定/复核变更"）。

→ 这是**零成本的主题判定标注集**（v1 完全未提），既可用于**评测任何新增分类器**，也可用于**回归对比**。
→ 更关键：其"判定依据"列**已经采用"排名 + margin"式措辞**（如"正文语义验证一致（排名第1名，margin=0.03）"）→ 任何新增语义模块**必须输出同形态证据**（top-k + margin + 依据），才能与既有裁定记录**对齐**。

### M-3 🔴 **v1 的"零硬依赖"实为不成立（环境实测）**

当前环境实测（`importlib.util.find_spec`）：`sklearn` **已装**；**`torch`/`hanlp`/`ltp`/`text2vec`/`bertopic`/`umap`/`hdbscan` 全部未安装**。
- `hanlp` 首次自动下载 **~1.2GB**；`ltp`/`text2vec`/`bertopic` 均依赖 **PyTorch**
- `umap-learn`/`hdbscan` 需**编译工具链**；且 v1 的 `pip install hdbscan` **可能过时**（新版 `bertopic` 已改用 `sklearn.cluster.HDBSCAN`）→ 包名与依赖链须先核
- 本仓有大量 `--offline` / `set_offline` / "离线自检"语义 → **模型首次下载需联网**，v1 未给"离线预置"方案

### M-4 🔴 **v1 未提"可复现性"（与既有断点/水位机制冲突）**

本仓幂等靠 `input_sha`（`classify_state.json` 断点）、新鲜度靠 `gate_watermark`、来源靠 `gate_provenance`。
ML 输出受**模型版本 / 权重 / torch 版本 / CPU-GPU** 影响 → **同一输入可能产出不同产物** → 使"断点跳过"误判"内容未变"、水位判据失真。
**v1 零提及"模型指纹入 provenance"**（而 `gate_provenance` 的 `finalized_by`/`generated_by` 机制**天然可扩展**承载之）。

### M-5 🟠 **v1 未提"新产物入链"要求 → 会重演 N-46 链外产物缺陷**

本仓纪律：新增数据处理节点须入 `STEP_ORDER`（现 25 步）+ 登记 `GOV_ARTIFACTS` + 水位（`_wm`）。
v1 的"质量度量报告 / `clean_rules_registry` 校验"若无入链设计，将成为**链外产物**（历史上 N-46 即因 `build_theme_report.py` 未接线而滞后 19 天）。

### M-6 🟠 **v1 未提治理清单同步（三处会直接 FAIL）**

### M-7 🟠 **v1 未用到既有"条款级"基础（重复投入）**

### M-8 🟠 **v1 未评估"体量×模型成本"**

## 三、修正版方案（v2）

### 3.0 优化方向（总原则）

> **先铸尺，再增强；零依赖先行，模型后置；只增强不改 schema；一切新产物可评测、可入链、可回退、可复现。**

四条否决线（任一不满足即不上线）：
1. **有度量**：该模块有标注集/基线/阈值标定与回归对比（复用 `BENCHMARK.md` + `recall_audit`）
2. **有指纹**：模型名/版本/权重 sha 写入产物 provenance 并纳入 inputs 指纹
3. **有清单**：`tools/_manifest.json` + `gates/__init__.py` GATES + `contract_manifest.json` + `GOV_ARTIFACTS`/水位 四处同步
4. **有回退**：未安装/超时/异常 → 精确回退既有正则路径，且回退**可被观测**（不得静默）

### 3.1 P0 —— 零依赖（立即执行，无外部依赖，含"铸尺"）

## 六、结论

1. **v1 的 8 项中有 2 项主张与代码事实不符**（E-1 条文判别**已实现**、E-2 `extract_status` **误述**）、**1 项层次错位**（E-3 主题分类的真实层次是"人工裁定留痕"，`cluster_by_keywords` 只是主题内子簇）、**3 处按 v1 实施会立即 FAIL 或推翻既有纪律**（E-4 受控值断言、E-5 隔离记录人工闸门、E-3 主题归属表 SSOT）。
2. **v1 最大遗漏不是"某个工具没选对"，而是缺少"可验收"这一环**：项目**已有** `BENCHMARK.md`（回归基线，已入链）、`recall_audit`（12 个覆盖率产物 + 阈值门禁）、`主题归属表`（1162 条**现成金标准**）——v1 全部未用，却提出"新建质量度量框架"。
3. **v2 的核心调整**：把"**铸尺**"（P0-2）与"**入口统一**"（P0-1）提到 P0；把模型引入整体后移 P1 并要求**逐项过四条否决线**；对 E-1/E-2/E-3 三项**先更正方案文本再实施**；对 docreader/ParadeDB **先论证可移植性**。
4. **可立即开工且零依赖的是 P0-1~P0-5**：它们不引入任何新第三方依赖，全部复用既有设施（`gen_benchmark`/`recall_audit`/`governance_store.worklist`/主题归属表金标准），且能直接产出"当前正则质量的量化基线"——这既是 v1 缺失的一环，也是后续一切增强的验收前提。
