# 数据流转分析与存储/交互优化方案

- 日期：2026-09-17
- 范围：`regulatory_compliance_orchestrator` 全仓（5 个子模块 + interfaces + gates + tools）
- 定位：对既有 `reports/数据流转与基准审计报告_2026-09-08.md` 的**架构级续作**——前者审"字段与基准值"，本篇审"存储载体与模块交互协议"
- 结论性质：**评估 + 方案**（本文不含任何生产代码改动；实施建议见 §6）

---

## 0. 摘要（结论先行）

### 0.1 现状一句话
本项目当前是**「文件系统 + 约定式单源 + 门禁强制」**架构：每个数据域指定唯一权威文件（JSONL/CSV/JSON），派生链经 `clean_index` 动态解析最新快照避免硬编码，16 道门禁充当"一致性执行器"。

### 0.2 对提议方案的总体裁决
提议方案（**SQLite 唯一事实源 + JSON 交换快照 + Markdown 正文**）在本项目**成立但不完整**，需按数据域分治：

| 提议主张 | 裁决 | 核心理由（本项目实证） |
|---|---|---|
| SQLite 做"唯一事实源" | ⚠️ **限定采纳** | 仅适用于**索引/元数据/状态/版本链/关系/审计**六类；正文与原件**不得**入库（§3.2.4 / §3.3.2） |
| 正文存 Markdown | ❌ **不采纳（作事实源）**，仅保留为**派生阅读件** | ①条款级"回源逐字核验"要求与语料**逐字一致**，MD 渲染引入不可控差异 ②gov 语料 1.10 GB / 16,612 文档，MD 化 = 万级碎文件（现 `processed/` 3839 文件已现瓶颈）③`data/` 不入 git → "易 diff" 优势在本项目**无法兑现** |
| 结构化字段存 JSON | ✅ 采纳（交换层）；元数据**升级进 SQLite 列约束** | 现状契约靠 `contract.py` 常量 + 门禁**事后**扫描；入库可把域约束前移到写入时 |
| 模块间交换视图 = JSON 快照 | ✅ 采纳，但**必须补协议** | 现状无统一快照协议：schema_version 写法不一、无统一 sha、`apply_timeliness_to_cleaned` 会**反向改写 cleaned**（快照被改） |
| 审计日志 = SQLite 表 + JSONL | ✅ **强烈采纳（最明确缺口）** | 全仓无 `status_history` 结构；变更留痕散落 4 处（`verification_state.prev_status`、`时效核验_*变更台账_*.csv`、`rfn_drift_ledger.csv`、`元数据修补台账_*.json`） |
| 向量检索（sqlite-vec/Chroma/Qdrant） | ⏸ **推迟** | ①FTS5 trigram 已满足条文/文号定位 ②1.1 GB 语料 embedding 为数量级成本 ③引入外部服务违背单机最小依赖 |
| "只有一个写入方"原则 | ✅ 采纳为**目标不变式** | 现状存在 5 个多写者热点（§2.4），靠编排**串行**掩盖，一旦并发/守护化即破 |
| "上层只读 exports/ 快照" | ⚠️ **修正采纳** | 对 1.10 GB 的 cleaned **不可行**（不能为解耦再复制 1 GB）；应按**产物体积分层**：小产物走快照，大产物走"单写多读 + 水位断言" |
| "JSON 快照由分类器统一导出" | ❌ **拒绝** | 本项目快照生产者天然分散（clean_index / merged / relations / base_publish），且 classifier **反向依赖** scrapers，不存在"分类器统一导出"的拓扑 |
| "内容与索引分离（doc_id 关联）" | ✅ 采纳其**分离精神**；`doc_id` 已存在且更成熟 | 本项目已有三键体系：`RFN`（监管文件）/ `IPN`（内部制度）/ `dedup_key`（清洗记录），**无需再造 doc_id** |

### 0.3 推荐目标形态：**三轨制**
```
① 治理轨（Metadata SSOT）  = SQLite 治理库 governance.db   ← 元数据/状态/关系/版本链/审计/水位
② 内容轨（Content）        = 现有 JSONL / 原件 / 派生 MD    ← 正文、原始文件、交付文档（保持文件系统）
③ 交换轨（Exchange）       = exports/*.json|csv + manifest  ← 只读、带 schema/水位/sha 的快照
```
**关键判定：本项目不需要把"全部数据"收进 SQLite，只需要把"会被人改、会被跨模块读、需要历史"的那一小部分（< 10 MB）收进去。** 语料正文、原件、交付文档继续留在文件系统。

### 0.4 首要三动作（1 周内可完成，零事实源风险）
1. **止血**：`rfn/sync_status.json` 非原子写、`build_fts` 先删后建、编排器无单实例锁、`raw_loader.py` 失效死代码（§6 阶段 0，逐条带 `文件:行`）
2. **落地治理库骨架**：新建 `governance.db`，仅收录 `run_log` / `watermark` / `artifact` / `audit_log` 四张表，**不改任何现有事实源**
3. **新鲜度判据换代**：门禁的 mtime 比较改为**水位（watermark）比较**（§4.5），消除 touch/copy/秒级精度导致的假阳假阴

## 3. 提议方案适用性评估

### 3.1 前提校验
提议的前提是"**各子模块都在同一项目、同一台机器上运行**"。本项目**满足该前提**：单仓、单机、`subprocess` 串行编排。因此"SQLite 适合做单机唯一事实源"的推理**在本项目成立**。
**但本项目的决定性约束不是"分布式"，而是另外三条**：
1. **语料体积**：1.10 GB cleaned + 1.01 GB raw + 733 MB SQLite（同机再增一个全量库需评估磁盘与备份成本）
2. **治理诉求**：交付要求"逐字回源核验""可 diff 的历史版本""可入 git 的审计台账"
3. **既成事实**：232 个 py 文件、16 道门禁、24 个 pytest 用例都建立在"文件即事实源"之上——迁移成本必须分期摊薄

### 3.2 逐类数据裁决

#### 3.2.1 原始文件（PDF/Word/图片）
- **提议**：原格式 + 路径存 SQLite
- **现状**：原格式已保留；路径登记在 `internal_policy_index.json.relative_path` 与 `external_attachments.jsonl.local_path`+`sha256`
- **裁决**：✅ **采纳（补强）**。新增 `artifact` 表集中登记，但**原件本身不入库**
- **本项目特有注意**：`originals/` 与 `corpus/` **跨层硬链接共享 967 个 inode**。SQLite 若记"唯一路径"与事实不符 → 必须记 **`path_keys`（多路径）或 `inode`**；删除任一路径不丢数据这一性质要在表设计里显式表达

#### 3.2.2 解析后正文 → Markdown
- **裁决**：❌ **拒绝作为事实源**；✅ 保留为**派生阅读件**
- **理由（本项目实证）**：
  1. **逐字核验是硬需求**：`verify_regulatory_citations.py` / 07 附录 A 的"回源核验"要求清单原文与**五源语料该条实际正文逐字比对**；MD 的渲染/换行/转义会引入不可控差异，等于自毁该判据
  2. **规模**：gov 语料 16,612 文档 / 1.10 GB → MD 化产生万级文件；本仓 `processed/` 3839 文件的随机读已被 `merged.py` 逐份 `json.load` 拖慢，再增一万级文件无收益
  3. **"易 diff"在本项目不可兑现**：`data/` 被 `.gitignore` 排除（`.gitignore:11`），MD 同样不入 git；能 diff 的只有 `docs/`、`reports/` 下的**交付件**
- **已有正确形态**：`processed/IPN-*_clauses.md`（制度条文阅读件）+ `draft_clause/IPN-*_条款对照素材.md`（起草素材）已是"派生 MD"，定位正确，无需改造

#### 3.2.3 结构化字段 → JSON
- **裁决**：✅ 采纳（**交换层**用 JSON/JSONL/CSV）；⚠️ **元数据升级进 SQLite 列约束**
- **升级点**：本项目受控枚举已有 `config/enums.py`（`TIMELINESS_STATUS` 7 值、`SOURCE_SET` 5 值、`RELATION_KIND` 等），但校验发生在**写入之后**（`gate_enum_values` / `gate_relations` 判据 3）。迁入 SQLite 后可写成 `CHECK(x IN (...))` 或枚举表 + FK，**让非法值在写入时即被拒绝**——这符合"域约束应在建模层面锁死，而非事后清洗"的治理原则
- **反例警示**：**域约束 ≠ 唯一约束**。`保监发〔2018〕27号` 在 nfra 与 supp 是两个不同文件（同号异文），故 `docno_norm` **只能建普通索引，不得建唯一索引**

#### 3.2.4 索引/元数据/状态/版本链/关系 → SQLite
- **裁决**：✅✅ **强烈采纳（本次优化主战场）**
- **本项目已具备的可行性证据**：`external_index.sqlite` 733.8 MB + `internal_index.sqlite` 19.11 MB 已稳定运行，"SQLite 单库承载"路线已被验证
- **同时暴露的工程缺口**：`build_fts.py:81,128` **先 `os.remove(db_p)` 再重建** → 重建窗口内读者必然失败、且崩溃即无库；无 `PRAGMA journal_mode=WAL`；`base_api._conn()` 每次开新连接、无 `busy_timeout`
- **收益量化（可验证）**：
  - `relations_api.by_src/by_dst` 由"每次读 7.04 MB" → 索引查询
  - 时效四层传播由"门禁事后断言" → **单事务提交**，且天然产生 `status_history`
  - 归属表 3 写者由"无锁直写 CSV" → 单写口 + WAL
- **边界**：**发布件 SQLite 保持"派生、可重建、不入 git"定位**（`**/published/` 已被忽略），不与治理库混为一谈

#### 3.2.5 模块间交换视图 → JSON 快照
- **裁决**：✅ 采纳 + **必须补协议**；❌ 拒绝"由分类器统一导出"
- **修正 1（生产者）**：本项目快照生产者分散且拓扑上 classifier 依赖 scrapers；正确形态是**"每个事实源各自导出只读快照，由发布层统一登记 manifest"**
- **修正 2（体积分层）**：不能对所有产物一刀切"读快照"
  | 产物档位 | 体积 | 交互方式 |
  |---|---|---|
  | 小产物（索引/元数据/关系/状态/视图） | < 10 MB | **exports/ 只读快照**（含 manifest + 水位 + sha） |
  | 大产物（cleaned/clauses/raw） | 100 MB – 1.1 GB | **单写多读 + 水位断言**，禁止复制 |
  | 封闭链路产物（`_t*_base/final`） | 数百 KB – 11 MB | 保持文件，但写方唯一化 + 注册进 manifest |

#### 3.2.6 审计日志 → SQLite 表 + JSONL 追加
- **裁决**：✅✅ **强烈采纳（最明确、最低风险的缺口）**
- **落地要点**：`audit_log` 表（append-only）+ 按日/按主题导出 JSONL 到 `reports/`（**可入 git**，解决 G12）
- **本项目纪律**：现有"受控修补纪律"（只改目标字段、原子写、`.bak` 备份、输出变更台账）应**升级为写 `audit_log` + 导出台账**，从"手工习惯"变为"技术强制"

#### 3.2.7 向量检索
- **裁决**：⏸ **推迟到阶段 5（按需）**
- 若实施：优先 **`sqlite-vec`**（与治理库同进程、零外部服务），且只对**条文级**（109,232 条 clauses）建向量，不对 1.1 GB 全文建
- 前置条件：先回答"FTS5 trigram 在哪些具体场景不够用"（目前无此证据）

              │                               ▼
┌────────┐  ┌─────────────────── 内容轨 Content ──────────────────┐

### 4.2 治理库 DDL 草案（启动版，非最终）

```sql
PRAGMA journal_mode = WAL;
PRAGMA synchronous  = NORMAL;
PRAGMA foreign_keys = ON;
PRAGMA busy_timeout = 5000;

-- ① 运行与水位（阶段 1 即落地，零侵入）
CREATE TABLE run_log(
  run_id      TEXT PRIMARY KEY,            -- RUN-<ts>-<pid>
  started_at  TEXT NOT NULL,
  finished_at TEXT,
  argv        TEXT,
  ok          INTEGER,                     -- NULL=进行中
  note        TEXT
);
CREATE TABLE watermark(
  artifact_key   TEXT PRIMARY KEY,         -- 'cleaned:gov' / 'relations_index' / 'merged_view'
  produced_by    TEXT NOT NULL,            -- 唯一写方（模块.函数）——机器可读的"单一写入方"声明
  produced_at    TEXT NOT NULL,
  schema_version TEXT NOT NULL,
  inputs_json    TEXT NOT NULL,            -- {"cleaned:gov":"20260917","attr_sha":"..."}
  content_sha256 TEXT,
  record_count   INTEGER,
  run_id         TEXT REFERENCES run_log(run_id)
);
CREATE TABLE gate_result(
  run_id TEXT NOT NULL REFERENCES run_log(run_id),
  gate   TEXT NOT NULL, passed INTEGER NOT NULL, detail_json TEXT,
  PRIMARY KEY(run_id, gate)
);

-- ② 原件注册（阶段 1；注意跨层硬链接：path_keys 为集合）
CREATE TABLE artifact(
  artifact_key  TEXT PRIMARY KEY,          -- sha256[:16]
  sha256        TEXT NOT NULL,
  bytes         INTEGER,
  kind          TEXT,                      -- pdf/doc/docx/xlsx/png/...
  path_keys     TEXT NOT NULL,             -- JSON 数组：同一 inode 的多路径（originals/corpus）
  inode         TEXT,
  registered_at TEXT NOT NULL
);
CREATE INDEX ix_artifact_sha ON artifact(sha256);

-- ③ 文档主档（阶段 2；doc_ref = RFN/IPN，**代理键不可变**）
CREATE TABLE document(
  doc_ref        TEXT PRIMARY KEY,         -- RFN-<16hex> / IPN-<16hex>
  kind           TEXT NOT NULL CHECK(kind IN ('regulatory','internal')),
  title          TEXT NOT NULL,
  docno          TEXT, docno_norm TEXT,
  issue_organ    TEXT, publish_date TEXT, effective_date TEXT,
  source         TEXT,                     -- ∈ SOURCE_SET ∪ {'internal'}
  timeliness_status TEXT CHECK(timeliness_status IS NULL OR timeliness_status IN
    ('valid','amended','repealed','partially_repealed','expired','pending','uncertain')),
  verification_source TEXT, last_verified_at TEXT,
  body_path TEXT, body_sha256 TEXT, body_len INTEGER,
  origin_artifact_key TEXT REFERENCES artifact(artifact_key)
);
CREATE INDEX ix_doc_docno ON document(docno_norm);   -- ⚠️ 不得 UNIQUE（同号异文真实存在）
CREATE INDEX ix_doc_title ON document(title);

-- ④ 时效历史（阶段 2；补 G5 缺口）
CREATE TABLE timeliness_history(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  doc_ref   TEXT NOT NULL REFERENCES document(doc_ref),
  status    TEXT NOT NULL, prev_status TEXT, replacement TEXT,
  basis     TEXT NOT NULL,                 -- 法宝核验 / 人工判定 / 规则判断
  source    TEXT, checked_at TEXT NOT NULL, actor TEXT, run_id TEXT
);

-- ⑤ 关系（阶段 2；与 contract.RELATION_FIELDS 27 字段一一对应）
CREATE TABLE relation(
  relation_id TEXT PRIMARY KEY,            -- REL-<16hex>
  relation   TEXT NOT NULL CHECK(relation IN ('basis','repeal')),
  src_kind TEXT, src_ref TEXT, src_key TEXT, src_name TEXT, src_docno TEXT, src_source TEXT,
  dst_kind TEXT, dst_ref TEXT, dst_key TEXT,
  dst_class TEXT CHECK(dst_class IS NULL OR dst_class IN
    ('entity','corpus','organ','generic','external')),
  basis_type TEXT, article TEXT, action TEXT, scope TEXT, reason TEXT,
  matched_by TEXT, confidence REAL,
  source_offset INTEGER, source_snippet TEXT,
  generated_by TEXT NOT NULL, generated_at TEXT NOT NULL
);
CREATE INDEX ix_rel_src ON relation(src_ref);
CREATE INDEX ix_rel_dst ON relation(dst_ref);
CREATE INDEX ix_rel_class ON relation(dst_class);

-- ⑥ 审计（阶段 1；append-only，天然适合多写方）
CREATE TABLE audit_log(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  ts TEXT NOT NULL, actor TEXT, action TEXT NOT NULL,
  target TEXT NOT NULL, target_key TEXT, field TEXT,
  old_value TEXT, new_value TEXT, basis TEXT, run_id TEXT
);
```

**只读视图（供上层消费，替代裸读文件）**：
```sql
CREATE VIEW v_doc_active AS SELECT * FROM document WHERE timeliness_status='valid';
CREATE VIEW v_timeliness_current AS
  SELECT d.doc_ref, d.title, d.docno, d.timeliness_status, h.checked_at, h.basis
  FROM document d LEFT JOIN (
    SELECT doc_ref, MAX(id) AS mid FROM timeliness_history GROUP BY doc_ref
  ) x ON x.doc_ref=d.doc_ref
  LEFT JOIN timeliness_history h ON h.id=x.mid;
CREATE VIEW v_relation_graph AS
  SELECT src_ref, src_name, relation, dst_ref, dst_name, dst_class, confidence
  FROM relation WHERE src_ref<>'' AND dst_ref<>'';
```

### 4.3 唯一写入方矩阵（单一写方不变式）

| 表 | 唯一写方 | 读方（经 DAO/视图） |
|---|---|---|
| `run_log` / `gate_result` | `gates.GatesRunner` + `tools/run_production_refresh` | 报告、`cli gates` 历史查询 |
| `watermark` | **各产物写方在自己落盘后写自己的水位**（append/upsert 单行） | 门禁、编排器、`daily` 汇总 |
| `artifact` | `base_publish`（发布层已是双底座汇合点） | `gate_original_resolvable`、恢复工具 |
| `document` | `base_publish`（仍由 scrapers / internal_policy_base 各自 upsert 到发布层） | 全部消费面 |
| `timeliness_history` | `timeliness_review`（唯一） | `gate_timeliness_ssot`、报告 |
| `relation` | `tools/extract_relations`（唯一） | `relations_api`、drafter、交付库 |

### 4.4 交换快照协议（exports/）

```jsonc
// exports/manifest.json
{
  "schema_version": "1.0.0",
  "generated_at": "2026-09-17T10:00:00+08:00",
  "generator_run_id": "RUN-20260917-100000-1234",
  "items": [
    {
      "name": "relations_index",
      "path": "exports/relations_index.jsonl",
      "produced_by": "tools.extract_relations",
      "schema_version": "1.0.0",
      "generated_at": "...",
      "watermark": { "cleaned:gov": "20260917", "internal:index": "<sha16>" },
      "content_sha256": "<full>", "record_count": 5266,
      "readonly": true
    }
  ]
}
```
**三条纪律**：
1. `exports/` **只读**——任何"回写"必须走原模块写入口（根治 G8）
2. **大产物不导出**（cleaned/clauses/raw）——只在 `watermark` 表登记，避免复制 1 GB
3. **schema_version 强制**——下游读快照先校验版本，不匹配即报错而非静默降级

### 4.5 新鲜度判据换代（mtime → 水位）

| | 现状 | 目标 |
|---|---|---|
| 判据 | `getmtime(产物) >= max(getmtime(输入)) + 2s` | `watermark[产物].inputs == 当前输入产物的 produced_at/sha` |
| 假阳 | touch/copy/跨卷精度 → 误报陈旧 | 无 |
| 假阴 | 内容未变但被重写 → 无谓重跑；`copy2` 保留 mtime 时可**漏报** | 无 |
| 可解释性 | 只报"哪项输入更新" | 报"缺哪条依赖边"——即 §1.4 的 11 条边 |
| 落地 | — | `gate_watermark`：校验每条声明依赖边的水位一致性 |

### 4.6 正文与原件：保持文件轨（明确不做的事）

| 不做 | 理由 |
|---|---|
| 正文入 SQLite BLOB/TEXT | 1.10 GB 级；重写代价高；丧失行式/流式读写 |
| 正文转 Markdown（作事实源） | 摧毁"逐字回源核验"判据（§3.2.2） |
| 原件 BLOB 化 | 摧毁跨层硬链接去重（967 共享 inode）；摧毁 Word COM/PaddleOCR 抽取链 |
| 引入 Chroma/Qdrant | 违背单机最小依赖；FTS5 已够用 |

## 7. 风险与规避

| # | 风险 | 触发条件 | 规避 |
|---|---|---|---|
| R1 | **库不可 diff、不入 git → 审计链仍靠导出件** | 误以为"入 SQLite 就有审计" | 强制 `exports/` 文本快照 + `reports/` 台账双写；`document` 等关键表按日导 CSV |
| R2 | 单库损坏影响全域 | 无备份/无演练 | ①WAL + `VACUUM INTO` 定期备份（**不得直接 copy 库文件**）②纳入 `backups/` 纪律 ③每表可从文件轨重建（双写期的额外收益） |
| R3 | **迁移期双源静默分叉**（库新、文件旧） | 只写一侧 | 强制比对断言 + 写两侧；断言失败即 FAIL 而非 warning |
| R4 | **代理键漂移重演**（历史上 `internal index` 全量重扫致 643 条 IPN 漂移） | 把可变字段（文号/标题）当主键 | 主键一律用**已有稳定代理键**（RFN/IPN）；`doc_no` **只建普通索引不建唯一索引**；迁移前做全量键集比对演练 |
| R5 | **同号异文被唯一约束误杀** | `docno_norm` 建 UNIQUE | 已知真实案例（`保监发〔2018〕27号` 在 nfra 与 supp 是两个文件）→ 禁止 UNIQUE |
| R6 | 采集长任务（约 30 h）与治理库写锁竞争 | 采集器也写治理库 | **分库**：采集器只写 raw 文件 + 结束时写一行 `watermark`；治理库不承载语料 |
| R7 | 破坏现有 16 道门禁 | 契约/路径/布局判据与新结构冲突 | 每阶段跑 `gates` + `pytest`；新判据**只增不减**，旧判据最后移除 |
| R8 | 硬链接语义丢失 | `artifact` 表按单路径建模 | 表用 `path_keys`（JSON 数组）+ `inode`；消费侧取"首个存在路径" |
| R9 | 门禁扫描自家报告 | 新报告含盘符字面量 | 报告一律**仓库相对路径**（`reports/` 虽在 `gate_hardcoded_paths` 的 `EXCLUDE_DIRS` 中，仍应保持净洁） |

## 8. 结论

1. **提议方案的"方向"正确**，但"**一套 SQLite 装下所有数据**"在本项目不成立。
2. 正确形态是**按数据域分治的三轨制**：**元数据/状态/关系/审计入 SQLite（< 50 MB）**；**语料正文、原件、交付文档留文件系统**；**交换层用带 manifest 的只读 JSON 快照**。
3. 本次改造**最大的收益点**不是"换成 SQLite"，而是三件事：**①多写者收口 ②状态历史补齐 ③新鲜度判据从时间戳改为水位**——这三件事即使在文件轨上也能做，但 SQLite 能让它们**用事务而非纪律**来保证。
4. 本项目**已有两处成功先例**（`external_index.sqlite` 733.8 MB、`internal_index.sqlite` 19.11 MB）证明 SQLite 可行；也**已有两处工程反例**（先删后建、Python 端全表扫）说明"派生库"需要的纪律尚未到位——**改造应优先补齐纪律，而非扩张库的职责范围**。
5. 建议**立即启动阶段 0 与阶段 1**（合计 3–4 天，零事实源风险），阶段 2 起按季度排期。
