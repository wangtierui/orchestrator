## 3 执行中发现并处置的问题项（2 项）

| # | 问题 | 处置 |
|---|---|---|
| **N-37** | 批量退出码转换的**导入位置缺陷**（三重表现）：① `from config.exitcodes import …` 被插到 `sys.path.insert` 引导**之前** → 独立运行 `python tools/x.py` 时 `ModuleNotFoundError: No module named 'config'`（gen_benchmark 实测暴露）；② 个别文件插进**函数体内**（`_relation_tool` 里的 `sys.path.insert` 被误当锚点）→ `IndentationError`；③ 8 个**纯 stdlib**工具被误加 `config` 依赖（它们本无仓内引导） | ① 统一把导入移到首个 `sys.path.insert` **之后**（引导后=独立 import 段，ruff isort 不再上移）；② 修正函数体误插；③ 8 个纯 stdlib 工具**回退**（删导入 + `return ExitCode.X`→`return N`）——纯 stdlib 工具的裸整数 return 是正确形态，判据⑤ 本就不覆盖 tools/ |
| **N-38** | **预存在**（非本批回归）：`std_lib/common_lib/logging.py` 依赖 `scraper_std.logging_setup` → 需 `std_lib/` 在 `sys.path`。`tools/governance_sync.py` 等"被调实现"工具 standalone `--help` 会在 `scraper_std` 导入处失败（batch 4 引入；这些工具走 `cli.py` 引导，生产路径正常） | 登记为遗留；修复建议：`bootstrap` 或 `logging.py` 对 `scraper_std` 做自引导，或明确"被调实现"工具不支持 standalone |
