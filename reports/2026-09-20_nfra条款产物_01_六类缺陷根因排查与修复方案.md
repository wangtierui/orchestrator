## 1. 排查对象与产物链路

### 1.1 两个文件的关系（同源派生，非同源异体）

```
五源 raw（data/raw/*.json）
   └─ clean 管道 std_lib/scraper_std/pipeline.py::run_pipeline
        ├─ map_unified（unified_schema.py 五源 mapper）→ body_text / body_text_webpage / dedup_key
        ├─ clean_text（cleaner.py：denoise → normalize_ws 折叠换行）
        ├─ repair_text（sentence_split.py：标点断句 + 标点后加空格 + 中英数间加空格）→ **回写 body_text**（pipeline.py:94）
        └─ 尾部固定节点 clause_index.build_clause_index()
              ├─ 逐行 parse_document(body_text)            ← 唯一解析实现 document_structure.py
              ├─ row（18 键）→ {src}_clauses_{date}.jsonl   ← **事实源**
              └─ render_markdown(stru, title) → {src}_clauses_{date}.md  ← **渲染视图**（同一次遍历写出）
```

结论：`.md` 与 `.jsonl` 是**同一解析结果的两种呈现**，`.md` 的问题不可能是独立缺陷；
`render_markdown` 的条文体分支把 `articles[].body` 平铺为 `**第X条** 正文`，非条文体分支用
`_render_node` 输出 `- **序号标题** 内容` 与两空格缩进子节点 —— 因此：

- `.jsonl` 暴露的是**字段级错误**（title/content 归属、body 尾部污染、无 level 字段）；
- `.md` 暴露的是同一错误的**可见化形态**（层级未展开、标题加粗吞正文、附件/日期裸挂在条款内）。

### 1.2 解析判据清单（本次全部根因的落点）

| 判据 | 位置 | 行为 |
|---|---|---|
| 层级体锚切分 | `document_structure.py:149-168` `_OUTLINE_ANCHOR_RE` / `segment_outline` | 前置字符须属 `[。！？…；:：\s]` 才切；**仅在整段做一次切分** |
| 条/章锚切分 | `:74-145` `_ARTICLE_RE`/`_CHAPTER_RE`/`_prev_allows_head`/`segment_body` | 前置为汉字/连接标点/书名号 → 判为引用，不切 |
| 层级体节点装配 | `:437-483` `_parse_outline` | marker 之后**整行剩余文本一律写入 `title`**；后续无锚行追加到 `content` |
| 条文体尾部 | `:388-394` `_parse_law` + `:77` `_TAIL_RE` | 仅 `^附则|^附件|…` **行首**匹配才截断 |

## 4. 问题表现与根因（逐条，含双侧证据）

### 4.1 问题一 —— `title` 吞掉 `（一）`，层级节点丢失

**nfra_clauses_20260919.jsonl（第 241 行对应记录）**

```json
{"level":"一级","number":"二",
 "title":"基本原则（一）服务国家战略，推动协调发展。以京津冀协同发展、…新机制。",
 "children":[{"level":"二级","number":"（二）",…}, {"（三）"}, {"（四）"}, {"（五）"}]}
```

**nfra_clauses_20260919.md**

```
- **二、基本原则（一）服务国家战略，推动协调发展。以京津冀协同发展、…新机制。**
  - **（二）顺应发展规律，坚持因城施策。…**
```

**根因（R2）**：`segment_outline` 的锚正则 `_OUTLINE_ANCHOR_RE`（`document_structure.py:149-155`）要求
层级序号前一个字符属于 `[。！？…；:：\s]`；本例 `（一）` 紧跟在标题末字「则」之后（源文本无任何分隔符），
lookbehind 不成立 → **不切行** → 整行成为一级节点文本，`（一）` 因此丢失。
同一根因还导致该文档 `三、/四、/五、/六、` 的首个子节点 `（一）/（五）/（九）/（十三）` 全部被吞（5 处）。

**同类（章级）**：`_prev_allows_head`（`:101-121`）对汉字前置一律否决，导致
`总 则第一章 总 则`、`资产管理产品信息披露要求 第一节 产品募集信息披露` 之类**章标题粘连**（nfra 实测 77 处）。

**为什么检核脚本没发现**：`validate_clauses` 的 V001–V007 只读行级字段与 `articles`；
`validate_schema` 只比 `structure_count == len(structure)`；18 道门禁无一读 `structure` 语义
（`gates/__init__.py::ALL_GATES`）→ 节点丢失不在任何判据的覆盖范围内。

### 4.2 问题二 —— `（一）总体目标` 的 `title` 吞掉正文

**raw vs cleaned 对照（同一文件）**

```
raw  content（换行完整）：…特制定本指导意见。\n一、总体目标和指导原则\n（一）总体目标\n借鉴国际金融监管改革成果，…增长。
cleaned body_text        ：…特制定本指导意见。 一、总体目标和指导原则 （一）总体目标 借鉴国际金融监管改革成果，…
                            （nl=0，sp=55；raw 为 nl=54，sp=1）
```

**clauses 产出**

```json
{"level":"二级","number":"（一）","title":"总体目标 借鉴国际金融监管改革成果，…可持续增长。","content":""}
```

**根因（R1 + R3）**：

1. **clean 层销毁段落边界**（R1）：`cleaner.normalize_ws(keep_newlines=False)`（`cleaner.py:36-56`）执行
   `t.replace("\n", " ")`；`pipeline._clean_record_body`（`pipeline.py:87-105`）以该结果作为 `body_text`。
   → 源端「标题行 / 正文行」的**唯一可靠分隔信号被抹掉**。
2. **解析层无标题/正文分离判据**（R3）：`_parse_outline`（`document_structure.py:459-467`）把 marker 之后
   的整行剩余文本无条件写入 `title`，`content` 只在「后续无锚行」时才填充。
   → 即使换行保留，若标题与正文同行也会被判成整段标题。

原型验证（§8 脚本 `proto_fix.py`）：对同一行 `（一）总体目标 借鉴国际金融监管…`，采用「候选①整段 / 候选②首个空白前片段，取首个标题形态（≤30 字、无 `。！？，；、：`）」的分离规则，
**现行 flattened 数据下即可得到 `title="总体目标"`、`content="借鉴国际金融监管…"`**，保留换行的数据同样正确。

### 4.3 问题三 —— 同段条款被切成 `title`+`content`；无效空格 / 不换行空格

**clauses 产出（nfra:245 → structure[4]）**

```json
{"level":"一级","number":"五",
 "title":"发行人应充分、 及时披露总损失吸收能力非资本债券相关信息， 真实、 准确、 完整地揭示债券特有风险， 包括但不限于次级性风险、 减记损失风险、 转股风险。",
 "content":"总损失吸收能力非资本债券存续期间， 发行人应按季度进行信息披露。"}
```

**根因（R1 的第二个副作用）**：`sentence_split.repair_text`（`sentence_split.py:93-137`）为「断句」目的
把①每个句末标点后加 `\n`（`:35/:62`）、②`，；、：,` 后加空格（`:36/:63`）、③中英/数字间加空格（`:38-39/:67-71`），
并在 `pipeline.py:94` **把该加工结果写回 `body_text`**。于是：

- 同一段「五、…第一句。第二句。」被插入换行 → 解析层把第二句当成节点的独立 `content`（**假切分**）；
- 标点后空格与中英空格进入事实源 → 条款文本出现「、 」「100 号」「2022 年 4 月 26 日」等无效空格；
- 源端 NBSP/U+2002 未被 `normalize_ws` 归一（`_MULTI_SPACE` 仅覆盖 `[ \t\u3000]`）→ 产物内保留 23,974 个异常空白字符。

按用户口径「该条无 title，正文应为整段」：修复应同时做 **F5（不再把断句加工回写事实源）+ F2（标题分离判据）**，
原型实测该条变为 `title=""`、`content="发行人应充分、及时披露…转股风险。总损失吸收能力…信息披露。"`（两句完整）。

### 4.4 问题三-bis / 问题四 —— 条款内混入附件、答记者问、发文机关与日期

**nfra_clauses_20260919.jsonl（nfra:334 → `articles[35]`）**

```
第三十六条 本办法自2021年2月1日起施行，《关于加强保险中介机构信息化建设的通知》(保监发〔2007〕28号)同时废止。 附：中国银保监会发布《保险中介机构信息化工作监管办法》（）中国银保监会有关部门负责人就《保险中介机构信息化工作监管办法》答记者问（）
```

**nfra_clauses_20260919.jsonl（nfra:245 → `structure[9].content`）**

```
中国人民银行 银保监会 2022 年 4 月 26 日 人民银行 银保监会联合发布《关于全球系统重要性银行发行总损失吸收能力非资本债券有关事项的通知》
```

**同类还有**：`中国银保监会…支持城市建设和治理的指导意见` 尾部 `中国银保监会 2022年5月6日 （此件发至银保监分局与地方法人银行保险机构）`；
`nfra_clauses_20260919.md` 全文出现 `答记者问` **172 次**。

**根因（R4）**：

1. `_TAIL_RE`（`document_structure.py:77`）只做**行首**匹配（`^(附则|附件|附表|附录|关于…的通知$)`），
   而 nfra 站点把附件/答记者问链接文本**拼接在同一行尾部** → 漏检；
2. 无「发文机关署名 + 日期」签名块与「XX联合发布《…》」网页噪声的截断实现；
3. nfra 侧仅有 URL 残渣剥离（`unified_schema.strip_nfra_url_fragments`，`:284-290`），
   剥掉 URL 后留下空括号 `（）`，进一步放大了污染（且这层只作用于 `body_text`，不含尾部截断）。

原型实测（文档级、尾区判定）：
`P4` 截去 67 字（`附：…答记者问（）`）、`P3` 截去 77 字（签名+日期+联合发布噪声）、`P1` 截去 40 字（机关名+日期+此件发至），
截断点均落在合法句末标点之后。

### 4.5 问题五 —— 条款内 `（一）～（四）`、`1～5` 未分层级

**clauses 产出（nfra:963 → `articles[28]`）**

```json
{"no":29,"number":"第二十九条","body":"第二十九条 行政复议机关的法律部门…作出行政复议决定：（一）…决定维持。（二）…（三）…：1.主要事实不清、证据不足的。2.…5.…（四）…"}
```

**根因（R5）**：`_parse_law`（`document_structure.py:370-417`）恒返回 `structure: []`，
`articles[]` 键集被契约固定为 `{no, number, body}`（`interfaces/contract.py:240`），
**不存在承载条内层级的字段**，也不存在「条 → 项 → 目」抽取实现（参考实现 `草拟版/auto_degrade_parser.py::LawParser`
有 `clauses[].items[]`，本项目适配时按"层级体不重标为第X条"的取舍未移植该分支）。

原型实测（`parse_article_items`）：该条抽出 1 个引导段 + `（一）～（四）` 4 个「项」 + `（三）` 下 `1～5` 5 个「目」，
**17,543 条含 `（一）` 的条文做守恒校验：16,644 条逐字一致，其余 899 条差异仅为半角括号→全角括号归一，无丢字**。

## 6. 修复方案

分期原则：**P0 全部落在解析层（只影响 clauses 产物，事实源不动、关联键不动）**；
**P1 才动 clean 层事实源**（需要全链刷新与回归对照）；**P2 为契约扩展（新字段）**。
所有修复均遵守本仓纪律：不改 `articles[].body` 原文语义、不臆造条号、可追溯（统计写 `parse_meta`）。

### 6.1 F1 —— 锚切分修复（P0，对应问题一）

- **修复对象**：`std_lib/scraper_std/document_structure.py`
  - 新增 `_resplit_embedded(line, kind)`；在 `segment_outline()`（`:158-168`）之后追加一次**段内二次切分**；
  - `_parse_law` 路径同理处理章行（`第X章 …第Y节 …`、`总 则第一章 总 则`），仅作用于**行首已是章/条锚**的行。
- **判据**（规避误切）：仅当「待切标记前的文本是短标题形态（≤40 字、不含 `。！？，；：`）」时才切。
  该判据已对 `负责一、二类口岸…`、`上述(一)、(二)、(三)项…`、`落实本通知第（一）（二）…` 等交叉引用做过否证校核。
- **修复步骤**：
  1. 实现 `_resplit_embedded`（正则复用 `_OUTLINE_L1_RE/_OUTLINE_L2_RE/_OUTLINE_NUM_RE` 语义，含半角括号）；
  2. 在 `segment_outline` 返回值上串联调用；law 模式对 `segment_body` 结果串联 `kind="law"` 版本（章/节标记）；
  3. `_drop_toc_chapters` 继续负责「目录页 + 正文」重复章的剔除（二次切分会把重复章还原为两行，正好回到该函数的语义）；
  4. 章标题末端若残留 `第X节 …`，剥离到 `chapters[].title` 之外（节暂不建节点，避免碎片行）。
- **验证方式**：`tests/test_document_structure.py` 新增 3 例 ——
  ①问题一句式（`二、基本原则（一）服务…` → 一级 `title="基本原则"` + 二级 `（一）` 存在）；
  ②章粘连（`总 则第一章 总 则` → 仅 1 个章、标题 `总 则`）；③反例（`负责一、二类口岸开放…` 不得被切）。
- **回归检查项**：`pytest tests/test_document_structure.py`；A 类计数由 574 降至 ≤ 50；
  `structure_count` 只增不减；文本守恒（拼接后与原 body 逐字一致）。

### 6.2 F2 —— 标题·正文分离（P0，对应问题二、问题三）

- **修复对象**：`document_structure.py::_parse_outline`（`:437-483`）
- **规则**（`_split_title_body(rest)`）：
  候选①=marker 后整段；候选②=首个空白前的片段；取**首个满足标题形态**者为 `title`（≤30 字，不含 `。！？，；、：`），
  其余部分与后续无锚行一并进 `content`；都不满足 → `title=""`（**不臆造标题**）。
- **修复步骤**：替换 `:459`、`:463` 的 `m.group(2)` 直接赋值；`content` 累加逻辑保持（`:479-482`）。
- **验证方式**：新增 3 例 —— ①`（一）总体目标 借鉴…` → `title="总体目标"`；②`五、发行人应充分…` → `title=""` 且 content 含两句；
  ③`（三）制定配套监管规章 为保证…` → `title="制定配套监管规章"`；④反例：`以人民为中心，提高群众获得感、幸福感和安全感` （无句末标点、21 字）应判为标题。
- **回归检查项**：B 类计数（81,489）预期大幅下降；**节点数、`structure_count`、文本总量不变**（仅字段归属变化）；
  `render_markdown` 的 MD 输出与旧版做全文 diff，人工抽样确认无内容丢失（`structure` 无语义消费方，程序回归面为零）。

### 6.3 F3 —— 文档级尾部截断（P0，对应问题三-bis、问题四）

- **修复对象**：`document_structure.py`
  - 新增 `strip_doc_tail(text)` 与其在 `parse_document()`（`:560-624`，紧接 `:576` 之前）的入口调用；
  - 命中信息写入 `parse_meta.tail_cut = {"marker":…, "at":…, "removed":…}`（可追溯，不静默）。
- **判据**（**只在尾区**判定，尾区 = 末 400 字或末 15%，取大者）：
  ①`附\s*[：:]`；②`答记者问`；③`此件发至`；④「机关名（可重复）… YYYY年M月D日」签名；⑤「机关名…联合发布《…》」网页噪声。
- **修复步骤**：实现后先在 `parse_document` 入口截断一次（**不再逐节点截断**，避免把「签名独占一行」的节点整段清空——原型已验证逐节点法在此场景会产生空节点）。
- **验证方式**：新增 4 例（问题三-bis、问题四、P1 尾部、以及**反例**：正文中的合法日期 `本条例自2010年6月1日起施行。` 与「附件一」引用不得被截）。
- **回归检查项**：C 类计数由 2,015 降至 ≤ 100；`articles[].body` 中 `答记者问/附：/此件发至` 归零；
  被截文本 100% 可在 `parse_meta.tail_cut` 与源 `body_text` 中回溯。

### 6.4 F5 —— 空白归一（P0 解析层防御 + P1 clean 层根治，对应问题三）

- **P0（解析层，零风险）**：在 `parse_document` 入口对文本做**只读归一**（不写回事实源）：
  `\u00a0\u2002\u2003\u2009\u3000` → 半角空格并压缩；`，；、：,` 后的空格删除（**仅用于解析**，不进产物文本）。
- **P1（clean 层，根治）**：
  - `cleaner._MULTI_SPACE` 扩展为 `[ \t\u3000\u00a0\u2002\u2003\u2009]+`，并把零宽字符纳入 `_ZERO_WIDTH`；
  - `sentence_split.repair_text` 的产物**只写 `split_sentences`/`raw_uncut_text` 派生字段，不再回写 `body_text`**（改 `pipeline.py:94`）；
  - 断句所需的标点后空格/换行改由下游消费方在渲染时处理。
- **验证方式**：①`test_misc_pure`/新增 cleaner 单测：NBSP/U+2002 归一断言；②解析层断言：`、 ` 不进入 `structure.title/content`。
- **回归检查项**：D 类 24,403 → 0；F 类 23,974 → 0；`body_text` 变更后 `dedup_key` 不变（派生式不含正文）；
  关键词召回/主题分类/关系抽取需按 §7.3 全链刷新并做前后对照。

### 6.5 F6 —— 条内层级字段（P2，对应问题五）

- **回归检查项**：`validate_schema` 19 键一致；`gate_contract` 通过；产物体积增量预估 ≤ +20%（仅含 `（X）` 的 17,795 条受影响）；

### 7.1 全量干跑对照（改解析面的强制要求）

单案例会漏「过度切分」与「吞条」两类回归，故必须全量对照：

1. 用旧版解析器把五源 `cleaned` 全量解析为 `old.jsonl`（现状产物即是）；
2. 用修复版解析同一输入得 `new.jsonl`；
3. 对照指标（全部必须满足）：
   - **行数** 16,617 不变；`article_count` 逐份 **不减**（law 模式零回归）；
   - **节点数** 只增不减（F1 落地后 nfra 应净增约 436 个二级节点，全源净增约 574）；
   - **文本守恒**：`sum(number+content)` 与源 `body_text` 去空白后逐份比对（允许括号归一），异常率 0；

   - **人工抽样**：每类 20 例，含反例（交叉引用 `第（一）项`、`附件一`、合法生效日期）。
