# 流程系统性深度分析报告

> 分析日期：2026-09-12 ｜ 对标：`reports/regulatory-compliance-orchestrator.md`（五步流程 + 闭环）+ `reports/端到端联动流程图.mermaid`（七阶段愿景）
> 证据基线：《代码审查报告_20260911》《中间产物衔接分析_20260912》《周调度增量审计_20260908》+ 本轮两路专项侦察（自动化/偏离、知识库/检索）
> 评估维度：① 节点断裂与衔接缺失 ② 自动化降级与执行偏离 ③ 产物结构（上游生成/下游消费） ④ 知识库体系（覆盖/更新/检索）

## 〇、结论先行

1. **流程骨架存在但"半自动"**：采集→清洗→门禁有真实自动化；但**supp 摄取、时效核验、classify、rfn 登记、报告生成、internal 全链均不在任何编排内**——"名义自动、实际手动/漏编排"是主形态；两个定时任务的定义在 OS/IDE 层（仓内仅 README 描述与历史痕迹），仓库不可见、不可管。
2. **闭环缺失**：规划第五步（内控）与"变更监听器重启"为**完全缺失/待建**；EAST/统信"监管统计"数据域仓内不存在。
3. **执行偏离成体系**：增量语义未在编排命令兑现（gov `--full`、nfra 全量、`nfra_weekly` 零消费）；正文补齐止于中间产物（附件/表格不入条款、OCR 校正不回写）；效力核验覆盖 2975/4043 且门禁不查覆盖率。
4. **知识库"四缺九偏"**：16 知识域中 3 完整/9 部分/4 缺失（附件表格落地、监管统计、执行证据、告警记录）；更新机制仅 clause_index 一处真增量且同日不重建；检索主键级有索引、**正文级全量线性**（335MB JSONL 驻留内存），无统一查询入口。
5. **"全绿"不可信**：recall rc 恒 0、N-3 lint 静默跳过（实盘 `重跑执行报告.json:54` 有 import error 仍 PASS）、3 道门禁空跑放行、hash 校验失效（同日改写全链隐身）。

## 一、基准与方法

**规划五步与职责**（regulatory-compliance-orchestrator.md）：
```
①爬虫数据更新 ─▶ ②领域文件提取 ─▶ ③体系化归类+关联分析 ─▶ ④外部监管→内部制度落地 ─▶ ⑤内控管理
（数据采集）      （增量筛选）       （知识加工）             （制度转化）              （合规闭环）
 全量首次+增量追加  主题聚类/关联关系/效力核验                 一级/二级/三级制度         内控评价/合规检查/整改追踪
        ▲                                                                                  │
        └──────────────────── 变更监听器重启（回到第一步）◀────────────────────────────────┘
```

**现状全景速览**（本轮触发方式矩阵摘要，共 18 项关键动作）：

| 动作 | 入口 | 触发方式 | 名义 vs 实际 |
|---|---|---|---|
| gov/mof/nfra/pbc 采集 | collectors/*.py（cli 无 collect 命令） | OS 层定时（周二 01:00）+ 手动 | 名义"定时"→ 仓内无调度器，prompt 编排 |
| supp 采集 | supp_ingest / supp_ingest_batch | **纯手动** | 名义"五源定时"→ 人工链 |
| clean / clause | run_clean_pipeline（编排器内） | 自动 | ✅（但尾部失败仅 WARN） |
| 时效核验 | cli timeliness verify | **纯手动**（需 token/Node） | 名义"常规流程"→ 手动+"后续不代跑" |
| consolidate / apply | 编排器内 | 自动 | ✅ |
| reconcile | 编排器内 | 自动（C2 人工确认） | 半自动 |
| recall/gates | 编排器 stage4/5 + 每日任务 | 自动 | rc 恒 0 / 空跑放行 |
| **classify** | cli classify | **纯手动（漏编排）** | 名义"数据变更后重跑"→ 底座静默过时 |
| **rfn 登记** | 无 CLI 入口 | **无入口** | 名义登记链→ 实际新文件永不入库（organ= TypeError） |
| 报告生成 | report_builders/*.py | **纯手动** | 名义"五级交付库"→ 一次性手工产物 |
| internal index→align→merged→draft | cli internal/draft | **纯手动** | 名义"常规流程"→ 与监管侧脱同步 |
| 变更监听器 | — | **无实现** | 规划闭环整体缺失 |

### 3.3 产物结构设计评估（上游生成 / 下游消费）

| 产物 | 上游生成难度 | 下游消费现状 | 结构问题 | 改进方向 |

### 3.4 知识库体系评估

## 五、结论

规划的五步流程**在"采集→清洗→门禁"段具备真实自动化骨架，在"归类→制度→内控"段大面积缺失或依赖手工**；四维度评估共同指向同一根因——**流程的"契约层"与"编排层"缺位**：产物之间靠各自兜底而非契约衔接（③），节点之间靠人工记忆而非编排串联（①②），知识库靠"手动全量重算"而非事件/增量更新（④）。

修复顺序建议与两份前序报告完全一致：**先静默错误（P0×8）→ 再编排与契约（P1）→ 后规划级补件（P2/长期）**。本报告"节点断裂矩阵（N1-N14）""执行偏离表（6 项）""降级项表（D-1~D-9）""知识库 16 域矩阵""检索 16 入口表"可直接作为后续修复的逐项验收清单。
