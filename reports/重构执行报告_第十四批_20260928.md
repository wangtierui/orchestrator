## 二、变更摘要

### T1 · `# noqa` 治理（最高产出比项）

| 发现 | 处置 |
|---|---|
| `# noqa: E402`（≥105）—— `E402` **已在 pyproject 全局 ignore** → **死抑制** | 删除 |
| `# noqa: PLC0415`（≥83）—— `PL` 前缀**从未 select** → **死抑制** | 删除 |
| `# noqa: BLE001`（120+）—— `BLE` **未 select** → 抑制失效，但被 `gate_runtime_hygiene` 判据② 当"宽泛捕获的意图声明"约定使用 | **启用 `BLE`** → 由"约定"变"机器强制"，**154 处**成为真抑制；未声明者直接报错 |

**预防机制**：启用 `RUF100`（未使用 noqa 检查）。实测即刻见效——我在同批为 `gate_config_integrity`
新增的 2 处 `# noqa: PLC0415` **当场被 RUF100 抓出**（正是它要防的形态）。

**踩坑与固化**：`ruff check --select RUF100 --fix` 会**覆盖配置的规则集**，使"配置内有效但不在
CLI 集合内"的 noqa 全被误判未使用（实测误删 **323 条有效抑制**）。已回退重做，并把该纪律写进
`pyproject.toml` 注释（**必须**走裸 `ruff check --fix`）。

### T2 · 主题名副本

- `tools/gen_benchmark.py` 的 `CLS_MAP`：自述"近似名"、注释指向权威 `THEME_MAP`，实测**漂移 9/11**，
  且 **T2/T3 语义错位**（本地 T2"偿付能力" vs 权威 T2"产品与精算制度"；本地 T3"产品条款费率"
  vs 权威 T3"资本与偿付能力监管"）。**全仓零引用** → 纯死副本，直接删除并注明"禁止再建本地副本"。
- `modules/internal_policy_base/align.py` 的 `THEME_TITLE_KW`（内部制度→主题对齐的**唯一**关键词表）
  **独缺 T3** → 资本/偿付能力类内部制度**永远无法**对齐到 T3（静默覆盖缺口）。
  补 T3 关键词 + `THEME_TITLE_KW_EXEMPT`（T0 显式豁免）→ 实测 **17 条**制度重新对齐到 T3。
- **判据 T**（`gate_config_integrity._check_theme_coverage`）：覆盖须 ⊇ `THEME_MAP − 豁免`，
  且不得含未登记主题码 → 让"漏写"与"有意不写"可区分。

### T3 · 时效 7 值 SSOT

| 站点 | 处置 |
|---|---|
| `gates/gate_timeliness_ssot.py` 兜底 `frozenset({7 值})` | **改 FAIL**——判据不可执行 ≠ 判据通过（原为"用可能漂移的副本当尺子量 SSOT"） |

### T4 · 来源枚举收口（29 → 4）

- 新增 `SOURCE_ORDER` / `SOURCE_PRIORITY`（**顺序**是 `SOURCE_SET` 无序集合无法表达的事实），
  并加自检断言（与 `SOURCE_SET` 同元素、无重复）。
- **21 个站点**改为派生（`SOURCE_ORDER` / `list(...)` / `set(...)` / 推导式）。
- 修正的**真实缺陷**：`gen_analysis_deliveries.py` 的"通用源" 4 元组（新增源会静默漏算）、
  `build_upper_laws.SRC_PREFIX_MAP` 五源恒等映射、`build_overview_report` 时效列序。
- **实装扫描门禁**：`gate_enum_values` 判据 C —— 按"**成组出现**"识别副本（≥3 来源同现 / ≥5 时效值
  同现），**三引号字符串内不计**（文档列举不是代码副本）；按"文件×形态"**计数冻结基线**（不记行号
  → 行位移不误报），**只减不增**（与 `gate_no_cross_module_import` 同款纪律）。
  残余 4 处均为**按源分列的策略映射**（源优先级 / 处理次序子集 / 单测抽样 / CLI 参数名映射），
  **逐条在基线里写明理由**。

### T5 · 条文产物校验接入门禁

`clause_index.validate_schema()`（字段集 / 条号形态 / 解析适配枚举 / 结构语义指标）**早已实现**，
但生产链与门禁**零调用**（唯一调用点曾是 `tests/test_e2e_pipeline.py`）→ 五源 16k+ 条文产物
在**全链 22 道门禁中无任何覆盖**。现经 `interfaces.clause_index_api`（唯一入口，复用既有实现）
接入 `gate_clean_schema`；无产物时跳过（不误判为通过），不可执行时 **FAIL**。

**实测**（首度进门禁视野）：`files=16611 / articles=108409 / chapters=12313 / structures=51536`，
结构语义指标 `title_swallow=0 / tail_contam=92 / space_contam=40 / law_items=439 / fallback=4872`。

### T7 · 元数据"自述失真"

`config/schema/contract_manifest.json` 顶层 `consumer` 写着 `gates.gate_contract._check_manifest`，
实际函数名是 `_manifest_checks` —— **元数据指向不存在的符号**，且原判据只校验 `contracts` 内的
file/symbol/count，**不校验顶层自述**。现：纠正名字 + **新增判据 N-81**（consumer 须可解析为
真实符号，失败即 FAIL）→ 元数据自述从此可校验。另修 `tools/_manifest.json` 主链步骤数（22 → 25）。

## 六、遗留风险

1. **T6/T8 未修**（登记为 **N-82~N-87**）：均为"正确但重复/形态陈旧"，不产生错误数据，
   属**可度量技术债**——本轮已给出证据与建议路径。
2. **枚举扫描基线**：`gate_enum_values` 基线冻结 4 处**按源策略映射**；若未来新增来源，
   这 4 处需人工复核（**这是有意的**：它们语义各不相同，强行统一反而会掩盖真实差异）。
3. **`# noqa: BLE001` 的语义**：现为**真抑制**（`BLE` 已启用）+ `gate_runtime_hygiene` 判据② 的
   意图声明载体；**禁止批量删除**（会同时触发 ruff 与门禁）。154 处存量宽泛捕获**未经逐一收窄**，
   属"已声明、未细化"状态。
4. **`--add-noqa` 的作用边界**：它只加抑制码，**不判断捕获是否恰当**；159 处宽泛捕获的语义收窄
   仍需按模块人工推进。
5. **`contract_manifest.generated_at` 仍为 `null`**：该清单是**手工维护**的总册（无生成器）。
   本轮补了"自述可解析"判据，但**覆盖完整性**（RELATION/CLAUSE/ATTACHMENT/FP/INDEX 等 8 类
   字段集未登记）仍未做——属 N-89 候选。
6. **`follow_imports` 已 `normal`、`check_untyped_defs` 已开**：mypy 严格化已到"参数层"上限；
   再进一步（`disallow_untyped_defs`）预计新增大量报错，须单独评估。
