## 二、G1/G2：自动提交的遗留问题（**"钩子不随 clone 生效"**）

**病灶**：`.git/hooks/**` **不入库**（git 安全设计：钩子可执行任意代码，不能随 clone 自动生效）
→ ① 每台机器/每次重克隆都要手工复制（**易漏**，漏了则自动提交**根本不跑**）；
② 钩子升级后各副本**版本漂移**（仓库里改了，本机仍跑旧的）。

**修复（版本化 + 工具化 + 机器核验）**：

| # | 改动 | 说明 |
|---|---|---|
| ① | 钩子**入库** `.githooks/{post-commit,post-checkout}` | 内容随 `git pull` 自动更新；`post-commit` 含 **autopush 块**（N-163 已改为留痕+可见）与 graphify 受管块 |
| ② | `git config core.hooksPath .githooks` | **一次性** config 即可生效（无需逐钩子复制）；已执行并核验 |
| ③ | `graphify_sync.py` 改读**有效钩子目录** | 原硬编码 `.git/hooks` → 在 hooksPath 模式下会写进**git 根本不执行的目录**（命令报 OK 而钩子不生效，典型"装了等于没装"）；现跟随 `core.hooksPath` |
| ④ | **`.gitattributes` 补 `.githooks/* text eol=lf`** | ⚠️ 本机 `core.autocrlf=true` → 否则钩子检出时变 **CRLF**，Git Bash 下报 `$'\r': command not found` 而**静默失效**。规则**窄范围**（不触碰既有 246 个 CRLF 文件，与既有 `*.bat eol=crlf` 同类先例） |
| ⑤ | 单源化 | 删除 `tools/git_hooks/`（内容移入 `.githooks/`）与 `.git/hooks/` 陈旧副本，避免"两处事实源" |
| ⑥ | `tools/install_git_hooks.py --check` | 核验四项：`core.hooksPath` 指向、钩子文件存在、**CRLF 检测**、必需片段（autopush/graphify）齐全 |
| ⑦ | 审计新增判据 | `tools/audit_health.py`「**远程同步**」类别并入**钩子就绪度**（缺 config / CRLF / 丢块均报 MED）→ 同类问题**不可能再潜伏** |

> **能力下沉说明**：核验逻辑放在 **`std_lib/common_lib/git_hooks.py`**，CLI 只做薄壳。
> 原因：它有**两个消费方**（CLI + 健康审计）；若留在 `tools/install_git_hooks.py` 再由审计导入，
> mypy 会把同一文件解析为两个模块名并报 `Source file found twice under different module names`
> （**实测踩中**）。
