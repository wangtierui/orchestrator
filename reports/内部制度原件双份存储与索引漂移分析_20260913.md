## 0. 结论摘要

| 问题 | 结论 |
| :--- | :--- |
| 为何重复？ | **两条独立链路各存一份**：A 由 `tools/ingest_corpus.py`（F-L05 外部语料归集）从 `D:/Desktop/1.总公司各部门制度` 复制；B 由 `internal_policy_base.indexer.ingest()`（P6 制度摄取）从**同一源目录**复制。二者是同源的两份物理副本。 |

### 2.1 两条链路、同一个源目录

**A 的写入方** —— `tools/ingest_corpus.py`（F-L05 外部语料归集）：

`copy_original` 是**物理复制**：

```107:112:modules/internal_policy_base/extract.py
def copy_original(src: str, dst_dir: str, rel_path: str) -> str:
    """原始件复制入仓（D-05 数据随仓），返回落盘绝对路径。同名冲突保留（按 rel 目录）。"""
    dst = os.path.join(dst_dir, rel_path)
    os.makedirs(os.path.dirname(dst), exist_ok=True)
    shutil.copy2(src, dst)
    return dst
```

→ **两条链路都从同一个"各部门制度"目录做全量物理复制**，于是同一份交付物在仓内落地两次。这与 `.gitignore` 无关（`data/` 不入 git），是**本地磁盘层面的重复**。

## 4. 问题三：是否存在数据同步或冗余问题

**存在，共 4 类，且第 3、4 类是真实缺陷。**

### 4.1 【冗余】A 与 B 的内容重复 —— 约 306 MB 可消除

A 的 967 个业务文档内容在 B 中 100% 存在（§1.3），A 总大小 306.2 MB → **这 306.2 MB 是纯物理冗余**。因为二者都不入 git，影响面是本地磁盘与备份体积，而非仓库体积。

### 4.2 【冗余】B 内部同一内容多份拷贝 —— 97 个冗余文件

B：1,134 文件 / 1,037 唯一内容 → **97 个文件是同一内容的重复拷贝**（75 组）。主因是"部门目录副本 + 根层重命名副本"并存（§2.3）。

### 4.3 【缺陷】主索引与原件路径严重失配

| 指标 | 实测 |
| :--- | ---: |
| `internal_policy_index.json` 记录数 | 957 |
| 索引 `relative_path` 能在 `originals/` 解析的 | **443**（46.3%） |
| 索引 `relative_path` **解析失败** | **514**（53.7%） |
| `originals/` 磁盘文件未被任何索引记录引用 | **691** |
| 索引 basename 能在磁盘找到（去路径后） | **933 / 957**（97.5%） |
| 索引内容（sha256）能在磁盘找到 | **933 / 957**（97.5%） |
| 磁盘内容未被索引覆盖 | 104 组 / 108 文件 |

**判定：这不是"文件丢失"，而是"路径漂移"。** 97.5% 的内容都在，只是索引记的路径（旧部门名/旧子目录名）与磁盘实际布局（新名）不一致。

**根因（代码级）** —— 摄取幂等键是**内容**而非**路径**：

```132:141:modules/internal_policy_base/indexer.py
    for f in files:
        key = f["sha256"]
        prev = state.get(key)
        if prev and prev.get("ipn") == f["ipn"]:
            skipped.append(f["file_name"])
            continue
        if prev:
            changed_items.append(f["file_name"])
        else:
            new_items.append(f["file_name"])
```

而主索引汇总**按 IPN 去重，只保留 `extracted_at` 最新一条**：

```211:217:modules/internal_policy_base/indexer.py
        # 同 IPN 多 sha（同名同文号同介质的不同内容版本）→ 主索引保留 extracted_at 最新一条
        # （2026-09-12：与 merged/policies 同口径；重复数透明登记于 stat）
        ipn = r.get("ipn", "")
        if ipn not in seen_ipn or (r.get("extracted_at") or "") >= ext_map.get(ipn, ""):
            seen_ipn[ipn] = {k: r.get(k, "") for k in PROCESSED_FIELDS}
            ext_map[ipn] = r.get("extracted_at") or ""
```

**机制合成（因果链）**：

1. 首轮摄取（源目录为**旧布局**）→ `originals` 落盘布局 A + 索引写路径 A；
2. 源目录被改名/重组（§2.2 的 3 个一级目录 + 若干深层目录）；
3. 再次摄取（新布局）：文件内容已在 `state` 中 →
   - 若 IPN 未变 → **skip**：不复制、**不更新路径** → 索引停留在旧路径；
   - 若 IPN 因"内容权威"重算而变化（`indexer.py:154-156`）→ 视为 changed → **再次 `copy_original` 到新路径** → B 出现"旧布局 + 新布局"两套副本；
4. 汇总按 IPN 去重 → 每个 IPN 只留 1 条记录，路径可能落在旧布局上 → **514 条路径不可解析、691 个磁盘文件无索引引用**。

即：**B 的目录是"两代布局的叠加"，而索引是"按 IPN 去重后的单代视图"**，两者天然对不上。

### 4.4 【缺陷】`internal reocr` 对不可解析路径**静默跳过**

```293:295:modules/internal_policy_base/extract.py
        orig = os.path.join(data_dir, str(rec.get("original_path", "")))
        if not os.path.exists(orig):
            continue
```

`original_path` 是摄取时按 `relative_path` 写入的相对路径（`indexer.py:165`），因此上述 514 条记录的 `original_path` **必然解析失败** → 被静默 `continue`：**不计入 `stats["total"]`、不输出告警**。

后果：`orchestrator internal reocr [--force]`（扫描件提质重建）**最多只能触达 443/957 = 46% 的记录**，而命令输出看起来"正常完成"。这与本批克隆检视中发现的"静默降级/假成功"属**同一类缺陷模式**（能力缺失被伪装成正常）。

### 4.5 【次要】A 的清单与磁盘存在口径差

`dept_policies/_ingest_manifest.json` 记 `file_count: 1019`，磁盘现存 1,028 个文件（其中 1 个为清单自身）→ **净 8 个文件未被清单登记**（清单生成后新增）。清单是"唯一可审计入口"，故该差值应被纳入核验，否则审计口径失真。

### 4.6 一个"反向"发现：B 有 108 个文件内容不在任何索引中

磁盘内容未被索引覆盖者 104 组 / 108 文件，构成：

- 非制度类散件：`制度清单.xlsx`、各口径 `附件1：2025年制度检视自查情况表-*.xls`、`*.png`（部门自己把制度截图存放）、`附件2 产品开发手册附件.zip`、`Thumbs.db`；
- 少量**较新制度**（如 `阳光人寿发〔2025〕88号_阳光人寿客户信息安全管理办法.doc`）——疑似清单生成后补入目录、尚未摄取。

其中 `.png/.zip/Thumbs.db` 属**不应进入"制度原件库"的噪声**；`制度清单/自查表` 则是"检视工作台账"而非制度正文。这两类宜在摄取侧按扩展名/名称规则排除并显式登记。

## 6. 问题四：是否需要合并的建议

### 6.1 不建议合并 A 与 B

理由：

1. **职责不同**：A 是"归集 + 审计"（其清单 `reports/corpus/*.manifest.json` 已入 git，是"语料从哪来"的唯一可审计凭证，且与 F-L05 的域归集语义一一对应）；B 是"摄取 + 运行"（IPN 索引锚点、`reocr` 的原件来源）。合并会使"审计凭证"与"运行原件"耦合，任一侧变更都会破坏另一侧的语义。
2. **粒度不同**：A 按**域**（domain）组织，一个域可含非制度语料（如 `east2_m20`）；B 按**制度身份**（IPN）组织。二者的分区键不同，物理合并会导致目录语义混杂。
3. **删除 A 的代价**：`reports/corpus/dept_policies.manifest.json`（入库）将失去对应本体，审计链断裂。

### 6.2 应做的是"消除物理重复 + 修复漂移"，分四步

| 优先级 | 动作 | 预期收益 | 风险/前置 |
| :--- | :--- | :--- | :--- |
| **P0** | 修复 `indexer.ingest` 幂等键：`state` 由 `sha256` 单键改为 **`sha256 + relative_path`** 双键（或新增 `path_key` 维度），使"同内容不同路径"能被登记为新路径而非静默 skip；同时**不再因路径变化重复复制** | 根除 §4.3 漂移的产生机制 | 需迁移既有 `_ingest_state.json`（966 条）；建议先备份 state 与 index |

### 11.2 解析质量控制（过程中修正的三类缺陷）

初版 dry-run 的解析质量**不达标**（曾出现 `…_盖章.pdf` 名称丢失、流转号当文号等），逐项修正后复检：

| 缺陷 | 实测反例 | 修正 |
| :--- | :--- | :--- |
| fallback_title 取错（`_` 后半段→"盖章"），内容标题重叠校验失败 → 73% 回退文件名 | `2-…通知_盖章.pdf` → 目标名 `…号_盖章.pdf` | `derive_title_from_name()` 取**完整词干**并清噪声 → 内容解析率 58%+ |
| 文号形态未校验，流转号/档案号被当文号 | `NEWYXYWFASQ 202503310001`、`SXLQB201912130013` | `_DOCNO_SHAPE` 形态校验（内容与清单**双路**都过）→ 该类改判 `_名称` |
| 名称残留编号前缀与内嵌文号 | `_10：-团险…`、`_18运营-阳光人寿发〔2023〕191号…` | `_PREFIX_NOISE` 多层循环（覆盖 `10：`/`3，`/`6人管-`）+ `_INLINE_DOCNO` 剔除内嵌文号 |
| 内容抽取的异体字/多余空格 | `阳光⼈寿…中⼼城市…`、`（2025 版）` | `fix_variant()`（康熙部首→通用汉字）+ `tidy_title()`（数字与"版/年"间空格、汉字间空格） |

> 教训：**批量改名属高影响操作，必须先 dry-run 抽样质检再 apply**。本次首轮 apply 后仍发现前缀残留，
> 因工具**幂等**（第二轮仅重命名 27 个、第三轮 0 待处置）得以低成本收敛——幂等性是这类治理工具的硬要求。

### 11.3 配套代码与门禁

- `indexer.ingest(only_paths=...)` + `unindexed_originals()` + `internal index --only-unindexed`：
  **定向补摄取**，避免全库重扫因"文件名 IPN"与"内容权威 IPN"口径差异产生重复记录（实测全库重扫风险）。
- `_AUX_CARRY_FIELDS` 防冲（沿用 F-D01 主题列范式）：命名/对账写入的辅助列不在 `PROCESSED_FIELDS`
  白名单内，索引重建会静默冲掉——修复后 `drafting_dept` 394 / `name_normalized_at` 842 /
  `path_relocated_from` 431 均跨重建保留。
- `copy_original` 增加"源即目标"保护（就地补摄取不再抛 `SameFileError`）。
- 门禁：`gate_original_resolvable` 基线 **24 → 0**（台账已隔离，索引内不应再有非正文件）；
  `gate_flat_layout` 白名单 `internal_policy_base: {originals, processed, ledgers, misc}`。
- 长期纪律（写入 README §6 步骤 8）：`originals/` 只放制度正文 + 文号兜底清单；
  台账/图片/压缩/数据库等一律隔离，**不让它们再进入制度索引**。
