# 目录规范排查报告（遗留问题 5/7/8 处置）

> 日期：2026-09-08。范围：`modules/` 全量目录（代码库，不含 gitignore 的 data 大文件）。

## 一、目录规范（明文化）

对 `modules/<module>/` 定义 4 类合法子目录：

| 类型 | 规则 | 示例 |
|---|---|---|
| `scripts/` | 纯脚本（工具/底座生成器），不含数据文件 | classifier/scripts、drafter/scripts |
| `data/` | 纯数据（csv/jsonl/json/md 产物与原始副本），不含 .py | classifier/data、internal_policy_base/data |
| **自持状态单元** | **脚本与其运行时持久状态共存**（源码 docstring/README 已声明；状态为模块运行必需、每次运行可重建） | recall_audit、rfn、clean_index、timeliness_review |
| `docs/` | 文档（markdown），不含代码 | （各模块 docs，部分未建） |

**判定原则**：
- 脚本与产物**是否强耦合同生命周期**？若是 → 自持状态单元（豁免 data/ 收纳，防路径契约破坏）。
- 产物被**其它模块消费**或**独立再生成**？若是 → 移入 data/。
- 状态件含 `_fulltext`/`_clauses` 等大文件？→ data/processed（已合规）。

## 三、collectors 结构说明（遗留问题 7）

现状：`collectors/{gov,mof,nfra,pbc,supp}/`（nfra 族 8 py 存在**同目录互引**，如 fetch_lists.py `import nfra_regulations_scraper`；supp 有 utils/ 二级）。
用户诉求"爬虫项目统一存储一个子文件夹内"存在两种解读：

- **A 物理拍平**：将 5 源 .py 平铺至 collectors/ 单层并加源前缀消歧 → 需同步改写 nfra/supp 族**同目录兄弟互引**（约 8+ 处 `import x` → `import <src>_x`），破坏性高、易错，且 sources.yaml `collector:` 引用字段与运行时 `__main__` 直跑入口均要改。
- **B 统一门面层**：保留 `<src>/` 源码组织（依赖安全），在 collectors/ 下增加统一调度门面（如 `collectors/registry.py` 依 sources.yaml 路由各源 collector 模块名），实现"外部只看单一入口"。符合"统一入口 + 源实现隔离"的模块化惯例。

**建议 B**（与 D-02 模块边界、Q3 同仓 import 纪律一致；避免为目录整洁破坏既有导入）。已暂停物理拍平，待确认后实施。
