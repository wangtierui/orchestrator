## 1. 目标与范围

### 1.1 目标

一个**本地/局域网 Web 控制台**（下称「确认台」），一个界面同时承载两类能力：

1. **待办闭环管理**（操作面）：worklist 的查看 → 详情 → 结构化处置（选项+理由+影响面）→ 业务回写 → 处置后验证 的全闭环；
2. **项目数据总览**（观测面）：数据流转、数据状态、关键指标、统计与可视化，实时反映整体运行状况。

### 1.2 范围（In Scope）

- 六大数据页面：总览 Dashboard / 数据流转 / 数据状态 / 指标可视化 / 待办闭环台 / 治理与审计（详见 §5）；
- 两页投放面（2026-10-13 用户新增需求，评估后纳入）：**文档检索与预览（P7）/ 投放管理看板（P8）**——详见 §5-P7/P8 及配套报告《文档投放入口评估与方案_20261013.md》；
- 实时更新（SSE 推送 + 轮询降级）；
- 待办处置动作（唯一允许的写操作，且必须经既有写 API）；
- 本地部署（127.0.0.1 默认，可配置局域网绑定）。

### 1.3 非目标（Out of Scope，明确不做）

- **不触发主链运行**：`run`/`gates` 等执行动作仍归 CLI 与计划任务（避免 Web 层获得执行权，破坏「唯一入口」纪律 SD-1）。可选的「一键触发」列为 P3 增强项且默认关闭（§11-3）；
- **不做业务逻辑**：Web 层零业务规则，全部经 `interfaces/*_api.py` 只读门面 + `governance_store` 既有写口取数与落数；
- **不引入外部资产**：前端零 CDN、零外链字体/图表库（本环境出口有过滤，`semantic_tools.json:10` 实测多站点被重置）；
- **不做多租户/权限体系**：单机单团队定位，认证用「绑定地址 + 可选令牌」两级（§8）；
- **不替代现有 CLI**：`cli.py worklist`/`status` 全部保留，控制台是其图形化延伸。

## 2. 设计原则（全部继承本仓既有纪律）

| 原则 | 本仓依据 | 在确认台的落实 |
|---|---|---|
| SSOT 单一事实源 | `paths.py`、`interfaces/*_api.py` 门面、`governance_store` 表级唯一写方 | 控制台**禁止裸拼 SQL / 裸读文件**，一切取数经 `interfaces/` 九个只读 API；写只走 `governance_store.worklist_resolve` 等既有写口 |
| 零硬依赖 | `notify.py:12-14`（webhook 可选、env-only）；`semantic_tools.json` 三条硬纪律 | 服务端**纯 Python 3.13 标准库**（http.server/sqlite3/json），前端单文件原生 JS + 手绘 SVG；无任何新增 pip 依赖 |
| 旁路降级 | `notify.py:14-16`（告警失败绝不中断主链） | 控制台自身故障（端口占用/DB 锁/渲染异常）**绝不影响主链**；页面局部降级（某数据源不可用 → 该卡片显示「不可用+原因」，不白屏） |
| 密钥 env-only | `PGVECTOR_DSN`、`REG_ORCH_NOTIFY_WEBHOOK` 均环境变量注入，`gate_secret_scan` 守护 | 访问令牌同样仅 `REG_ORCH_WEB_TOKEN` 注入，**禁止入库/硬编码**；API 响应过滤密钥类字段 |
| 可观测披露 | SD-3（降级链可观测）、SD-9 | 每页数据卡片显式标注数据源 API、抓取时间、新鲜度；不可用即明示 |
| 克隆可移植 | pyproject.toml:3 单仓纪律 | 确认台随仓分发，`git clone` 后 `cli.py serve` 即用，无外部服务依赖 |

## 4. 技术选型

| 项 | 选型 | 理由 | 被否决的替代 |
|---|---|---|---|
| 服务端 | `http.server.ThreadingHTTPServer`（标准库） | 零安装、克隆即用、无版本冲突；并发需求极低（单团队几人） | Flask/FastAPI：需新增依赖；SSE/路由用标准库 200 行内可承载，无实质收益 |
| 数据库访问 | `sqlite3` 只读连接（`file:...?mode=ro` URI） | 控制台永不写库，杜绝与主链写冲突（WAL 下只读不阻塞写方） | 读写连接：无必要且危险 |
| 实时通道 | **SSE**（`text/event-stream`）+ 前端 5s 轮询降级 | SSE 单向推送足够（控制台无浏览器→服务端高频需求）；标准库可手写；断线自动降级轮询 | WebSocket：标准库支持弱，双向通信无场景 |
| 前端 | 单文件 HTML + 原生 JS + **手绘 SVG 图表** | 出口网络有过滤（多站点实测被重置），任何 CDN 都是可用性风险；本项目图表需求（折线/柱状/环形/流水线）SVG 300 行可覆盖 | ECharts/Chart.js CDN：违背零外链；打包引入：增加构建链 |
| 部署 | `cli.py serve [--port 8787] [--bind 127.0.0.1]` | 与 18 命令注册表同构；可挂 Windows 服务/计划任务自启动（沿用现有调度纪律） | 独立 exe/安装包：过度工程 |

**新增依赖数：0。**

### P0 总览 Dashboard（默认页）

### P1 数据流转（**动态桑基图**，用户 2026-10-13 确认选型）

用**动态桑基图（Sankey）**呈现「数据怎么流的」——节点 = 处理环节，边 = 数据流向，**边宽编码该环节最近一次处理的记录数**，流量大小一眼可辨：

- **拓扑事实源**：服务端从 STEP_ORDER（`run_production_refresh.py:674-735`）+ `config/sources.yaml` 五源 + `triggers.yaml` 条件步骤 + 内部制度线（originals → index → align → merged → published internal → draft）导出节点与边，**前端零硬编码**；
- **三层视图可切换**：① 主链全景（五源并行 → 汇聚 → 发布）；② 单源下钻（gov: collect → raw → clean → relevance → apply → classify）；③ 内部制度线；
- **动态语义**：运行中当前步骤节点脉冲发光、相关边流动动画；步骤完成即按实际记录数刷新边宽；未运行时显示**最近一次运行的流量残影**（各步记录数），点击边看该步台账明细；
- **边宽数据来源**：优先取台账每步记录数（依赖 `_raw_size` 缺陷 D-2 修复后的运行汇总，见《全面检视与重构审查报告_20261012.md》阶段四 D-2）；修复前降级为「状态桑基」（边宽均等、颜色编码状态），图例如实标注；
- 条件步骤（`timeliness:verify`/`inbox:drop`/`internal:update`/`wiki:sync`）以菱形节点 + 条件说明标注（条件文本取自 `triggers.yaml` 六种 CONDITION_IMPLS）；
- 点击节点 → 抽屉展示：argv、rc、exit_code、起止时间、stdout/stderr tail（读 `reports/_tmp/step_logs/<step>.log`，`run_production_refresh.py:502-506` 既有落盘）、失败时的 note；
- 实现：手绘 SVG（贝塞尔流量边 + 矩形节点，约 400 行封顶），实时更新走 SSE（§7）。

### P4 待办闭环台（**核心操作面**）

落地闭环审查 §2.5 的五环 + 本方案 §6：

1. **列表区**：筛选器（kind / status(open/deferred/resolved/dismissed) / confidence / 年龄段）+ 排序（最老优先）+ 关键词搜索；每行：kind 徽标、subject、产生方（payload.script/round）、置信度、年龄、建议动作摘要；
2. **详情区**：完整 payload（证据、上下游）、`suggestion`、**影响面预览**（该条目关联的产物/主题/制度——经 `governance_api` 与各 api 实时算出）、历史同类处置参考；
3. **操作面板**：受控选项单选（confirm/reject/defer/escalate/need_info，取值登记进 `config/enums.py` 受控域）+ 每选项附理由模板（下拉预置 + 自由补充）+ **操作人必填**（`--by` 语义，前端输入，回传服务端落 `resolved_by`）+ 二次确认弹窗（显示将发生的业务回写动作清单）；
4. **反馈区**：提交后即时显示回写结果（改了哪些表/文件）、验证状态（绿灯=已验证 / 黄灯=待下一轮验证）、后续动作提示（如需 `--resume` 重跑哪步）；
5. **历史区**：resolved/dismissed 台账（处置人、时间、选项、理由全文、回写结果），支持导出；
6. **deferred 队列**：延期项 + 到期提醒（aged 告警同源）。

### P5 治理与审计

- `tools/audit_health.py` 九类审计结果汇总（README 一致性/usage_policy/门禁失效等，逐项 pass/fail + 详情链接）；
- `semantic_tools.json` 增强层接线状态（wired/pending + 指纹），如实披露「未接线」项（SD-9）；
- `gate_secret_scan` 最近结果；
- `audit_log` 查询（`governance_api.audit()`）：谁在何时对治理库做了什么——**控制台自身的处置动作也写此日志**（操作人、item_id、选项、回写结果）。

### P6 告警与运行日志

- `reports/_alerts/` 列表 + 详情（json/md 双格式既有产物直接渲染）；
- `reports/_tmp/step_logs/` 按步骤检索查看（P1 抽屉的完整版）；
- `run_log` 表历史运行列表。

### P7 文档检索与预览（运营者自查入口；排期由《项目最优重构方案》统一确定——用户 2026-10-13 明示「根据整体项目重构方案选取最优节点」）

把双底座已发布文档变成**可检索、可预览**的自查入口（只读，经 `interfaces/base_api.py` 既有门面，零新查询逻辑）：

- **检索**：一个搜索框同时查外部监管记录与内部制度（`base_api.search_external` / `search_internal`，FTS5 trigram，既有 908MB 索引）；支持按 rfn / document_number / source / theme / timeliness_status 精确过滤（`query_external` / `query_internal`）；
- **详情预览**：记录正文渲染（markdown 化展示）+ 元数据卡（rfn、文号、发布/生效日期、时效三态、核验来源、theme、来源 URL、record_id）+ 关联信息（该记录的 clauses 条目、relations 边、RFN 登记信息，经 `clause_index_api` / `relations_api` / `rfn_api`）；
- **原件入口（file 协议直开，用户 2026-10-13 确认）**：内部制度原件（`internal_policy_base/originals/`，811 个硬链接）与五源原文附件（`data/docs/<scraper_slug>/`）**不做 HTTP 文件服务**；页面展示 `paths.py` 注册目录下的规范路径 + 「打开原件」链接（`file:///...`，新标签页，由操作系统关联程序接管，loopback 本机可用）；路径一律白名单生成、禁用户输入拼路径（防遍历）；
- **明确边界**：本页是「运营者自查与核验」入口，**不是组织内文档分发门户**——投放的编排与台账见 P8，组织分发维持既有 wiki 通道（论证详见《文档投放入口评估与方案_20261013.md》）。

### P8 投放管理看板（投放状态一屏掌握）

回答「该投的投了吗、投的是什么状态」——全部只读展示 + 可复制命令，**不代执行**（与决策 4 同精神：执行留 CLI）：

## 6. 待办处置的写路径设计（安全核心）

**铁律：Web 层自身不写任何业务数据，只调用既有写 API。**

| 动作 | 执行路径 |
|---|---|
| worklist 状态更新 | `governance_store.worklist_resolve(item_id, status, resolution, by)`（既有函数，CLI 已在用；控制台补传 `by`） |
| 业务回写 | **kind→action 注册表**（闭环审查 §2.5-④）：每个 kind 映射到该模块既有写入口的调用（如 rfn_theme_uncertain→主题归属写口、timeliness_conflict→`verification_state` 覆写口、align 类→align_result 写口）；注册表与产生方 9 处调用点一一对应，双向闭合 |
| 审计留痕 | 每次处置写 `audit_log`（by/item_id/option/回写明细），与 CLI 处置同格式 |
| 幂等 | 同一 item 重复提交同选项 → 返回「已处置」而非重复回写（按 status 守卫） |

> 注册表的**每个映射项即为一个小开发任务**（9 个产生方 → N 个 action），工作量集中在 P4；P4 上线初期可先只做「worklist 状态 + 审计」两写、业务回写按 kind 逐个点亮（每点亮一个即受 `gate_declaration_executor`「声明面执行者存在性」守护，不会静默半成品）。

## 7. 实时更新机制

| 层 | 机制 |
|---|---|
| 变更探测 | 服务端 2s 轮询 diff：`last_run_steps.json` mtime/内容、`step_logs` 目录、`_alerts` 目录、worklist 表计数、watermarks；任一变化 → 推 SSE 事件（携带变更类型 + 最小载荷） |
| 推送 | SSE `/api/events`（单连接多事件；ThreadingHTTPServer 每连接一线程，几人并发无压力） |
| 降级 | SSE 断线（EventSource 自动重连 3s）；连续失败 → 前端切 5s 全量轮询；服务端不可用 → 页面显示「控制台离线，主链不受影响」横幅 |
| 防抖 | 服务端 2s TTL 快照缓存：主链运行时高频文件变化不放大为 DB 压力；SQLite 全走 `mode=ro` 只读连接，**与主链写操作零锁竞争** |
| 精度说明 | 运行中「当前步骤」由 `step_logs` 最新 mtime 推断（零改动主链）；如需逐步精确游标，可选增强：`run_production_refresh` 每步写 `run_state/current_step.json`（一行写入，P2 可选，默认不做） |

## 8. 安全与权限

| 项 | 设计 |
|---|---|
| 绑定 | **仅 `127.0.0.1`（loopback）**——用户 2026-10-13 确认：不需局域网访问，不做 `--bind` 参数与 token 认证（少一个攻击面，也少一处密钥纪律负担） |
| 认证 | 无（loopback 本机自用，访问控制交由操作系统登录账户）。若未来开放局域网再议 `REG_ORCH_WEB_TOKEN` 方案（设计已预留，本期不实现） |
| 读隔离 | 全部 SQLite 走 `mode=ro` URI；API 响应过滤密钥形态字段（DSN/token/secret 正则，复用 `gate_secret_scan` 的检测模式） |
| 写隔离 | 仅 §6 三类写路径；无「执行链」「改配置」「删文件」类端点 |
| 注入防护 | 参数化 SQL 全量（经 interfaces 门面天然保证）；文件路径类查询白名单校验（防路径遍历，只允许 `paths.py` 注册目录） |
| 响应头 | CSP（禁内联外链）、`X-Content-Type-Options`、无 Cookie 会话 |
| 审计 | 所有写操作落 `audit_log`（操作人+动作+结果），P5 页可查 |

## 12. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 控制台取数拖慢主链 | 全 `mode=ro` 只读连接（WAL 下不阻塞写方）+ 2s 快照缓存 + interfaces 门面既有轻量查询 |
| 页面数据与 CLI 口径不一致 | 禁裸读：一切经 interfaces/ 同一函数（与 `status`/`governance` 命令同源），从结构上消除双口径 |
| 前端单文件膨胀 | 按页拆 JS module（ES module 原生支持，无构建）；SVG 图表函数库 300 行封顶 |
| 网络暴露风险 | 仅 loopback 绑定（无局域网、无 token，最小攻击面）；无执行类端点；secret 形态过滤 |
| 门禁/文档漂移（重蹈 23/24 道覆辙） | README 受管块、命令清单全部机器核验（gate_config_integrity），不手写计数 |
| 业务回写引入数据错误 | 注册表逐 kind 点亮 + 二次确认弹窗列明动作 + audit_log 全留痕 + 处置后验证灯 |
