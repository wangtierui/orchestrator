## 二、T1 · N-95 病因定案（**结论反转**）

### 2.1 逐因分解（4192 行实测）

| 缺因 | 条数 | 占比 | 性质 |
|---|---|---|---|
| **R2 无可查表键**（`dst_ref`/`dst_key` 皆空） | **2459** | 58.7% | 上游未解析 → 目标不在归属表/条款表 |
| **R5 表命中文件但未定位** | **738** | 17.6% | ⚠️ **原以为是 bug，实测为正确行为**（见 2.3） |
| R3 snippet 无「第M条」 | 440 | 10.5% | 素材缺失 |
| R4 目标条款表无该文件 | 299 | 7.1% | 表覆盖不足（`by_rfn=293` / `by_dedup=2599`） |
| **OK 已定位** | **237** | **5.7%** | — |
| R1 目标非监管文件 | 19 | 0.5% | 本不该定位 |

### 2.2 关键排除：**两侧条号键空间是一致的**（不是归一化失配）

第十六批我曾假设"`第一条` → `'一'` 与 `no=1` 失配"。**实测推翻**：

```
norm_article_no("第一条") -> '一'          # 归一化正常
目标表 by_norm = {'一': '第一条', '二': '第二条', ...}   # 键空间同形
目标表 by_no   = {1: '第一条', 2: '第二条', ...}
```
两侧**同形且同源**（`clause_locator` 文档串明示"`norm_article_no()` 只做形态归一，不引入第二套编号语义"）。

### 2.3 结论反转：R5 是**正确的"宁缺勿错"**

R5 样例（`locate_dst_article` 返回空）实为：

```
第一条目的本文件规定了寿险首问工单管理的基本流程…            ← 制度**自身**的正文
阳光人寿保险股份有限公司有价单证管理办法 第一章总则 第一条为规范…   ← 同上
```

即 **`source_snippet` 是"源文档正文窗口"，其中的 `第一条` 是源侧自身的条号**，不是对目标文件的引用条号。
`locate_dst_article` 的行为是「snippet 中出现多个条号 → 只有**恰一个**能在**目标表**命中才采用，否则留空」
（`clause_locator` 歧义纪律明文：**多命中/未命中一律留空，宁缺勿错，保持可审计**）。

→ 在这类行上**填 `dst_article` 才是错误**（会把"源侧自己的第一条"写成"目标的第X条"，
属**臆造引用**）。故 **R5 = 正确行为**，不是缺陷。

### 2.4 真正的可改进点（零依赖不可达 → 需上游变更）

| 改进 | 覆盖面 | 代价 | 判定 |
|---|---|---|---|
| **snippet 改为"引用跨度"**（只取 `《X》第N条` 命中片段，而非正文窗口） | 可显著提升 R5/R3 的**可信**覆盖率 | 改 `extract_relations` 的 snippet 构造 → **`relations_index.jsonl` 内容变更**（`source_snippet`/`dst_article`/`relation_id` 派生态） | **需独立批次 + 回归对比**（本批不夹带） |
| 目标表加**按标题**查表（booktitle 兜底） | 部分 R2/R4 | 需与 N-48 的标题兜底同口径；新增索引 | 登记 |
| R3 用"目标首条"填充 | — | ❌ **禁止**：无证据即等于臆造 | 不做 |

**→ 登记 N-98**：`source_snippet` 改"引用跨度"（含 `relation_id`/`dst_article` 影响评估与回归对比方案）。
