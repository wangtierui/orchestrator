## 二、根因（证据链）

**机制**：`.git/hooks/post-commit` 每次提交后执行 `git push origin main`（用户约定 2026-09-08，
"本地唯一演进点，普通 push fast-forward 语义"）。

**根因（两条叠加）**：

1. **仓库分叉（事实原因）**：远程存在提交 `72c4a26`（**第二十六批**），而本地有 `b6e177e`
   （**同一批、同标题、同作者、同时间**）。经 `git diff` 核对：**差异文件数 = 0**（内容完全等价）
   ⇒ **同一批被提交了两次**（两处工作副本各提交一次），二者父提交同为第二十五批 `cdf8b43`
   ⇒ **永久分叉**，此后每次 `push` 均被拒：
   ```
   ! [rejected] main -> main (non-fast-forward)
   error: failed to push some refs to 'https://github.com/wangtierui/orchestrator.git'
   ```
   ⇒ **第二十六批起的 8 批提交（26→34）从未推送成功**。

2. **钩子静默吞错（为何无人察觉）**：原实现
   ```sh
   git push origin main >/dev/null 2>&1 && echo "pushed" || echo "push skipped/failed"
   ```
   把**全部输出与错误**丢弃，只留一句含糊的 `skipped/failed` ⇒ 失败**不可观测**。
   这与本仓"降级链须可观测（不得静默）"的纪律**直接冲突**——同步失败正是一次"降级"。

## 三、修复

### ① 消除分叉（以远程为基线 rebase 本地）

```bash
git -c core.hooksPath=<空目录> rebase origin/main --empty=drop
# → warning: skipped previously applied commit b6e177e   ← 内容重复者被自动识别并跳过
# → Successfully rebased and updated refs/heads/main.
```
* 选用 **rebase**（而非 merge）的理由：这批内容**只存在过一个"第二十六批"**，若用 merge 会在历史上
  留下**两个同批提交**，与本仓"唯一事实源/一致性"纪律相悖；
* rebase 改写了**从未推送过**的 8 个提交 SHA ⇒ **无需 force-push**，对他人无影响；
* 执行时**临时禁用钩子**（`core.hooksPath` 指向空目录），避免中途逐提交触发推送。

### ② 恢复同步

```bash
git push origin main
# → 72c4a26..459e50a  main -> main      ✅
git rev-list --left-right --count HEAD...origin/main   # → 0   0（完全同步）
```

### ③ 修病灶：钩子不再静默（版本化 + 留痕 + 可见）

**版本化**：钩子现入库于 `tools/git_hooks/post-commit`（可复现；`cp` 到 `.git/hooks/` 即生效），
**graphify-sync 块原样保留**（该块由 `tools/graphify_sync.py` 管理）。

**四条改进**（仍**不阻断提交**：commit 成败与 push 解耦）：

| # | 改进 | 说明 |
|---|---|---|
| ① | **留痕** | 每次结果写入 `logs/git-autopush.log`（时间 / HEAD / 领先数 / 真实错误） |
| ② | **可见** | 失败时回显**真实原因**（逐行缩进）与**处置命令**，不再 `>/dev/null` |
| ③ | **漂移可见** | 每次回显「本地领先远程 N 个提交」，超阈值可直接察觉 |
| ④ | **纪律对齐** | 与仓内"降级必须可观测"同款口径 —— 同步失败属降级，必须可观测 |

### ④ 机器化核验（防同类潜伏）

`tools/audit_health.py` 新增类别 **「远程同步」**（只读）：

| 情形 | 判定 |
|---|---|
| `origin/main..HEAD` 计数 **> 0** | **MED**：本地领先远程 N 个提交（未推送）；若钩子日志末尾为 `FAIL` 则一并报出 |
| 无 `origin/main` 跟踪引用 | **跳过并披露**（克隆环境未配远程 → 不阻断） |
| 计数 = 0 | 通过（0 发现） |

> 意义：**此类问题不会再潜伏 8 批** —— 下一轮审计会立刻报出"本地领先远程"。

## 五、遗留风险

| 编号 | 事项 | 说明 / 下一步 |
|---|---|---|
| **R-1** | **钩子不随 git clone 自动安装** | `.git/hooks/` 不入库 → 需人工 `cp tools/git_hooks/post-commit .git/hooks/`（已在钩子头部与 README 注明）。**若需完全自动化**，可考虑改用 `core.hooksPath` 指向入库目录（`.githooks/`），代价是影响所有钩子管理方式 |
| **R-2** | **分叉的历史成因未完全避免** | "同一批在两处副本各提交一次"仍可能重演；建议协作约定：**同一时间只在一个工作副本演进**，或定期 `git fetch && git status -sb` 查看 `ahead/behind` |
| **R-3** | 钩子**不自动整合**远程变更 | 失败时只提示 `git pull --rebase`；**刻意不自动 rebase**（自动改写历史风险高，须人工判断） |
