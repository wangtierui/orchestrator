# 周调度增量/全量审计报告（2026-09-08）

结论先行：**当前"周采集调度"在抓取层整体是"全量遍历列表 + 记录级复用/合并"，不是日期驱动的增量抓取**；
清洗层每次对整份 raw 全量重清洗生成日期化快照，仅 clean→条文（clause_index）一层按快照日期增量跳过。

## 1. 调度事实

- 定时任务：`orchestrator`（每周二 01:00，五源采集 + recall + reconcile + gates）、`orchestrator-2`（每日 06:00 检索幂等 + gates）。
- 无任何 `--since / --date / --only-new / --diff / --days` 类日期增量拉取参数（全仓 regex 核实）。

## 2. 各源抓取语义矩阵（当前代码证据）

| 源 | 列表层 | 详情/写入层 | 主库落盘 | 增量结论 |
|---|---|---|---|---|
| gov（xzfgk） | 每次从第 1 页全翻 | `--resume`（默认 False）才跳过已抓 detail_url | `tmp+os.replace` 原子覆盖 | 默认全量；仅 resume 省详情+merge 防丢历史 |
| mof | 每类别全量分页拉完 | 指纹 diff（`_sig_current/_sig_prev`），added/updated 才重抓详情附件 | 主库整体原子覆盖 | 列表全量、详情**记录级增量** |

## 3. 清洗/下游层

- clean：每次对整份 raw 全量重清洗 → `{project}_cleaned_{YYYYMMDD}.{csv,jsonl}` 新日期快照（同源 raw 无变化也生成当日快照，属轻量 ~1s/源）。
- clean_index：登记每源多份快照 date/sha。
- clause_index：`state[src].date == clean 日期 → built=False 跳过`，真正增量断点。
- reconcile（drift gate）：`clean_snapshots` 日期推进才触发重扫（快照推进阻断语义）。

## 4. 结论与增量执行纪律

"周采集"网络成本大头 = gov/mof/pbc/nfra 列表全翻 + 未命中已抓的详情。**增量目标 = 每周只抓上次以来新增/变更**。落地：

1. 列表层日期早停改造风险高、站点结构耦合，**不推荐立即做**（本次未改）；以「详情复用 + 快照断点」先收敛请求量与重建成本。
2. **gov：默认增量已落地**（`--resume` 缺省 True，新增 `--full` 才全量重抓）——跳过已抓详情、合并历史主库防丢（commit 随本报告）。
3. **nfra 周调度入口 = `nfra_weekly`**（顶部窗口增量），不要用 `nfra_collector` 全量离线重建。
4. mof/pbc 现行为已是"记录级增量/URL 复用"，保留。
5. clean 全量重清洗成本可控（~秒级），保留日期化快照纪律；supp 重清洗后需 `apply_timeliness_to_cleaned --source supp` 回写时效（权威链）。
