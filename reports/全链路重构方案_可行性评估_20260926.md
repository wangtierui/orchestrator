### 3.2 §4.2 文号提取契约化——❌ 拟导入的符号不存在；且两套实现不可合并

方案原文：

```336:336:reports/全链路重构方案_20260924.md
from std_lib.scraper_std.doc_number import DOCNO_PATTERNS
```

**该符号不存在**：`doc_number.py` 全文无 `DOCNO_PATTERNS`（全仓唯一出现处就是本方案第 336 行），实际用的是私有 `_PATTERNS`（`std_lib/scraper_std/doc_number.py:141`），且文件**无 `__all__`**（仅尾部 `extract = extract_doc_number` / `normalize = normalize_document_number`，L457-458）→ 直接 `ImportError`。

**更关键的是语义不等价，替换会改变抽取结果**：

| | `doc_number._PATTERNS` | `relations.iter_docno_signatures` |
|---|---|---|
| 覆盖形态 | 代字锚定式 / 国务院令 / 公告"YYYY年第N号" 等 15+ 类 | **仅**裸括号式 `[〔\[(（]YYYY[〕\])）]N号` |
| 输出 | 经 `normalize_doc_number` 归一的**完整文号** | `YYYY+N` 的 **6 位数字签名**（如 `201919`） |
| 用途 | 文号识别/补全 | 与归属表「发文字号」数字尾做 `endswith` 命中 |

`relations.py:223-235` 的 docstring 明确写了这是**刻意保持不同口径**：

```python
"""从正文抽取**文号签名**（四位年 + 序号，如 `201919`），含**裸括号式**（无机关代字）。
R-F01 收敛点：`merged.extract_rfns` 的 `docno_sig` 语义即"正文文号签名 → 归属表文号数字尾"
匹配；原正则 `[〔\[(（]\s*(\d{4})\s*[〕\])）]\s*(\d{1,4})\s*号` 只认裸括号式，
本函数保持该语义（区别于 `extract_docnos` 的"带机关代字完整文号"口径）。
"""
```

**结论**：§1.4 把二者并列为「文号提取两套实现」并暗示应统一，**属误判**；§4.2 的处方会同时引入 `ImportError` 与语义漂移（`merged.py` 的 RFN 命中率、`reconcile` 的桥接率都会变）。
