## 二、K1：镜像站准入核验（**实测**，非推断）

`tools/check_mirrors.py --probe`（可复跑复验）：

| 目标 | 结果 |
|---|---|
| 清华 **tuna PyPI** | ✅ `pip download six` **rc=0**（实际取回 wheel，2.4s） |
| 清华 tuna 首页/其他子站 | ⚠️ **可达**，但**浏览器 UA 被 WAF 拒（403「您目前无法访问此页面」）**；`curl/*` 等非浏览器 UA **200 通过**（实测） |
| **hf-mirror.com** 元数据 / 非 LFS 文件 | ✅ `/api/models` 200；`bert-base-chinese/vocab.txt` **HTTP 200，109540B** |
| **hf-mirror** 的 **LFS 大文件（权重）** | ❌ 302 → `cas-bridge.xethub.hf.co`；该主机 **TCP 443 可连但 TLS 被重置**（`curl: (35) Recv failure`；urllib 同）→ **权重通道阻断** |
| `huggingface.co`（官方） | ❌ 超时 |
| `modelscope.cn` / `wisemodel.cn` / `aliendao.cn` / `gitee.com` / `ai.gitee.com` / `atomgit.com` | ❌ HTTPS 连接被重置（TCP 有时可连） |
| `gitcode.com` | ⚠️ 418（WAF）；`raw.gitcode.com` ❌ 重置 |
| `file.hankcs.com`（HanLP 官方权重） | ❌ 连接重置 |
| **GitHub 系**（api / raw / codeload / `objects.` / `media.`） | ✅ **全通**（含 tar 归档 Range 实测 200） |
| Docker registry（`registry-1.docker.io` / daocloud） | ❌ 超时 / 401 |

**结论**：**依赖（pip）与元数据/小文件**已确认可走镜像并已配置；**权重（LFS 大文件）在本环境无可用通道** ——
这是本批的**根本约束**，直接决定 K3/K4/K5 的"权重"部分不可闭环（**如实登记，不虚报**）。

## 四、K3：DeepKE 部署 + **aprcoie 彻底移除**

### 4.1 DeepKE 框架部署（✅）

- 源码：`git clone --depth 1 https://github.com/zjunlp/DeepKE` → `external/upstream/DeepKE`（42MB，`example/re` 关系抽取等在位）
- 许可：**MIT**（读 `LICENSE` 实录）→ 登记入 `license_registry.verified`
- **新增探测类型 `source_tree`**（`semantic_tools.probe()`）：源码树框架**无 pip 包**，用 `module` 会报"未装"、
  用 `manual` 无法表达"已部署"、用 `local_model` 会**误承诺权重**。故新增一类：
  **可用性 = 源码树就位（`expect_files` 实检）+ 运行时依赖可导入**；
  **权重可得性另由清单 `weights` 元数据如实记载** —— **框架与权重分开表达**
- 实测：`{"kind":"source_tree","available":true,"offline_ready":true,"runtime_missing":[],
  "detail":"源码树就位（external/upstream/DeepKE；指纹 4b698ea390ac）"}` ✅

### 4.2 ⚠️ DeepKE **微调权重不可得**（硬阻断，如实登记）

候选（均在 hf-mirror 上**存在且元数据可读**）：`zjunlp/OneKE`（双语开放信息抽取，**分片权重 + `all.md5` 校验**）、
`zjunlp/KnowPrompt`（关系抽取 `f1=0.90.ckpt`）、`zjunlp/mt5-ie`。
**但**：它们是 **LFS 文件** → 302 到 `cas-bridge.xethub.hf.co` → **TLS 被 SNI 层重置**（§二）。
**解封路径**：在可达环境下载后离线迁入 `external/models/DeepKE-<name>/` 并按 `local_dir` 登记。
**可用替代**：`external/models/` 已预置 **bge-base-zh-v1.5 / text2vec-base-chinese**（BERT 族编码器），
DeepKE 的推理/训练可复用它们作基线编码器。

### 4.3 **aprcoie 彻底移除**（用户明示：不再保留为降级方案）

| 位置 | 处置 |

### 4.4 ⚠️ DeepKE 运行时的**依赖冲突**（未识别问题，已登记）

`requirements.txt` 钉死 `torch<=1.11 / transformers==4.26 / numpy==1.21 / scikit-learn==0.24`，
与主栈（`torch 2.14.0+cpu` / `transformers 5.17.0`）**冲突** → **`pip install -r` 会摧毁现有语义栈**。
故：框架按**源码树**就位，运行须**独立 venv** 或仅取最小推理子集（已写入清单 `runtime_note`）。

## 六、K6：接入主链 + **修复入链问题**（本批核心价值）

### 6.1 用户三项抱怨的**根因定位**

| 用户所指 | 根因（实测） |
|---|---|
| 「**入链节点配置不佳**」 | `MODEL_BINDINGS` 把 `bge_base_zh`/`text2vec`/`youtu_embedding` 绑在 **`classify:all`** 上，而该节点**并无嵌入调用点** → **绑定指向不存在的调用点＝纸面接线** |
| 「**需要接入模型的节点未成功接入**」 | `clauses` 节点的 LTP **已接线但默认关**（`REG_ORCH_SEMANTIC_SPLIT` 未置）→ 从链路视角"未接入" |
| 「**部分节点模型未能成功入链**」 | 嵌入模型**权重依赖全就绪**（`external/models` 12.5GB）且 `preflight` **五道闸全过**，但**主链无任何调用点** |

### 6.2 修复

1. **新建真实调用点 `tools/semantic_assist.py`（链步骤 `semantic:assist`）**：
   以 `THEME_TITLE_KW`（主题关键词 **SSOT**，10 主题）为原型 → 嵌入 → 对 cleaned 抽样做**最近邻主题裁定**，
   输出 top-1 主题、**相似度**与 **margin（top1−top2）**、建议分布、**与确定性归属的一致性**（有基线时）、
   **分歧清单**、以及**指纹**（模型名/版本/权重 sha）；
   产物固定落在 `reports/semantic/`（**硬校验：绝不写事实源**）。
2. **绑定改指真实调用点**：`bge_base_zh`/`text2vec`/`youtu_embedding` → `semantic:assist`（`wired=true`，
   `gate=usage_policy.enabled`）；`bge_base_zh@relations`/`youtu_embedding@relations` **如实保持未接线**
   （关系语义档本轮未落地，不虚报）。
3. **新增 `source_tree` 探测类型**（§4.1）—— 让"框架已部署"可被机器判定。
4. **`usage_policy` 增 `adoption` 子块**：把「**产出分析视图**（只读、可回退）」与「**采信改判**」**分开表达** ——
   前者 `enabled=true`（安全），后者 `adoption.enabled=false` + 阈值 **刻意留空**（须先由可评样本 P/R 定值）。
