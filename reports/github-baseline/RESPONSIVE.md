# 响应式：同一控件在四个断点下的表现

- 采集时间：`2026-11-03T19:53:38`
- 方法：`Emulation.setDeviceMetricsOverride` 逐宽度重设视口 → 重新加载 → 量可见性与几何
- 原始数据：`responsive.json`

| 控件 | 1440 | 1012 | 768 | 544 |
|---|---|---|---|---|
| top-search | 191×32 | 32×32 | 32×32 | 32×32 |
| filter-author | 89×32 | 89×32 | 89×32 | 89×32 |
| density | 65×32 | 65×32 | 65×32 | 65×32 |
| list-search | 1047×30 | 619×30 | 375×30 | 407×30 |
| tab-open | 102×30 | 102×30 | 102×30 | 102×30 |

## 读出来的规律

- `top-search`：1440 时 **191×32（带文字）**，其余三档一律 **32×32（只剩图标）** → GitHub 在 1012 以下把搜索收成图标，而不是隐藏；
- `list-search`：1047 → 619 → 375 → 407，窄屏不是等比缩小，而是**换行后重新分配**；
- `density`（密度开关）与 `filter-author` 在四档都**始终可见**，只是位置从右侧行内（1327/614）挪到左侧换行区（37/67）；
- 断点值可按 Primer 记：544 / 768 / 1012 / 1280；本次实测在 1012 与 1440 之间发生了折叠。
