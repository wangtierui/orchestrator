## 二、表格结构化：评估结论与"最优方案"（已执行）

### 2.1 评估：**存在优化空间，且不是效率问题而是"丢数据"问题**

实现全貌：`excel_matrix`（矩阵原语：内容边界/上限/表块/表头）→ `excel_structure`（分类化 v2：统计表/说明表、维度列识别、行列投影）
→ `table_recovery.structured_table_fields`（统一入口；xlsx/xls 走 v2，其余走矩阵轨）。

**逐场景量化后确认 9 类会丢表格数据，其中 4 类"静默丢"（无任何落盘标记）**：

| # | 场景 | 是否静默 | 处置 |
|---|---|---|---|
| **⑤** | 统计表**无指标值的行**（名录/分类标题/**小计行**）被裁掉，且 meta 无计数 | ✅ 静默 | **已修**：不再裁行；行数/指标行数双计（`metric_row_count`） |
| **④** | 稀疏指标列被阈值裁剪，**被裁列的单元格值**消失 | ⚠️ 有计数无值 | **已修**：值留痕 `meta.sparse_metric_values`（列 → {行序: 值}） |
| **⑥** | 无指标回退时只留有 `fill≥2` 的列 ⇒ **孤值列**丢失 | ✅ 静默 | **已修**：改为 `fill≥1`（保留一切有值列） |
| **⑮** | `.xlsm/.xlsb` 走矩阵轨 `_tables_from_xlsx`：按**声明维度**逐行展开且**无上限**（与 N-208 同型） | ✅ 静默 | **已修**：右裁空单元格 + 连续空行视为表尾 + `XLSX_MAX_ROWS` 上限 |
| **⑩** | supp 本地目录收录**覆盖** `table_structured`（原采集已抽到的表被抹掉） | ✅ 静默 | **已修**：改为**合并**（保留既有 + 追加新） |
| ③ | 矩阵硬上限（200k 行 / 1024 列）截断只 WARNING，**记录里无标记** | ✅ 静默 | **未做** → W-N |
| ⑧ | xlsx 公式**无缓存值**时取值 None，无检测/标注 | ✅ 静默 | **未做** → W-N |
| ⑦ | 表头 >4 行 / 注释行 >2 行时超出部分语义漂移 | 部分 | **未做** → W-N |
| ⑨ | 扫描件 PDF / 无边框表：表格轨完全无产出 | 有 notes | 登记（能力边界） |

**关键洞察（"省体积"与"保完整"可以同时满足）**：原实现靠**裁行**消除海量 null（实证 1178105：3379 名录行 × 21 空列 ⇒ 71k null）。
本批改为**保全部行 + 紧凑投影（省略空值键）**⇒ 既不丢行，也不产生 null 膨胀 ✓。

### 2.2 最优方案（已执行，4 步）
1. **不裁行**：`_build_stat_unit` 去掉 `rows = metric_value_rows`（名录/小计行保留；`dimension_rows` 因此自然覆盖全部行）；
2. **紧凑投影**：`{k: v for k in kept_keys if not _is_blank(v)}`（空值键省略，体积不增）；
3. **不丢值**：被裁稀疏列的有值单元格落 `meta.sparse_metric_values`；无指标回退改 `fill≥1`；
4. **审计化**：`meta.metric_row_count` 双计 + ⑮ 路径上限告警 + ⑩ 合并语义。

（③/⑧/⑦ 的"静默 → 可审计"改造思路已定：矩阵轨补 `truncated` 元数据、公式缓存检测落 `meta`、表头上限标记；因本批预算与风险收敛**未执行**，见 §四。）

（⚠️ 批 48 的 W-A/W-B/W-D 为**同字母不同义**（refactor 转交 / 279MB 数据层治理 / 四源 raw 迁移），勿混用。）

### 3.2 W-A / W-B / W-D（已交付）
- **W-D 零落盘**（`pbc_serve.py`）：`translate_path` 不再写 `.json` 视图；新增 **`send_head` 覆写**：命中缺失的 `.json` 时由同目录 `.jsonl` **现读现渲染进响应体**（`BytesIO`，零落盘），渲染失败仍 404。
- **W-A 去冗余**（写侧 + 映射侧）：
  - 写侧停止记录级聚合副本：`gov_collector`（`d["attachment_text"] = att_text`）、`gov_zhengceku`（`"attachment_text": att_text`）、`mof_attachments`（`"attachment_content": "\n\n".join(...)`）；
  - cleaned 侧改**按真附件派生**（`unified_schema` gov/mof 两处）：`... or "\n\n".join(str(a.get("text") or "") ...)` ⇒ **交付口径不变**（等价于原聚合），仅消除 raw 双份。
- **W-B 接线**（交付链）：
  - 新增 `attachments.sidecar_record_content(rec, content_dir, *, threshold=200_000)`（记录级；内容寻址文件名 `<sha16>.txt`；主数据置 `attachment_content=""` + `attachment_content_path` + `attachment_content_md5`；`_metadata` 记 `attachment_content_sha256` / `attachment_content_sidecar`）；
  - 接入 `pipeline.py` 映射后（`data/docs/shared/attachment_text/`）⇒ **原死代码机制的承诺（"超大附件折中"）首次真正生效**；
  - ⚠️ 与既有实现的差异如实登记：`attachment_content_md5` 列沿用既有语义**存 sha256**（算法明示于 `_metadata`），未改列名以免动契约。

### 3.3 W-I supp 附件多格式抽取（已交付）
- `supp_parser.extract_document_text`：PDF 路径**不变**（pypdf 文本层 → Tesseract OCR）；非 PDF 或 PDF 解析失败 ⇒ **委托共享抽取器** `crawler_common.extract_document_text`（含 N-208 后的 XLSX 剪裁/上限、docx/xlrd/OLE2 分派）⇒ 实测 docx 表格与 xlsx 单元格文本均可取出。
- **途中新发现并同步修复**：`supp_parser.py:33 from supp_ocr_pdf import ocr_scanned` 在**包式导入**（`modules...collectors.supp_parser`）下必然 `ModuleNotFoundError`（脚本式导入才成立）⇒ 改为 try/except 双形态导入 ⇒ **该模块首次可被测试与包内调用**（此前只能脚本运行）。

### 3.4 W-H 非五源 naive xlsx：**核实边界 + 登记（未改码，如实说明）**
| 点位 | 实际用法 | 风险评估 | 处置 |
|---|---|---|---|
| `tools/build_east_backlog.py::extract_xlsx` | `load_workbook(read_only=True, data_only=True)` + 逐行读取（read_only 流式） | **无 N-208 型内存爆量**；按声明维度迭代有 CPU/耗时开销 | 未接共享原语 → **W-L** |

| 其他（非五源） | `modules/internal_policy_drafter/**` 等 | 不在 raw 写入链 | 登记 |
