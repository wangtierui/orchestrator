## 二、变更摘要

### ① 三层分工固定（不得混用）

| 层 | 模块 | 回答的问题 |
|---|---|---|
| 探测 | `semantic_tools` | **有没有**（依赖 + 权重 + 离线就绪）；事实源 = `config/schema/semantic_tools.json` |
| 加载 | `semantic_models` | **怎么装进内存**（本地路径 / 强制离线 / 池化 / 兼容垫片） |
| **执行** | **`semantic_enhance`（本批新增）** | **用什么（选型）/ 怎么传参 / 出错怎么办** |

业务代码**只依赖执行门面**；禁止直接 `import transformers/ltp`（`policy.gate` 明令）。

### ② 调用入口 / 参数传递 / 异常处理路径（**唯一约定**）

**入口**：`se.embed(...)` / `se.split_sentences(...)` / `se.describe()` / `se.fingerprint()`
＋ **CLI**：`python -m std_lib.common_lib.semantic_enhance --describe|--embed|--split`

**参数**：`mode`（场景）/ `model`（显式覆盖，优先级最高）/ `batch`（控内存）/ `normalize`（L2 归一，默认 True）
/ `strict`（**异常语义开关**）/ `level ∈ {strict, loose}`（**受控 SSOT**：`sentence_boundary`）

**异常路径**（**链式降级，绝不吞错**）：
```
候选链逐个尝试 → 成功：返回实际模型名 + 指纹（写 provenance）
                → 失败：记录原因，试下一个
链耗尽 → strict=False（默认）：返回 ok=False + 打印 fallback_notice（**可观测**）
       → strict=True       ：抛 EnhanceUnavailable（含每个候选的失败原因）
```

### ③ 模型选型策略（**用户明示，落入清单 SSOT**）

| 场景 | 首选 | 降级链 | 依据 |
|---|---|---|---|
| **`full`（默认）** | **`bge_base_zh`** | `text2vec` | 全量批处理（17k+）：768 维、CPU ≈0.06s/句 |
| **`incremental` / 显式指定** | **`youtu_embedding`** | `bge_base_zh` → `text2vec` | 2B/2048 维更强，但 ≈3.5s/句 → 仅小批量 |
| `model="…"` | 该模型 | 同 mode 链 | **覆盖 mode** |

### ④ 执行接线（真实节点）

`std_lib/common_lib/relations.py::split_sentences`（**抽取层切句，挂接 `relations:gen`**）
→ 改为经门面 `semantic_enhance.split_sentences(text, level="loose")`：

* **默认（ML 关）**：仍走 `sentence_boundary.split_by(text,"loose")` ⇒ **逐项一致（零回归，已实测）**；
* 置 `REG_ORCH_SEMANTIC_SPLIT=1`：走 **LTP 分词锚切句**（增强），失败**自动回退并留痕**。

> **为何默认关**：分句口径变更会改变条文/关系产物 → v2 纪律「无度量不得上线」，
> 须先在**可评样本**量出 P/R 再启用（开关已就绪，一行 env 即可启用）。
