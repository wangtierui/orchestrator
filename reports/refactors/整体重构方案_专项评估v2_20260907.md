## 2. 专项二：RFN ↔ 五源重清洗变化的对应

### 2.1 现状事实（实测）
- RFN 派生：`registry.unique_key()` → `"DOC:"+文号|md5(标题)[:8]` 或 `"MD5:"+md5(标题|来源|发布日期)`；`rfn_of = "RFN-"+md5(去重键)[:16]`（`rfn/registry.py:94-109`）→ **去重键含 title/docno，重清洗改 title/docno 会重派 RFN**。
- 归属表 8 列无 `source_url/dedup_key/index_no` 稳定技术键；`文件指纹.csv` 表头 6 列与 registry `FP_FIELDS` 5 列存在漂移（待治理项）。
- recall 关联仅用 **文号+标题归一化**：`scanner.match_808`（`scanner.py:226-230`）、`build_outputs.py` 按文号+标题去重/归集 → 重清洗改名/改号后**同实体可能匹配不上、或误当新文件重注册产生双 RFN**。
- clean 的稳定键 `dedup_key = sha256(index_no|source_url, source_url, publish_date)`（`unified_schema.build_dedup_key`，**不含 title/docno**），但 gov index_no 取自文号（`map_gov: index_no=_resolve_doc_number(rec)`）→ dedup_key 在文号变化时**非绝对稳定**；真正跨快照稳定的溯源锚是 **source_url**。
- timeliness 层 `verification_state.sync_to_classifier`、`diff_timeliness` 均按 文号/标题 键比对，无技术键。
- `check_rfn_sync` 仅校验 doc_no 一致性（标题不比对；超白名单 exit 1，可 --fix）。

### 2.2 问题定义
"五源重清洗导致 clean 内某文件的 title/document_number 变化"有两类：
- **C1 展示字段纠错**（补"有关"、去括号后缀、文号括号半/全角、错字修正）→ 实体未变，RFN **应保持不变**，归属表展示字段可刷新。
- **C2 实体真变化**（文号年度/序号实质变更、标题实质改写、新版本）→ 按现行去重键规则**应派生新 RFN**（历史旧 RFN 保留并标注 superseded 关系）。

### 2.3 方案（推荐：桥接表 + L0 溯源锚优先 + 漂移门禁）

**① 建立 RFN↔clean 溯源桥（新仓新增）**
新增 `modules/regulatory_classifier/data/rfn_clean_bridge.csv`，列：
`监管文件编号, 文件来源, source_url, dedup_key, 登记时标题, 登记时文号, 最近确认日期, 最近状态`
- 由 recall 扫描/注册时同步维护（RFN 确定后反查该 clean 行 source_url/dedup_key 落桥）。
- **归属表 8 列、主题归属表 3 列不增列**（保持 Gate4 `CSV_FIELDS` 契约零变更）；桥独立成表，规避 Gate4 schema 预检波及。

**② 召回/注册匹配升级为四级（替代现二级）**
`query_or_register` / `scanner.match_808` 统一走 interfaces 提供 `match_regulatory_record()`：
1. **L0 溯源锚**：`source_url` 精确 或 `dedup_key` 精确 → 命中既有 RFN（重清洗首选命中，实体稳定）；
2. L1 文号归一化精确（现逻辑）；
3. L2 标题归一化精确（现逻辑）；
4. L3 标题双向包含 + 文号佐证（现逻辑）。
- 命中既有 RFN 时：若 title/docno 与桥/归属表不一致 → 记为 **drift 候选**（不直接改），进入 ③。

**③ 漂移处置（C1/C2 分流，人工确认 + 幂等脚本）**
新增 `modules/regulatory_classifier/scripts/reconcile_clean_drift.py`：
- 扫描归属表 vs clean latest（经 clean_index 动态取）title/docno 差异 → 产出 `reports/drift_清单_<date>.csv`；
- 每行建议 `keep_rfn+refresh_fields`（C1）或 `new_rfn+link_supersedes`（C2），由人工确认；
- 确认后脚本执行：
  - C1：**更新归属表/主题归属表展示字段与指纹**，RFN 不动，写 sync_status + audit 变更记录；
  - C2：走 `register_doc` 生成新 RFN，旧 RFN 记录 superseded_by 关系（新增归属表"编号备注"列注记或桥表记录），不删旧行。
- 门禁：`gates/gate_rfn_drift.py`——clean 重清洗后 drift 清单**有未处置 C1/C2 候选即 FAIL**（提示先跑 reconcile），阻断下游 base/final 重建，防止双 RFN 或错配底座静默入库。

**④ 同步治理**
- 修正 `文件指纹.csv` 表头与 `rfn.registry.FP_FIELDS` 的 5/6 列漂移（纳入 gate_rfn_sync 检查）。
- `check_rfn_sync` 增加 title 漂移提示级（WARN，不直接 FAIL），避免重清洗常见改字导致整仓门禁卡死。

### 2.4 该方案与既有体系的衔接
- 依赖关系不变：`recall_audit` 仍消费 clean_index + 归属表；桥表与 reconcile 脚本归 classifier scripts（现行链成员）。
- 枚举/门禁纪律不变；`run_gates.py` 门禁序列增补 `gate_rfn_drift`（第 8 道）。
- RFN 生成规则**不改**（避免既有 1,059 条重编号）。

## 3. 专项三：共享库统一（消除重复编写）

### 3.1 现状事实（实测）
- **已有事实源**：`std_lib/scraper_std/`（24+ 模块）是 scraper 五源清洗事实源；`std_lib/scraper_std/common/`（10 模块）被 cn_law_hub 13/14 模块 import；`std_lib/scraper_std/scripts/{downloader,parser,spider_main}.py` 为四源壳的事实源；repo 根 `fs_lock.py`（原子写 + PidFileLock/ProcessLock，N-8 SSOT）已被 gov/mof/pbc/nfra + classifier diff_timeliness 引用。
- **重复编写点（实测清单）**：
  1. `norm_docno/norm_title`：classifier `recall_audit/scanner.py:79/85`、`build_outputs.py:23/28`、`probe_mapping.py:24/31`（+ `*_protocol.py` 死路径）各自本地实现；`rfn/registry.py` 另有 norm_docno；`drafter/scripts/verify_regulatory_citations.py` 自实现 `_norm_docno/DOCNO_CORE_PAT`；均**未 import** `scraper_std.doc_number`（五源 2026-09-05 已统一的文号模块）。
  2. 原子写/锁/指纹：`fs_lock.py`（N-8）vs `rfn/registry.py` 自带 `_save_csv_rows`(os.replace)+`_lock`(msvcrt)+`fingerprint` vs `mof_law_scraper` 自写 `_atomic_write` vs `scraper_std/common/file_io.py`（非原子）——同功能 3–4 处。
  3. classifier 现行链**无直接 scraper_std import**（仅 import clean_index/fs_lock）；`scanner/build_outputs` 通过 `sys.path.insert(0, "D:/WorkBuddy/regulatory_scrapers")` 跨仓取 clean_index——重构后此盘符硬编码一并消除。

### 3.2 方案（共享库单副本 + 依赖面收口）
在新仓收敛为**一个**共享库：

```
regulatory_compliance_orchestrator/
├── std_lib/scraper_std/                 # ★ 唯一共享库（复制自 scraper std_lib）
│   ├── unified_schema.py  pipeline.py  cleaner.py  doc_number.py  http.py ...
│   ├── common/  (cache/ratelimit/file_io/text_utils/logger/...)
│   └── scripts/  (downloader/parser/spider_main)
├── std_lib/common_lib/                  # ★ 新增通用层（跨域共用，scraper_std 之下）
│   ├── paths_api.py         # 路径解析封装（自 paths.py 抽取；业务只调它）
│   ├── fs_lock.py           # 迁移 repo 根 fs_lock.py（N-8）
│   ├── io_atomic.py         # 原子写 csv/json/jsonl（os.replace 统一收编）
│   ├── norm.py              # norm_docno / norm_title 唯一实现（内部委托 scraper_std.doc_number + rfn 归一）
│   ├── index_store.py       # "get_index() 单例 + 持久化 JSON 索引"模式复用件（供 clean_index/RFNIndex/internal index 共享骨架）
│   └── audit.py             # 写操作审计（audit_log 追加）
```

收口规则：
1. **所有 norm 归一调用统一走 `std_lib/common_lib/norm.py`**；classifier recall_audit / registry / drafter verify 删除本地 norm_docno/norm_title/`_norm_docno` 副本，改 import（docstring 注明单一来源）。
2. **所有文件锁统一 `fs_lock.ProcessLock/PidFileLock`**；registry 的 msvcrt `_lock/_unlock` 改委托（跨平台、与 nfra 周锁一致）。
3. **所有原子写统一 `io_atomic`**；registry `_save_csv_rows`、mof `_atomic_write` 改调用它（`scraper_std/common/file_io.py` 若保留则委托 io_atomic，保持非原子函数仅测试用）。
4. **所有 sha256/指纹统一**（registry.fingerprint / scraper_std / file_io 合并为 `io_atomic.sha256_file`）。
5. **clean_index 由 scraper 根迁移到共享可引用处**：因 classifier 已依赖它，新仓将其作为 `std_lib/scraper_std/clean_index/` 或 `std_lib/common_lib/clean_index/` 单副本（由 interfaces/clean_index_api 引用），classifier 通过**相对共享库 import**（同仓内路径），消除 `sys.path.insert(0, "D:/WorkBuddy/regulatory_scrapers")`。
6. 共享库**禁止反向 import modules/**（依赖方向单向）；modules 依赖共享库经 `std_lib` 前缀。
7. 枚举一致性：`config/enums.py` 为唯一枚举事实源（v1 §6.2），`scraper_std/unified_schema.py` 从它再导出并保留 `assert_enum_bindings`。

### 3.3 落地验收
- 新增 `gates/gate_no_duplicate_libs.py`：扫描 modules 四仓 .py，检测"本地重复定义 norm_docno/norm_title/_atomic_write/msvcrt 锁"即 FAIL；检测 `sys.path.insert` 中盘符字面量即 FAIL（与 gate_hardcoded_paths 联动）。
