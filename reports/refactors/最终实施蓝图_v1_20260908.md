## 3. 职责边界与单向数据流

```
[采集层]
  external: 五源(collectors) → data/raw/{src}.json(仅json, N1)
  internal: 制度原文 → internal_policy_base(scanner/OCR/parser) → internal_policy_index
[清洗层]
  external: scraper_std.pipeline.run_pipeline(--project) → data/cleaned/{src}_cleaned_{date}.{csv,jsonl}
            sanitize 内置(N2)；附件文本统一 attachment_content(N3)；clean_index/index.json
[知识层]
  classifier: recall_audit(召回) → rfn.register_doc/归属表(8列不变)
              → reconcile_clean_drift(RFN↔clean, Q1/Q2) → 主题归属(T0-T10)
              → 40 底座/11 明细/upper_laws → report_builders(docs)
[对齐层]
  internal_policy_base.aligner: 内部制度(IPN) ↔ 监管主题/RFN → merged_view.json
[应用层]
  drafter: 读 merged_view+底座 → 草稿/对照/六件套 → verify 门禁 → 回写 internal index(版本链)
[编排层]
  cli.py 全阶段 + pipeline --all 幂等 + gates 9 道 + git(pre-commit) + 单一 automation
```

## 5. 全链路阶段与自动化（pipeline --all）

| 阶段 | 命令 | 输入→输出 | 幂等 | 门禁后验 |
|---|---|---|---|---|
| P1 collect | `orchestrator collect --source {s}` | 官网→data/raw/{s}.json | 增量+断点 | — |
| P2 clean | `orchestrator clean --project {s}` | raw→cleaned(双轨,sanitize) | 原子写+history | check_pipeline_contract(S-4) |
| P3 index | `orchestrator index --refresh` | cleaned→clean_index/index.json | 是 | validate_files |
| P4 retrieval | `orchestrator retrieval` | cleaned→召回交付物 | 四门禁+签名 | gate(clean/validity/contract/schema) |
| P5 classify | `orchestrator classify` | 归属表→40底座/11明细/upper | 是 | _verify_written+check_rfn_sync |
| P5b report | `orchestrator report --theme T1..T10` | 底座/明细→docs 报告 | 是 | 内容对照 |
| P6 internal | `orchestrator internal scan` | 原文→internal index | 增量 | schema 校验 |
| P7 align | `orchestrator internal align` | internal×监管→merged_view | 是 | 对齐覆盖统计 |
| P8 draft | `orchestrator draft` | merged_view→草稿/六件套 | 是 | gate_citations --strict |
| P9 gates | `orchestrator gates` | 全仓 | 是 | exit 0/1 |
| T0 timeliness | `orchestrator timeliness {verify,sync,consolidate,report}` | 核验→**自动**传播(P2/3/4/5 受影响层) | 签名断点 | gate_timeliness_ssot |

触发调度（单一 automation 语义）：
- 每周二 01:00：collect(五源)→clean→index→retrieval→classify→report（增量）
- 每日 06:00：retrieval/classify 签名变化检测 + internal scan/align
- 每次核验后：timeliness verify→sync 自动传播
- 交付前：gates + pre-commit

## 6. 门禁与 git

- 9 道 gates：① scraper_std SSOT(junction) ② check_rfn_sync ③ gate_citations --strict ④ gate_hardcoded_snapshots ⑤ check_flat_layout ⑥ check_pipeline_contract ⑦ gate_enum_values --strict ⑧ **gate_rfn_drift**（漂移未处置即 FAIL）⑨ **gate_no_duplicate_libs**（重名重复定义/sys.path 盘符即 FAIL）+ **gate_hardcoded_paths**（盘符字面量，v2 新增，故为 10 道，若含 SSOT/契约/timeliness 则为 12 道——最终以 gates/ 清单为准并全部纳入 pre-commit）。
- git：初始提交（无数据）；每阶段 Pn 完成一次 commit + 对照 diff 记录；`.gitignore` 排除 data/cache/logs/venv/backups；大数据用复制快照（data_migration_manifest 追踪）不入库。
- pre-commit：ruff/mypy + 门禁脚本（替代原"无 git 手动 run_gates"）。

## 7. 共享库统一（复用于 internal_policy_base）

- `std_lib/scraper_std`（复制自 scraper）唯一领域共享库：清洗/OCR/文号/docx/附件/条文分段 + **新增 document_structure（章-条-款-项/目录树抽取）**。
- `std_lib/common_lib`：跨域通用件（fs_lock/io_atomic/norm/index_store/audit）。路径入口以根 `paths.py` 为准（common_lib/paths_api 归一，蓝图修订项 R4）。
- OCR：`get_ocr()`（PaddleOCR→Tesseract 降级）唯一；引擎路径入 `config/ocr.yaml`；tessdata 随仓；PaddleOCR venv editable 指向由 config 解析，禁止硬编码。
- 依赖方向：modules → std_lib；common_lib 不得 import scraper_std（分层规则文档化）；modules 间禁直连，一律 interfaces。
- 全仓 import 禁止 `sys.path.insert` 盘符；测试可用 conftest 注入 repo root。
