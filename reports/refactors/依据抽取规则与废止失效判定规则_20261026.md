
## 依据抽取规则与废止/失效判定规则-总则

**R-GEN-01 规则适用范围**

本规则适用于行政规范性文件与政府规章的**依据关系抽取**与**废止/失效判定**。政府规章的废止程序与规范性文件存在差异（规章废止决定一般提请政府常务会议研究决定，规范性文件可报请政府负责同志审签），但废止与失效的实质情形在清理标准上共享同一套法定清单，规则层不做实体情形区分，仅在 `procedure_source` 与 `execution_status` 中保留程序差异（[17†L45-L47]）。

**R-GEN-02 废止与失效分列原则**

“废止”与“宣布失效”是两条独立的法定路径，对应不同的情形清单与法律效果。任何规则不得将二者混入同一状态字段或同一理由映射表。清理决定文本中，二者通常分列于不同的决定条款和不同的附件目录（[19†L9-L11]）。

**R-GEN-03 终态不由单一文本信号产出**

任何单一关键词命中或单一规则输出均不构成“已废止/已失效”的终态。终态必须经过程序来源赋值、执行状态判定、冲突消解和时间区间构建后，由 R-QC-03 合成。


## 第一层：依据关系抽取规则（R-DEP）

### R-DEP-01 制定依据句式抽取

**规则描述**：在条款作用域内定位“根据”引导词，取其后同一句内第一个书名号内容作为依据文件名称。列举制定依据时，文件名称应使用**全称并加书名号**，同时注明文号、公布时间及现行有效状态；文号中年份使用六角括号〔〕。

**模式**：`(?:根据|依据)\s*《([^》]{2,80})》`

**输出**：`relation = depends_on`，`relation_subtype = legislative_basis`（当所在条款含“制定本×”时）或 `application_basis`（其余情形），`target_name`，`trigger_word`，`evidence_span`。

**边界**：不按“根据/依据”的引导词本身区分立法依据与适用依据（二者实践中混用）；仅以**所在条款是否含“制定本×”** 作为 `legislative_basis` 的判定标准。此修正关闭 BUG-11。


### R-DEP-02 第一条优先锚定

**规则描述**：若第一条含“制定本×”且句中出现依据引导词，优先在该条款内执行抽取，`confidence = high`，`anchor = "第一条"`。第一条未命中时回落至全文扫描，但回落**仅针对 `legislative_basis` 子类型**，`application_basis` 不因回落而升级为 `high`。

**边界**：此修正关闭 BUG-12。


### R-DEP-03 多文件并列拆分

**规则描述**：一次依据引导词后连续出现多个书名号时，拆为多条独立 `depends_on` 边，共享 `group_id` 与 `trigger_word`。抽取范围为引导词到句末标点（`。；;`）之间的全部书名号。


### R-DEP-04 依据粒度到条款

**规则描述**：书名号后紧跟“第X条”时，`target_clause` 记录条号；否则 `target_clause = null`。

**模式**：`《([^》]+)》\s*(第[一二三四五六七八九十百千]+条)`


### R-DEP-05 文号同步抽取

**规则描述**：依据文件名后紧跟括号且括号内含“〔〕”文号格式时，抽取文号作为消歧键。

**模式**：`《([^》]+)》\s*[（(]\s*([^）)]*〔\d{4}〕\d+号[^）)]*)[）)]`

**输出**：`target_doc_number`。


### R-DEP-06 非文件依据排除

**规则描述**：引导词后接会议、批复、批示、讲话、实际情况、统计资料等非规范性文件对象时，**不建依据边**，记入 `excluded[]`。

**黑名单模式**：`(?:会议精神|会议决定|批复|批示|讲话|实际情况|统计资料|调研结果)`


### R-DEP-07 无书名号指称的候选抽取与匹配回填

**规则描述**：依据引导词后同一句内无书名号，但存在尾缀词表命中（办法/规定/通知/意见/决定/细则）或发文字号格式（`〔\d{4}〕\d+号`）时，作为 `target_name` 候选，`extraction_method = suffix_or_docnum`，`confidence = medium`，进入 `pending_match` 队列。

**匹配回填规则**：匹配成功后回填 `target_doc_id`，`confidence` 升级为 `high`（文号精确匹配）或 `medium`（名称模糊匹配），升级后的边**参与 R-REP-04 依据灭失推理**。匹配失败则标记 `unresolved_reference`，不参与推理，进入人工核查。此修正关闭 BUG-10。


### R-DEP-08 依据类型词表分类

**词表**：`法 / 条例 / 规定 / 办法 / 细则 / 规则 / 意见 / 通知 / 决定 / 批复 / 标准 / 纲要 / 规划 / 方案 / 公告`

**输出**：`target_doc_type`；未命中标 `unknown`。


### R-DEP-09 简称与指代补充抽取

**规则描述**：正则/规则引擎抽取高确定性实体（书名号、文号、条号）后，用轻量 NER 补充简称（“该办法”“前述规定”）和上下文指代。`extraction_method = ner` 的边需经文件库匹配确认后方可建边；未匹配的进入 `unresolved_reference`，不参与自动状态计算。


## 第二层：废止与失效的法定情形与信号抽取（R-REP）

### R-REP-01 明示废止句式抽取（文档级，排除名词化误报）

**规则描述**：在文档级定位“废止”动作，取其前最近的书名号为被废止文件；动词前无书名号时向后取。

**名词化排除**：`废止` 前后不得紧跟 `后|前|时|之日|程序|工作`，以避免将“《XX》废止后”“废止程序”等名词化表述误判为废止动作。此修正关闭 BUG-7 的现象二。

**日期语义**：

- 句式为“原《X》同时废止”且同句有“自……起施行” → `target_end_date = 新文件施行日`；
- 句式为“《X》自……废止” → `target_end_date = 该日期`；
- 无日期 → `target_end_date = 废止决定公布日`（从版记或成文日期取）。

字段统一为 `target_end_date`，不得复用 `effective_date`。此修正关闭 BUG-7 的现象一。

**输出**：`relation = repeals`，`relation_subtype = explicit`，`target_name`，`target_end_date`。


### R-REP-02 废止/失效目录表抽取（表标题定大类）

**规则描述**：附件为表格时，**首先以表标题确定大类**，其次以理由列名辅助确认，最后才在已定大类内进行子类映射。

| 优先级 | 判定依据 | 结果 |
|---|---|---|
| 1 | 表标题含“废止” | 行级大类 = `REPEAL_*` |
| 2 | 表标题含“失效” | 行级大类 = `INVALID_*` |
| 3 | 表标题缺失，理由列名含“废止理由” | 大类 = `REPEAL_*` |
| 4 | 表标题缺失，理由列名含“失效理由” | 大类 = `INVALID_*` |

大类确定后，R-REP-03 仅在该大类内映射子类；子类未命中时分别退化为 `REPEAL_OTHER` 或 `INVALID_OTHER`。清理实践中，废止目录与失效目录通常作为两个独立附件并列，表头列名可能相同，因此表标题是唯一可靠的大类信号（[5†L4-L8][12†L12-L13]）。此修正关闭 BUG-6。

**输出**：每行一条边，`row_index`，`reason_text`，`edge_major_class ∈ {REPEAL, INVALID}`。


### R-REP-03 法定情形子类映射（废止与失效分列）

**规则描述**：对 `reason_text` 在 R-REP-02 已确定的 `edge_major_class` 内做子类映射。映射表以河北省清理办法第八条、第九条及贵州清理决定的实践表述为基准。

**废止（REPEAL_*）映射**：

| 代码 | 关键词模式 | 法定情形 |
|---|---|---|
| `REPEAL_UPPER_CONFLICT` | `相抵触\|不一致\|违反` | 与上位法和国家政策相抵触 |
| `REPEAL_COVERED` | `已被新的.{0,20}(?:覆盖\|替代\|代替)` | 主要内容已被新的法律、法规、规章或规范性文件覆盖 |
| `REPEAL_ULTRA_VIRES` | `超越.{0,10}权限\|擅自设定` | 超越法定权限（如擅自设定行政处罚、许可、收费、强制） |
| `REPEAL_REFORM` | `不适应\|滞后` | 滞后于改革要求，与高质量发展需要不相适应 |
| `REPEAL_BUSINESS` | `放管服\|营商环境` | 不符合“放管服”改革、不利于优化营商环境 |
| `REPEAL_COMPETITION` | `公平竞争\|排除.{0,4}限制竞争` | 妨碍统一大市场，违反公平竞争审查 |
| `REPEAL_OTHER` | 大类已定为 REPEAL 但子类未命中 | 其他需要废止的情形 |

**失效（INVALID_*）映射**：

| 代码 | 关键词模式 | 法定情形 |
|---|---|---|
| `INVALID_PERIOD` | `适用期已过\|有效期已满` | 适用期已过或有效期已满且不需要延期 |
| `INVALID_METHOD` | `管理方式已改变` | 管理方式已改变 |
| `INVALID_OBJECT` | `调整对象已消失` | 调整对象已消失 |
| `INVALID_TASK` | `任务已完成\|事项已办结\|不需要继续存续` | 规定的事项及任务已完成 |
| `INVALID_BASIS_GONE` | **不由本规则产出**（见 R-REP-04） | 作为主要制定依据的法律、法规、规章、政策已经废止或失效 |
| `INVALID_OTHER` | 大类已定为 INVALID 但子类未命中 | 其他原因需要宣布失效 |

`INVALID_BASIS_GONE` **从本映射表中删除**，仅由 R-REP-04 图谱推理产出。文本中几乎不会出现“依据缺失”四字，保留该关键词映射是无效规则，且会与 R-REP-04 重复产出同一代码而无法区分来源。此修正关闭 BUG-3。


### R-REP-04 依据灭失的图谱推理（含部分变更分支）

**规则描述**：若 R-DEP 抽取到的 `legislative_basis` 目标文件（经 R-DEP-07 匹配回填后）的当前效力状态为已废止或已失效，源文件落入“依据灭失”情形。判定不比对条文内容，仅查询目标文件的 `validity_status`。

**分支**：

| 依据文件状态 | 输出 | confidence |
|---|---|---|
| 完全废止/失效 | `INVALID_BASIS_GONE` | `high` |
| 被修改（部分条款变更） | `BASIS_MODIFIED_PARTIAL` | `medium`；不直接判源文件失效，仅生成条款级复核候选 |
| `target_doc_id = null`（未匹配） | 不推理 | — |


### R-REP-05 否定与保留抵消（作用域限定）

**规则描述**：出现“继续有效”“予以保留”“延长有效期”“暂不废止”时，抵消**同一 `target_doc`** 的废止/失效边，置 `edge_status = retained_override`。备注列或他处提及**其他文件**的“继续有效”不触发抵消。此修正关闭 BUG-14。

**输出**：仅修改 `edge_status`，**不直接修改 `doc_status`**。文档级状态由 R-QC-03 在全部边消解后合成。此修正关闭 BUG-8。


### R-REP-06 有效期届满的自动失效（外部延续记录驱动）

**规则描述**：文档级抽取施行日与有效期届满日。规范性文件有效期一般不超过 5 年，冠以“暂行”“试行”的不超过 2 年（部分地方规定为 3 年）；**有效期届满未明确延续的，自动失效**，不需要另行履行废止程序。

**届满判定的关键修正**：不再以“原文本中无延期条款”作为条件（该条件对任何原文件恒为真），改为查询**外部延续记录**。

| 情形 | 处理 |
|---|---|
| 届满日 ≤ `as_of` 且**无**延续决定/重新公布/有效期延长公告 | `end_reason = INVALID_PERIOD`，自动失效 |
| 届满日 ≤ `as_of` 且**有**延续记录 | 按延续记录更新 `validity_interval.end` |
| “自发布之日起施行” | `start = 公布日`，不置 `unknown` |

此修正关闭 BUG-2。

**输出**：更新自身 `validity_interval`，**不产生 `repeals` 边**。


### R-REP-07 默示废止仅生成候选

**规则描述**：“与本文件不一致的以本文件为准”“此前发布的有关规定同时停止执行”等表述构成默示废止，但对象常为类指而非具名。**不自动建边**，仅生成 `candidate_repeal`，`confidence = low`，`edge_status = candidate`，不进入终态计算。


### R-REP-08 公平竞争审查的例外保留

**规则描述**：经公平竞争审查认为具有或可能具有排除、限制竞争效果，但符合《公平竞争审查条例》第十二条所列情形，且**没有对公平竞争影响更小的替代方案**，并**能够确定合理的实施期限或者终止条件**的，可以出台，不得径行标记废止。

**输出**：`REPEAL_COMPETITION` 候选，附加 `exception_possible = true`，并要求关联实施期限/终止条件字段。仅当例外条件不成立（无替代方案且无实施期限/终止条件）或后续评估认定妨碍统一市场时，方可升级为废止信号。


### R-REP-09 外部事实核验（调整对象消失/任务完成/管理方式改变）

**规则描述**：R-REP-03 文本命中的 `INVALID_OBJECT`、`INVALID_METHOD`、`INVALID_TASK` 仅生成 `invalid_candidate`，`confidence = low`。绑定外部事实库（机构变动库、专项整治结项库、管理方式变更记录）后，命中“机构撤销/任务办结/管理方式已变更”的，升级为对应 `INVALID_*`，`confidence = high`；未命中的保持候选。此修正关闭 BUG-5。


### R-REP-10 超越权限的文本识别

**规则描述**：清理实践中“超越法定权限”的典型表述包括“超越部门职能权限制定的”“增加法律、法规规定之外的行政权力事项”“超越职权规定应由市场调节、企业和社会自律、公民自我管理的事项”“擅自设定行政处罚、行政许可、行政收费、行政强制”。命中上述模式时，映射至 `REPEAL_ULTRA_VIRES`，`confidence = high`（若表述明确）或 `medium`（需结合权限清单核验）。


## 第三层：程序来源、执行状态、冲突与时间规则

### R-PROC-01 程序来源与执行状态双字段

**规则描述**：每条废止/失效边必须携带两个**正交字段**，不得合并为单一字段。

| 字段 | 取值 | 说明 |
|---|---|---|
| `procedure_source` | `self_cleanup` / `record_review` / `fair_competition_review` / `judicial_review` | 启动废止的程序来源 |
| `execution_status` | `executed` / `proposed` / `unknown` | 废止决定是否已经作出并公布 |

备案审查中，“建议制定机关修改或者废止”与制定机关**实际完成废止并报告**是两个不同阶段：建议阶段（`proposed`）不产生终态效力，制定机关完成废止后（`executed`）方可参与终态计算（[9†L15-L20]）。此修正关闭 BUG-4。

**置信度基准**：`self_cleanup` + `executed` + 附件目录行结构完整 → `high`；`record_review` + `proposed` → `medium`，终态置 `repeal_proposed`；`record_review` + `executed` → `high`。


### R-CONF-01 冲突适用顺序（先交叉，后单一）

**规则描述**：对同一事项存在规定不一致时，**先执行交叉检测，再做单一情形检测**。上一版将交叉情形嵌入顺序链，导致“新的一般规定 vs 旧的特别规定”在到达裁决分支前已被“后法优于前法”吞掉。此修正关闭 BUG-1。

**Step 1 交叉检测（优先执行）** ：

若 `(A 为新的一般规定 ∧ B 为旧的特别规定)` 或 `(A 为旧的一般规定 ∧ B 为新的特别规定)`，输出 `ARBITRATION_REQUIRED`，**终止冲突判定，不进入 Step 2**。裁决主体按《立法法》第八十五条、第八十六条确定：法律之间由全国人大常委会裁决；行政法规之间由国务院裁决；同一机关制定的规章/规范性文件由制定机关裁决；地方性法规与部门规章之间由国务院提出意见。

**Step 2 单一情形**：

- 2a 层级不同 → `upper_law_priority`；
- 2b 同一机关 ∧ 生效日不同 → `new_law_candidate`；
- 2c 同一机关 ∧ 覆盖范围不同 → `special_law_candidate`。

**Step 3**：无法归类 → `conflict_unresolved`，进入人工复核。

`ARBITRATION_REQUIRED` 和 `conflict_unresolved` **均不进入废止状态计算**。


### R-CONF-02 变通规定抑制

**规则描述**：自治条例、单行条例、经济特区法规依法可对上位法作变通规定并在本区域内优先适用。对这类文件，不得仅因“与上位法文字不一致”输出冲突；先检查变通立法身份，属于则 `conflict_suppressed = true`。


### R-TIME-01 不溯及既往约束

**规则描述**：《立法法》确立法律、行政法规、地方性法规、自治条例和单行条例、规章**不溯及既往**，例外是“为了更好地保护公民、法人和其他组织的权利和利益而作的特别规定”。废止决定通常只向将来发生效力；备案审查中制定机关自行修改或废止的，纠正方式为制定机关自身的立法行为，基于法不溯及既往原则，一般不产生溯及力问题。

**约束**：判定“某行为发生时文件是否有效”时，以 `behavior_date` 为锚点，不得用 `interval.end` 否定其之前的全部行为。`retroactive_effect = false`（默认）；仅在废止决定明示溯及时置 `true`。


### R-TIME-02 有利溯及标记

**规则描述**：触发条件为：新规定在处罚幅度/许可条件上对相对人更为有利 **且** 文本或立法说明含“从旧兼从轻/有利于当事人”意图。命中则标记 `favorable_retroactivity_candidate`；未同时满足两个条件的不产出该标记。此标记不改变文件层面的效力状态。


## 第四层：边消解、质检兜底与终态合成

### R-PRI-01 同目标多边消解（恢复并前置）

**规则描述**：同一 `(source_doc, target_doc)` 对上出现多条废止/失效边时，按以下优先级合并：

```
附件目录行（结构完整） > 明示废止句式 > 默示废止候选
```

高优先级理由写入 `reason_codes`，低优先级写入 `alt_reasons[]`；合并为一条边，`edge_status` 取高优先级结果。此规则恢复上一版被遗漏的消解逻辑，关闭 BUG-9。


### R-QC-01 存疑兜底

**规则描述**：若 `validity_interval.start` 或 `validity_interval.end` 无法确定，且无权威效力状态源可查，`doc_status = unknown_pending_review`，**不得默认置为“现行有效”**。`ARBITRATION_REQUIRED`、`conflict_unresolved`、`invalid_candidate`、`candidate_repeal`、`unresolved_reference`、`BASIS_MODIFIED_PARTIAL` **均不进入**“已废止/已失效”的自动终态。


### R-QC-02 抽检与回退

**规则描述**：对 `extraction_method = suffix_or_docnum` 或 `extraction_method = ner` 或 `confidence ∈ {medium, low}` 的边，按不低于 5% 比例抽检；抽检准确率低于 95% 时，该规则或模型版本的输出整体回退至 `candidate_only` 模式，只生成候选、不参与状态计算，直至修复。每条规则附带最小回归用例集，规则变更时强制回跑。


### R-QC-03 终态合成（含中间态）

**规则描述**：仅以下信号可参与自动终态合成，且必须满足相应准入条件。

| `doc_status` | 准入信号与条件 |
|---|---|
| `repealed` | `REPEAL_*` ∧ `confidence ∈ {high, medium}` ∧ `execution_status = executed` ∧ 经 R-PRI-01 消解且未被 R-REP-05 抵消 |
| `invalid` | `INVALID_PERIOD`（R-REP-06 届满且无延续记录）∧ 或 `INVALID_OBJECT`/`INVALID_METHOD`/`INVALID_TASK` 经 R-REP-09 外部事实核验升级至 `high` ∧ 或 `INVALID_BASIS_GONE`（依据状态可查且明确） |
| `retained` | R-REP-05 命中（`edge_status = retained_override`），且无更高优先级废止信号 |
| `repeal_proposed` | `procedure_source = record_review` ∧ `execution_status = proposed`；保留建议来源与依据原文，**不并入 unknown_pending_review**，以保留信息 |
| `unknown_pending_review` | 其他所有情形（含低置信度、候选、仲裁待决、部分依据变更、未匹配引用） |

`repeal_proposed` 是本版新增的中间态，用于区分“已有废止建议但制定机关尚未执行”与“完全未知”，避免信息丢失。此修正关闭 BUG-15。


## 规则执行顺序

```
1. 公文结构解析 → 条款、版记成文日、附件表标题+表头
2. 依据抽取 R-DEP-01~09 → depends_on 边（含 pending_match）
3. 候选边匹配回填 R-DEP-07 → 升级为可推理边 或 unresolved_reference
4. 依据状态查询 R-REP-04 → INVALID_BASIS_GONE / BASIS_MODIFIED_PARTIAL
5. 废止/失效信号抽取 R-REP-01 / R-REP-02（表标题定大类）
   → R-REP-03（大类内子类映射）→ R-REP-10（超越权限）
6. 外部事实核验 R-REP-09 → invalid_candidate 升级或保持
7. 程序来源与执行状态赋值 R-PROC-01（双字段）
8. 边消解 R-PRI-01 → 合并同目标多边
9. 保留抵消 R-REP-05 → 仅改 edge_status
10. 有效期届满 R-REP-06（外部延续记录查询）
11. 公平竞争审查例外 R-REP-08
12. 冲突检测 R-CONF-01（先交叉后单一）/ R-CONF-02
13. 时间约束 R-TIME-01 / R-TIME-02
14. 质检 R-QC-01 / R-QC-02
15. 终态合成 R-QC-03（含 repeal_proposed 中间态）
```


## 关键字段语义（防止跨规则误用）

| 字段 | 所在层级 | 允许值 / 说明 |
|---|---|---|
| `edge_status` | 边级 | `active` / `superseded` / `retained_override` / `candidate` |
| `doc_status` | 文档级 | `repealed` / `invalid` / `retained` / `repeal_proposed` / `unknown_pending_review` |
| `procedure_source` | 边级 | 程序来源，与执行状态正交 |
| `execution_status` | 边级 | `executed` / `proposed` / `unknown` |
| `edge_major_class` | 边级（附件行） | `REPEAL` / `INVALID`，由 R-REP-02 表标题确定 |
| `reason_codes` | 边级 | 子类代码列表；`alt_reasons` 保留低优先级理由 |
| `target_end_date` | 边级 | 被废止/失效文件的终止日期，**不得与 `effective_date` 混用** |


## 与上一版相比的缺陷关闭对照

| 原缺陷 | 修正规则 | 修正方式 |
|---|---|---|
| BUG-1 冲突顺序吞掉裁决情形 | R-CONF-01 | 交叉检测前置，Step 1 命中即终止，不再进入单一情形链 |
| BUG-2 有效期“无延期条款”恒真 | R-REP-06 | 以外部延续记录替代原文本特征 |
| BUG-3 `INVALID_BASIS_GONE` 重复且矛盾 | R-REP-03 / R-REP-04 | 从关键词映射表删除，仅由图谱推理产出；增加部分变更分支 |
| BUG-4 程序来源与执行状态混淆 | R-PROC-01 | 拆为 `procedure_source` 与 `execution_status` 双字段 |
| BUG-5 外部事实确认在规则链中断裂 | R-REP-09 | 新增外部核验规则，文本命中仅生成候选，升级后才参与终态 |
| BUG-6 附件表废止/失效大类丢失 | R-REP-02 | 表标题优先定大类，理由列名辅助，子类在已定大类内映射 |
| BUG-7 日期语义不明 + 名词化误报 | R-REP-01 | 统一为 `target_end_date`；排除“废止后/废止前/废止程序” |
| BUG-8 边状态与文档状态混用 | R-REP-05 / R-QC-03 | 边级 `edge_status` 与文档级 `doc_status` 分离 |
| BUG-9 同目标多边无消解 | R-PRI-01 | 恢复优先级消解，附件目录 > 明示废止 > 默示废止 |
| BUG-10 候选边与依据灭失推理断裂 | R-DEP-07 | 增加匹配回填与升级机制，升级后参与 R-REP-04 |
| BUG-11 按引导词强行区分依据类型 | R-DEP-01 | 改为以“是否含制定本×”判定 |
| BUG-12 回落扫描污染 `application_basis` | R-DEP-02 | 回落仅针对 `legislative_basis` |
| BUG-13 有利溯及无触发条件 | R-TIME-02 | 补充双条件触发 |
| BUG-14 保留抵消作用域不清 | R-REP-05 | 限定为同一 `target_doc` |
| BUG-15 建议废止信息丢失 | R-QC-03 | 新增 `repeal_proposed` 中间态 |
| BUG-16 简称/指代未覆盖 | R-DEP-09 | 恢复 NER 补充抽取与匹配确认机制 |


## 配置示例（节选）

```yaml
- rule_id: R-REP-02
  name: 附件表废止/失效大类判定
  scope: appendix_table
  major_class_resolution:
    - source: table_title
      pattern: "废止"
      major: REPEAL
    - source: table_title
      pattern: "失效"
      major: INVALID
    - source: column_header
      pattern: "废止理由"
      major: REPEAL
    - source: column_header
      pattern: "失效理由"
      major: INVALID
  sample:
    input_table:
      title: "省人民政府决定废止的行政规范性文件目录"
      headers: ["序号", "文件名称", "发文字号"]
    expect: {edge_major_class: REPEAL}

- rule_id: R-CONF-01
  name: 冲突适用顺序
  scope: cross_document
  step1_cross_check:
    condition: "(A=新一般 ∧ B=旧特别) ∨ (A=旧一般 ∧ B=新特别)"
    output: ARBITRATION_REQUIRED
    terminal: true
  step2_single:
    - hierarchy_diff: upper_law_priority
    - same_agency ∧ effective_date_diff: new_law_candidate
    - same_agency ∧ coverage_diff: special_law_candidate
  sample:
    input: {A: "新的一般规定", B: "旧的特别规定"}
    expect: {conflict_type: ARBITRATION_REQUIRED, participates_in_status: false}
```

这套规则全文的核心设计原则可以概括为：**法定情形以清理办法的废止/失效双清单为骨架，附件表标题决定大类而非理由关键词反推，程序来源与执行状态正交编码，冲突判定先交叉后单一，时间锚点以行为发生时而非清理结论倒推，任何单一信号不单独产出终态**。所有规则变更应附带最小回归用例，规则调整时强制回跑抽检（R-QC-02）。
