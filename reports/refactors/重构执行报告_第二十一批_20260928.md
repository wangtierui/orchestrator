## 二、变更摘要

### ① 位置归因（N-109）：**零人工**收窄误定位上界

**方法**：窗口 = `text[max(0,pos-h) : pos+h]` → 窗口内"引用起点"下标 = `pos - max(0,pos-h)`。
对每一个由窗口命中的条号，判定其在窗口内的位置：

- 落在**引用起点之前** → 属**源侧前文**（"本办法第12条……依据《X》"中的 `第12条`）→ **误定位嫌疑**；
- 落在**引用起点之后** → 属**引用本身或紧随后文** → 合法。

**实测（当时产物 338 行）**：

| 归因 | 行数 | 占比 |
|---|---|---|
| **引用之前** | **125** | **85%** |
| 引用之后 | 22 | 15% |

> ⚠️ **这是对本 AI 上一批结论的反驳**：第二十批以"窗口↔跨度**冲突**"为唯一信号得出
> "窗口误定位**零证据**"。但**跨度无命中时根本无从冲突** → 该检验**不充分**。
> 位置归因才揭示真相：**N-98 最初担心的"前文污染"确实存在且量级可观（125 行 = 有目标键行的 7.2%）**。

### ② 决议：**前文剔除**（U2）

写入侧把目标侧定位的窗口输入**限制为引用之后的部分** `[pos, pos+h)`（保留跨度退路）。

**实测（决定性）**：

| 指标 | 基线（第十九批前） | 第二十批（并集） | **第二十一批（前文剔除）** |
|---|---|---|---|
| 目标侧定位 | 237（5.7%） | 338（8.1%） | **609（14.5%）** |
| 双侧 | 147 | 224 | **489** |
| 引用之前命中 | — | 125（未识别） | **0** ✓ |
| 冲突 | 0 | 0 | **0** |

**为何覆盖反而大增（+271）**：前文条号与目标条号**并存**时 → 候选 >1 → 按"唯一命中才填"**弃权**；
**剔除前文后只剩目标条号** → 变为**唯一** → 命中。即前文污染**同时**是"误定位源"与"**歧义源**"，
剔除它**两个问题一并解决**（精度 ↑、覆盖 ↑）。

### ③ 口径 SSOT 收敛（**消除重复派生**）

`_snippet` 的半宽原先在"写入侧"与"诊断侧"**各自** `snippet_window // 2` → 抽为
`relations.snippet_half_window()`，两处共用（避免口径漂移）。
同时把"抽号→查表"抽为公共原语 `clause_locator.dst_article_candidates()`
（须**位置**信息的诊断消费方与 `locate_dst_article` **同源**，逻辑只有一份）。

### ④ 标签与口径**即时更正**（防文档-实现脱节）

1. 跨度标签：`"纯披露，不参与定位"` → `"窗口未唯一命中时的退路"`（N-106 起已参与）；
2. 上界口径：前文剔除后归因显示"引用之前 = 0"→ "仅窗口"全部落在**合法位**，
   故上界**不宜再读作"可能的错"**，改为"**未经跨度互证的量**"（口径随事实调整）。

### ⑤ 途中即时发现并修复

1. 审计侧初版仍用**整窗**判定候选位置 → 会把"永不可能成为 dst_article 的前文条号"计入归因
   （归因失真）→ 改为**与写入侧同口径**（只看引用之后切片）✓
2. f-string 内嵌双引号致 `SyntaxError`（两轮各一次）→ 统一改用「」✓
