# 阶段一：项目现状阐述（事实层，不做评判）

## 1.1 项目定位与目标

**定位**（README.md:5-7）：源码树编排工程（Single-Repo Orchestrator）——以统一入口把「采集 → 清洗 → 时效核验 → 条文 → 归属/主题 → 关系 → 内部制度 → 发布 → 分析交付 → 门禁」串成一条可复跑、可审计、可断点续跑的生产链路。

**核心目标**（README.md:18-20）：以**唯一入口 + 唯一事实源 + 可观测降级 + 机器化门禁**四条纪律，构建端到端高可用、无阻断、可审计的监管合规治理链路；任何增强能力可缺失（零硬依赖）但不可静默，任何失败可恢复但不可隐藏。

**技术栈**（README.md:21-28 + pyproject.toml:12）：
- Python **>= 3.13**（`requires-python`，P0 骨架起即如此，见 §2.F）
- 文件产物（JSONL/CSV）+ SQLite FTS5 + PostgreSQL/pgvector（可选）+ `data/governance.db`（SQLite 治理库）
- ruff / mypy / pytest / 24 道自研门禁；extras：`[dev]` `[ocr]` `[semantic]`
- 模型权重随仓外置于 `external/models/`（git 忽略）

**版本事实**：pyproject `version = "0.1.0"`（pyproject.toml:9）；README 自称 `v3.0.0`（2026-09-30 覆盖式重写）；CHANGELOG 最新条目为「第五十六~六十五批」（2026-10-08~10-12）。

## 2.A 数据格式选型

### A1. raw 文件格式（**最高优先级回溯点**）

- 【选型点】raw 主库存储格式：单文件 JSON 数组 → **JSONL**（首行 `_meta` 信封 + 一行一记录）
- 【当前实现】`modules/regulatory_scrapers/data/raw/{gov_laws,mof_laws,nfra_regulations,pbc_laws,supplementary_regulations}.jsonl`（run_production_refresh.py:134-143 `RAW_JSON`）；写入流式（gov_parse.write_outputs，.tmp + os.replace 原子）；读取双格式兼容（pipeline.load_raw_records）
- 【选型时间】**2026-10-09（批 47，commit a02be4d）**完成 JSONL 化；批 49（05a9c52）四源统一。此前（P0~批 46）为单文件 JSON 数组
- 【当时理由】（git show a02be4d 提交信息原文）「`.json` 单数组解析 1GB 主库实测峰值 **5.24~6.13GB**（≈6× 体积）；JSONL 读写均可**流式** ⇒ 峰值与语料体积解耦」；迁移有等价性证明（13178 条、滚动 sha f784c6e89ed8b9ba 一致才删旧文件）
- 【当时约束】gov 主库 943.6MB、13178 条；clean 阶段全量载入
- 【当前约束】实测 gov 458.6MB（批 47 后体积缩小）；mof/nfra/pbc/supp 均 <100MB
- 【约束是否变化】是（格式已完成迁移，问题已解决）
- 【当前替代方案】① Parquet（列式+压缩，需 pyarrow，本环境网络策略不可达）；② 分片 JSONL；③ 保持 JSONL
- 【替代方案评估】Parquet 对单机文本语料收益有限且引入重依赖；分片对 <500MB 主库无必要；**JSONL 已是当前约束下的最优解**
- 【是否应改变】**否**（已改变且成立）
- 【优先级】—

## 5.2 总体评估

**项目健康度：良好偏上（生产链路真实可跑、纪律面密集，但「声明面与执行面的一致性」存在系统性薄弱环节）。**

- **强项**（有实证）：① 调度事实源与实装完全一致（7/7）；② 数据校验/隔离/失败传播链完整（uncertain 兜底纪律、隔离件、时间窗判定）；③ 水位/血缘机制覆盖链内全部自产自销产物；④ 增强层零硬依赖 + 降级可观测的纪律执行彻底；⑤ 桌面干扰治理（四重机制）是罕见的深度运维实践；⑥ git 历史即变更日志（280 提交全部带动因）。
- **最紧迫的 3 项改进**：
  1. **R-1（P0）**：wiki 同步链路因一条硬编码错路径静默失效 13 天——「全绿仍失实」的活案例，且同构风险（条件观察路径、动态步骤展开值）无任何门禁覆盖；
  2. **R-2（高）**：relevance 步骤只跑一个源（循环残留变量），五源中四源的 BOUNDARY 产生面缺失——批 63「接线」动作本身不完整；
  3. **R-4（高）**：README/BENCHMARK/_manifest 三处文档漂移 + 守卫（audit_health）未入 CI——文档可信度是本院纪律的基石，当前有裂缝。
- **主要风险**：① 「门禁只校验声明面、不校验执行面语义」的模式性风险（D-1/D-3 两个 P0/高缺陷均由此逃逸）——建议把 R-1 的 T4 判据与 R-2 的 R3 判据作为该模式的通用补丁；② 生成物（BENCHMARK/手册）新鲜度无机器守护；③ modules 侧 21 个无登记脚本的「暗物质」面积。
