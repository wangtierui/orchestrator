# 审查方法（工具与脚本）

## A. 静态分析
- `ruff check .`
- `mypy .`
- `vulture --min-confidence 80`
- `pylint` / `flake8`

## B. 接线检测
1. 读取 `STEP_ORDER`、`COMMANDS`、`schedule.yaml`、`triggers.yaml`。
2. 遍历 `tools/`、`modules/`、`std_lib/` 下所有 `*.py`。
3. 未被覆盖的 → 标记「未接线候选」。

## C. 事实源检测
1. 读取 `contract_manifest.json`。
2. 对每个数据域，检查多写入者、多处定义、硬编码不一致。

## D. 共享库使用检测
1. 枚举 `std_lib/` 公共能力。
2. 检查全仓重复实现。
3. 检测自研与成熟库重叠。

## E. 调度一致性检测
1. 确认 `schedule.yaml` 是否为唯一事实源。
2. 检查 `cli.py schedule` 覆盖度。
3. 检查其他定时入口。
4. 检查 README §5.2 漂移。

## F. 全流程链路覆盖检测
1. 对照 `STEP_ORDER`，检查数据处理节点覆盖度。
2. 输出「应归入链路但未归入」清单。

## G. 元数据与校验专项
1. 检查元数据集中性与唯一性。
2. 检查校验逻辑覆盖度。
3. 检查空值/隔离/失败传播一致性。

## H. 选型回溯专项
1. 用 `git log` 追溯关键选型的提交时间。
2. 读取提交信息、CHANGELOG、ADR，提取当时理由。
3. 对照当前约束，评估是否应改变。
