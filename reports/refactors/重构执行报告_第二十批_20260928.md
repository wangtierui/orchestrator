## 二、变更摘要

### ① 度量：定位**正确性边界**（N-106，纯只读）

**为什么需要**：N-95/N-98 只测得**覆盖率**（窗口定位 5.7%），但"命中的**对不对**"无从判断
（缺金标）。`source_span`（引用自身文本）为此提供**低成本锚点**：同行同函数、仅换输入，
**冲突即证明至少一方错**。

**实测（1733 个有目标键的行）**：

| 分类 | 行数 | 含义 |
|---|---|---|
| 一致 | **90** | 窗口与跨度给出**同一**条号 → 互相印证 |
| **冲突** | **0** | 给出**不同**条号 → 必有一错（= **误定位下界 0.0%**） |
| 仅窗口 | 147 | 窗口抽到、跨度没有（条号在引用**邻域**，无法证伪 → 误定位**上界** 8.5%） |
| **仅跨度** | **101** | **窗口弃权、跨度可定位** → 窗口的**真短板是「漏」而非「错」** |
| 皆无 | 1395 | 两侧皆无法唯一命中（多为依据类无条号的合法情形） |

> **结论**：N-98 原假设（"窗口含源侧条号致**误定位**"）**零实测证据**（冲突 0）；
> 真正可改进的是**漏定位 ≥101 行**。这条结论**无法靠推理得到**，只能靠度量。

### ② 决议：**并集定位**（窗口优先 → 跨度退路）

依据度量结论，最优解**不是二选一**而是**取并集**：

```
目标侧条号 = locate_dst_article(窗口)  · 若唯一命中则用之（覆盖更广）
           ? 否则 locate_dst_article(引用跨度) · 若唯一命中则用之（补 101 行漏定位）
```

**为何安全**：① 两侧**各自坚持"唯一命中才填"** → 质量闸门不放松；
② 度量已证**零冲突** → 退路**不会引入与窗口矛盾的取值**；
③ `dst_article` 是 **N-49 增强轨字段**（**不进 `relation_id`**，第十九批已核）→ **id 稳定、零迁移**。

**实测**：

| 指标 | 变更前 | 变更后 | 变化 |
|---|---|---|---|
| 目标侧定位 | 237（5.7%） | **338（8.1%）** | **+101**（与度量预测**精确一致**） |
| 双侧 | 147 | **224** | +77 |
| 冲突 | 0 | **0** | 不变（零矛盾） |
| 一致 | 90 | 191 | +101（两侧互证增加） |

定位来源分布 → `{'': 1775, 'snippet': 90, 'span': 24, 'src_offset': 2079, 'src_offset+snippet': 147, 'src_offset+span': 77}`
（`span` 合计 24+77 = **101** ✓ 与预测吻合）

### ③ 受控域随之扩展（**双向**同步）

本轮因**实测证据**重新纳入）。受控值注记与闭包断言同步。
