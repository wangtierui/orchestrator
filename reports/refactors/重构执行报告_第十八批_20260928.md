## 二、变更摘要

### R1/R2 · P1 语义增强**接线层**（本轮核心）

**为什么不直接 `pip install` 那 10 个工具**：v2 已判定 P1 的前置是"**先铸尺**"，且本仓有
"**零硬依赖 / 克隆可移植性**"（CP-A01）纪律。直接装依赖只会得到两种坏形态：
① 未安装的克隆**导入即崩**；② `try/except: pass` 吞掉一切 → 增强能力**静默失效**。
故本轮交付的是**接线与治理**，使"启用增强"成为**一次显式的、可观测的、可校验的**动作：

| 组件 | 作用 |
|---|---|
| `config/schema/semantic_tools.json` | **工具清单唯一事实源**：10 条，各含 `repo`（用户提供的仓库地址）/ `purpose` / `pypi` / `probe` / **`pipeline_ref`（对应 v2 方案项）** / 体积 / 离线性 / 许可待核 |
| `std_lib/common_lib/semantic_tools.py` | 探测（`module`/`service`/`manual` 三类）、批量探测、**指纹**、**可观测回退说明**、CLI（`--probe` / `--fingerprint`） |
| `pyproject [semantic]` | 可安装 extra（`hanlp` / `text2vec` / `bertopic` / `umap-learn`；版本为**保守下界**并注明"上界待实测锁定"） |
| `gate_config_integrity` **判据 U** | 清单自洽（必备字段 / repo 为 http / probe 名 / 探测不抛异常）+ **`policy` 三纪律不得被静默放宽** + **extra 交叉核对**（清单说有 extra 则 pyproject 必须真有） |
| `gen_benchmark` **§6.6** | 每轮全链刷新"当前环境具备哪些增强能力"→ 回答"这一轮跑的是增强路径还是正则回退" |

**实测**：`语义增强能力：0/10 可用（全部未安装 → 全链走既有正则路径）`；判据 U 通过
（`{tools:10, extras:["semantic"], policy:{hard_dependency:false, degradation:required, fingerprint:required}}`）。

**清单对 10 个工具的落点登记**（防止"先把依赖装上再说"）：
`hanlp`/`ltp`→P1-3（分句结构）｜`text2vec`→P1-1/P1-2（主题辅助裁定·关联语义档）｜
`bertopic`/`umap`/`hdbscan`→P1-5（主题内子簇）｜`aprcoie`→P3-1｜`signalgraph`→P3-2｜
`weknora_docreader`→P2-1（**只补版面**，OCR 通路已存在）｜`paradedb`→P2-2（须先做零服务替代评估）。

### R3 · N-100 隔离件轮转（分组保留）

`_plan_dir` 原只有**全局** `keep` → 用于隔离件会**误归档其他源的当前隔离件**（把在用数据移走）。
新增 `group_by_regex`（捕获组为分组键，组内各保留 `keep` 个）+ POLICY 类目
`clean_quarantine_stale`（`keep=1`，只移动不删除，`--apply` 仍为人工闸门）。

**实测**：`clean_quarantine_stale {'exists': True, 'total': 4, 'kept': 2}` —— 4 份隔离件、每源留最新 1 份 ✓
（nfra 09-26/09-27/09-28 三份 → 留 09-28；supp 09-26 一份而 cleaned 已 09-28 → 该源仅此一份，保留）

### R4 · N-101 `degraded` 口径**定案**（键名误导）

**根因**（`clause_index/__init__.py:419-422`）：
```python
elif mode == "law":  stat["law"] += 1
else:                stat["degraded"] += 1     # ← 实为"非 law 体裁计数"
```
`CLAUSE_PARSE_MODES` = `bulletin / empty / law / notice / plain / plan` 是**体裁**而非质量等级。
**实测分布（16611 文件）**：`notice 9140 (55.0%)` / `plain 4843 (29.2%)` / `law 2599 (15.6%)` / `empty 29`。
→ 我第十七批报的"degraded 84.35%"**看着像告警，实为正常**（多数监管文件本就是通知/公告）。

**处置**：① 就地纠正语义注记（键名保留仅为兼容）；② 基线改为报**体裁分布** + 三项**真信号**
（`empty 0.17%` / `fallback 29.33%` / `invalid 94`），不再换算成误导性的"降级比例"。

### R5 · N-94 但书**度量先行**（零行为变更）

在 `structure_semantics` 增两档但书计数（**只计数，不参与任何切分/校验判定**）：
宽档 `proviso`＝条 body 含 `但`；严档 `proviso_strict`＝同句内 `但` 与法定例外用语（除外/不适用/另有规定）同现。

**实测**：`proviso=4540` 条 / **`proviso_strict=925` 条**（占 108409 条的 4.2% / **0.85%**）。

> **这正是"度量先行"的价值**：严档仅 **0.85%** → 为 925 条改动 **1542 行**解析器的切分逻辑，
> **性价比不成立**。N-94 据此**结案为"不值得整体改造"**，建议仅在出现具体误切案例时**定点修**。

### R6 · N-98 影响面评估（**定案：可行且低风险**）

| 问题 | 实测结论 |
|---|---|
| `source_snippet` 怎么来的？ | `RelationPipeline._snippet(text, pos)`（`relations.py:907`），**±100 字符窗口**（`snippet_window=200`）——即"正文窗口" |
| 改成"引用跨度"会动 `relation_id` 吗？ | **不会**：`_relation_id` 判别字段为 `src_kind/src_ref/relation/dst_ref/normalized_name` + `src_key/dst_kind/dst_docno/article/action/scope/reason`，**不含 snippet/offset** |
| 会破坏门禁吗？ | 不会：`gate_relations._NON_EMPTY` 要求 `source_snippet` 非空，而引用跨度本身即命中文本 → 仍非空 |
| 对定位率的影响 | **正向**：窗口收窄后"源侧自身条号"造成的多义消失 → R5 类（738 条，第十七批已定案为正确弃权）将可**正确命中** |

→ **建议下批实施**：`source_snippet` → 引用跨度，**另保留窗口为新字段 `source_context`**
（审计上下文不丢失；契约允许加字段）。须做新旧对照抽样后再切换。
