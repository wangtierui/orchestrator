## 二、生产全链遗留风险处置（8 项）

### ① `clean:gov` 超时 → **根因查明并修复（N-182）**

**现象**：`clean:gov` rc=-1（TIMEOUT），耗时 **15526.3s**，恰擦 N-150 预算 15510s（raw 1034MB × 15）。

**根因（三层证据链）**：

| 证据 | 内容 |
|---|---|
| **归一化耗时突变** | `s/MB`：09-28~09-29 01:58 为 **0.14~0.19**（正常）；**09-29 13:05 起 1.74**；09-30 达 **15.00** —— **raw 体量完全未变（1035MB）** ⇒ 非体量增长 |
| **profiler 定位** | 切片跑 `run_pipeline` 51.75s 中 **48.5s（94%）** 在一个只被调用 11 次的函数内，触发 **254 万次 `difflib.SequenceMatcher`** |
| **代码定位** | `std_lib/scraper_std/ocr_correction.py:JiebaDict.check_and_fix`：`for tok in tokens: for w in vocab: SequenceMatcher(tok, w)` ⇒ **O(tokens × vocab)**（vocab 上限 2000） |
| **为何"现在才发作"** | `build_high_freq_dict` 在 `import jieba` **失败时返回 `{}`** → `checker=None` → 该循环**根本不执行**（历史 clean 因此快）。**jieba 安装于 2026-09-29 11:36**（site-packages mtime），紧邻首次劣化（13:05）⇒ **休眠的二次复杂度被新依赖激活** |

**修复（结果逐字节等价）**：候选剪枝用**数学必要条件**（`ratio = 2M/(la+lb) ≥ 0.85` ⟺ `M ≥ ceil(17(la+lb)/40)`，整数运算）+
**稀有字倒排索引**（短词必含全部字符 ⇒ 缺任一即不可能达标）+ **逐调用缓存** + **词表序确定化**（原为 `set` 哈希序 ⇒ **跨进程不可复现**，属事实源可复现性缺陷）。

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 120 条真实 gov 正文总耗时 | **653.30s** | **5.34s**（**122.3×**；结果逐字节一致） |
| 外推 gov 全量（13178 条） | ≈ 20h | ≈ **586s** |
| **真机（调度链实测）** | **TIMEOUT:15526s**（09-30） | **246s / 259s / 290s**（10-05/06/07） |

**测试固化**：`tests/test_ocr_correction_equiv.py`（14 项：等价性/复杂度守卫/可复现性/缓存）。

### ② 同函数的**死逻辑**（`best_d` 初值 99）→ 固化"**不得启用**"

`best_d = 99` 与判据 `d > best_d`（ratio ≤ 1）构成**永假比较** ⇒ 该功能**从未生效**（恒不替换）。
**若"顺手修好"（初值改 0）会造成事实源灾难**（实测真实 gov 语料）：

| 样例替换 | ratio | 性质 |
|---|---|---|
| **`第十八条` → `第八条`** | **6/7 = 0.857** | **法规条文编号被篡改** |
| `第二十条` → `第二条` | 0.857 | 同上 |
| `第十一条` → `第一条` | 0.857 | 同上 |

- 200 条中 **198 条被改（99%）**、**2559 次**替换；外推全量 **13046/13178 条**、**~69 万字符**；
- 编号词之间存在 **222 组** ≥0.85 的"危险对"（如 `第二条第十款 → 第二条第十八款`，0.923）。

⇒ `ratio ≥ 0.85` 对中文法规文本**不安全**。已用**可证伪测试**固化决策
（`test_dead_logic_is_actually_a_safety_guard_do_not_enable`、`test_repaired_logic_would_corrupt_article_numbers`），
并登记待办 `WL-20261008100903807-6108-df404e`（删除该功能 / 换语域安全判据）。

### ③ 「上游失败下游仍消费」→ 机制**已存在**，补**回归测试**（原零覆盖）

- 机制：`_run()` 记录每步 `started_at/ended_at` **时间窗**；`gates/gate_run_steps.py` **危险组合**判据 =
  "失败步骤 + 其产物 mtime **落在该步时间窗内**" → **FAIL**（可经 `data/run_state/acknowledged.json` 留痕降为 WARN）。
- 本次实跑：`clean:gov` 窗 19:19–23:38，而 gov cleaned **mtime = 17:00（窗外）** ⇒ `dangerous=[]`
  ⇒ **门禁 rc=0 是正确的**（未发生"失败产物被下游消费"）。
- **缺口**：该门禁此前**无任何测试**（`tests/` 零引用）。已补 `tests/test_gate_run_steps.py`（**7 项**，临时目录 + monkeypatch 隔离）：
  无台账→跳过披露 / 危险组合→FAIL / 人工确认→WARN / 历史产物→不误报 / 产物映射三类。
- 另：`_run_chain` 的失败传播为 **`if args.stop_on_error and rc: break`** ⇒ **默认继续下游**（设计如此，与 N-152 判据配套）。

### ④ N-150 系数**来源被污染** → 登记重标定

N-150 的 `15 s/MB` 系由**被缺陷污染**的数据标定（当日 nfra 13.4 s/MB 是 jieba 激活后的异常值；同数据激活前仅 0.14~0.19 s/MB）。
修复后实测 **0.24~0.28 s/MB**（clean:gov 246~290s / 1035MB）⇒ 现系数约为实测的 **60×**，作为上限无害但**掩盖真实余量**。
已登记 `WL-20261008100903947-6108-096444`（建议改为 ~2 s/MB 并同步注释与 README §8）。

### ⑤ 模型加载**无进程级缓存**（N-183）→ 修复 + 测试

`semantic_enhance.split_sentences` / `embed_documents` **每次调用**都 `load_segmenter/load_embedder`，
而两函数**无缓存** ⇒ **逐文档重复加载模型**。实测后果：
① 200 条正文的 A/B 因逐条重载**卡住 20 分钟无输出**；② 若启用 ML 分句，gov 13178 条 ≈ **4.6 天**（13178 × ~30s）⇒ **该路径实际不可用**。
修复：`load_segmenter` / `load_embedder` 加**进程级缓存**（`_resolve()` 仍每次执行 ⇒ 就绪度判据不降级；权重缺失照旧 fail-closed）。
测试：`tests/test_semantic_model_cache.py`（3 项：同键复用 / 不同名不串扰 / resolve 失败不命中缓存）。

### ⑥ `agreement` 基线**结构性缺失**（N-184）→ 修复，指标首次可算

`semantic_assist` 用 `cleaned.theme_name` 作"确定性基线"，而该字段在**五源 cleaned 中 100% 存在却 100% 为空**
（`unified_schema` 默认值，链上无回填）⇒ **`agreement` 恒为 `None`** ⇒
"ML 建议 vs 确定性归属"的差异**在生产中不可测**（恰是本仓"启用增强层前须先量 P/R"所依赖的指标）。

修复：① 基线改从**真实归属源** `modules/regulatory_classifier/data/_t{N}_final.json` 读取（2138 条目，标题用
`norm_title_strict` 精确匹配）；② 抽样**优先取有基线的记录**；③ 如实披露 `baseline_coverage` / `baseline_source_counts` / `sample_policy`。

| 指标 | 修复前（09-30） | 修复后（10-08） |
|---|---|---|
| `agreement` | **None** | **0.5455** |
| `agreement_n`（可比条数） | 0 | **330**（覆盖 **38.46%**） |

### 3.2 逐节点差异（**均为实测**，只写分析视图）

| 节点 | 启用前 | 启用后 | 差异结论 |
|---|---|---|---|

## 五、遗留风险

| 编号 | 事项 | 建议 |
|---|---|---|
| **R-1** | **ML 分句两后端均不可用于长文本**：LTP **静默截断**（>~550 字尾段合并）、HanLP **不截断**（长文本推理爆炸） | ① 若要用 ML 分句：**先按 ≤500 字分块**（并在拼接处处理句边界），或换支持长文本/分块的后端；② **当前"默认关闭"是正确且必要的**（待办见 §二②之外的登记） |
| **R-2** | OCR 词典校正的**功能决策**（删除 / 换语域安全判据） | 待办 `WL-20261008100903807-6108-df404e`；本域更该补的是 **`config/ocr_confusion.json` 形近字映射表（当前 0 条）** |
| **R-3** | N-150 系数待**重标定**（原系数源于被污染数据） | 待办 `WL-20261008100903947-6108-096444` |
| **R-4** | N-183 的进程级缓存使模型**常驻内存**（进程内） | 单进程批处理无碍；若需长时间驻留多模型，应加**显式释放**接口 |
| **R-5** | `agreement` 覆盖率仅 **38.46%**（受分类器覆盖度限制） | 若要全量度量，需扩展基线来源（归属表/分类器全量）或按"有基线记录"全量抽样 |
| **R-6** | 分类器产物 `_t{N}_final.json` 未声明为 `semantic_assist` 的水位上游 | 建议登记依赖边（否则分类器更新后 `agreement` 静默用旧基线） |
| **R-7** | 本批新增 3 个测试文件含**真实数据路径**依赖（`reports/_tmp/gov_slice.json` 等仅用于测量脚本，未入测试） | 测试均为合成/隔离数据 ✓；测量脚本在 `reports/_tmp/`（不入库） |
