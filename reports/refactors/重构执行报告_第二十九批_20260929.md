## 二、变更摘要

### ① 模型节点入图（Mermaid）

- **绑定事实源**：新增 `gen_flow_map.MODEL_BINDINGS`（模型 → 步骤 / 阶段 / 作用 / **降级措施**），
  与工具清单**双向校验**：清单中每条工具都必须有绑定，否则图中给出**「未绑定」告警**（不静默）。
- **图结构**：阶段主链（A→G）不变；每个模型以 `-.->|"<具体步骤>"|` 挂到**所属阶段节点**，
  节点标签形如 `hanlp 已接入·未启用` → **节点位置 = 阶段，边标签 = 精确步骤**。
- **同工具多用途**：以 `<tool>@<用途>` 区分（`youtu_embedding` 同时挂 `classify:all` 与 `relations:gen`）。
- **样式区分**：`classDef on`（绿实线）/ `classDef off`（灰虚线），并按状态自动分类。

**当前结果**：**14 个模型节点 = 已启用 4（`hdbscan`/`pgvector`/`sqlite_vec`/`umap`）
＋ 未启用 10**。未启用者**同样入图**并标注将来挂接位置。

### ② 模型 ↔ 链路节点定位表（§三）

每行含：**挂接链路节点** | 阶段 | 在该节点做什么 | **状态** | **未启用原因** | **降级措施**。
纪律：未启用者**必须**给出原因与降级（不得留空、不得写「无」）。

| 节点 | 挂接的模型 |
|---|---|
| `clauses`（阶段1） | `hanlp`、`ltp` |
| `clean`（阶段1） | `weknora_docreader` |
| `classify:all`（阶段2） | `youtu_embedding`、`text2vec`、`bertopic`、`umap`、`hdbscan` |
| `relations:gen`（阶段2） | `youtu_embedding@relations`、`aprcoie`、`signalgraph` |
| **按需节点**（阶段4） | `pgvector`、`sqlite_vec`、`paradedb` |

### ③ 途中即时发现并修复（3 处，均为**真实缺陷**）

| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| 1 | 阶段节点 ID 被写成 **「阶」** | 误用 `cfg["stage"][0]` 取中文首字 | 新增 `STAGE_NODE` 映射（阶段→`A`/`B`/…） |
| 2 | `paradedb` 被误判为**已启用** | 客户端库 `psycopg` 偶然可用 → 落"已启用"分支，**而其服务从未部署** | `_model_status` 增判：`kind=service` 且 `service_reachable is None` ⇒ **未启用（服务未部署/端点未配置）** —— 正是 N-113 三态要区分的事实 |
| 3 | `bertopic` 被误判为**已启用** | **清单缺 `offline_env`**（与 text2vec/youtu 不一致）→ 权重未取得却无信号 | 补 `offline_env: ["HF_HOME","TRANSFORMERS_OFFLINE"]`（**清单一致性修复**） |

> 第 2、3 条是**"状态判定把未启用说成已启用"**—— 若未发现，会让读者以为增强层已生效。
> 这类"**误报启用**"比"误报未启用"危险得多（后者只是保守）。

## 三、规范对齐

| 规范 | 落实 |
|---|---|
| 不重复造轮子 | 绑定/状态全部由**既有探测**（`probe_all`）与**清单**派生，不新增第二份事实源 |
| 唯一事实源 | 绑定唯一于 `MODEL_BINDINGS`；状态唯一于探测结果；链路唯一于 `STEP_ORDER` |
| 数据一致性 | 清单与绑定**双向校验**（未绑定即告警）；清单缺项（`bertopic` 的 `offline_env`）即时补 |
| 统一调度 | 总图仍由 `tools/gen_flow_map.py` 生成（**标注禁手改**）；本批不新增链步骤 |
| 可定位性 | **每个**接入模型都能在图中找到节点、在表中找到步骤与降级 |
