## 1. 专项①：四源是否均已实现正文及附件文档获取？

### 1.1 现状事实（实测结论表）

| 源 | 正文字段 | 正文可用性 | 附件文档下载 | 附件文本入库位置 | 缺口 |
|---|---|---|---|---|---|
| gov | `full_text` | ✅ xzfgk 详情 HTML 正常；flk（OBS 不可达）**已停抓清理** | `fetch_attachments_gov.py → data/docs/gov.../attachments/<清洗ID>/` | 拼 `attachment_text`（**非 cleaned 列**） | flk"正文文档版"从未抓到（已停）；附件文本未入 cleaned `attachment_content` |
| mof | `content_text` | ✅ 详情 `lcontent` HTML 正常（`--no-detail` 才跳过） | `/file/f/get` fileType 0(附件)/90(下载文字版) → `data/docs/mof.../attachments/<law_id>/` | 附件列表元数据（`att.text`） | 90"下载文字版"是否全文入库待统一 |
| nfra | `content` | ⚠️ 详情正文常为 `docClob` **序言非全文**；实质正文多挂 PDF 附件 | `fetch_attachments.py → cache/nfra/attachments/`，pypdf 抽文本，`--ocr` 才 OCR | 主 json `rec["attachments"]`（manifest+text） | 正文完整性依赖附件抓取成败 |
| pbc | `content` | ✅ 详情 HTML normal；规范性文件原仅存 PDF 名 | 主 scraper 多格式路由（LO 转 docx）+ `backfill_pdfs.py` 补 PDF→content；落 `data/docs/pbc.../attachments/` | 附件文本回填 `content/summary` | 附件文本经回填，缺少独立 attachment_content 列 |
| supp | `body_text` | ✅ webpage 全文或本地 PDF OCR | `scraper_std.attachments.download_and_extract` → BlobCache `cache/supp/attachments/` | ✅ 入 `attachment_content` | 唯一完整入库者 |

**统一结论**：
1. **四源+supp 均实现了"附件文档下载"与"文本层抽取"**（共享 `crawler_common.extract_document_text` 路由 pdf/docx/xlsx/ole2）；nfra/pbc 因正文本体挂附件**实际下载过 doc/pdf**。
2. **正文文档（doc/pdf 详情版）"从未抓到"的实为 gov(flk 已删) 与 supp(官网 HTML 为主)**；gov/mof 默认 `enable_ocr=False`（仅标 needs_ocr），nfra/pbc/supp 扫描件走 OCR 链。
3. **最大不一致点 = 附件文本未统一进 cleaned 的 `attachment_content` 列**：仅 supp 完整入库；gov 存 `attachment_text`（非 39 列之一）、nfra 存主 json attachments、pbc 回填 content。→ classifier scanner 的正文检索（body_text/attachment_content 字段并集）对 gov/mof/nfra/pbc **覆盖不均**。

### 1.2 方案
- 新仓 `collectors/*_collector.py` 统一语义：附件文本在清洗前归一为 39 列既有字段 `attachment_content`（不再各自命名）；清洗后 body_text 兜底拼接 `body_text + attachment_content` 的策略由 classifier scanner **显式声明**而非隐式字段猜测。
- nfra 正文完整性：collect 后置校验 `content 过短(序言) 且 attachments 未抓成功 → 标 needs_attachment_recovery`，进入 recovery 队列。
- gov flk：确认保持停抓（OBS 不可达属源限制），在 config/sources.yaml 声明 enabled=false + reason，避免后续误启。
- 补充"内部/外部共用正文文档下载入库统一流程"（见专项③ OCR 库，供 internal_policy_base 复用）。

## 2. 专项②：timeliness_review 变更后是否自动同步 clean/classifier？

### 2.1 现状事实（实测）
- `verification_state.py`：`is_fresh/mark_checked/changed_from_last/sync_to_classifier`——**sync_to_classifier 按文号→标题包含匹配**写归属表"时效状态"列（自动备份 .bak + 原子写）。
- `sync_three_modules.py`：三模块联动编排（① scrapers 回写 cleaned 三字段→clean_index 重建→门禁 ② classifier：sync_to_classifier→复制 mirror.json→`sync_all_layers.py --apply`→_propagate_final→base 重建 ③ drafter 引用门禁）——但**需人工触发**。
- `verify_source_pkulaw.py` / `verify_missing.py`：**只写 state + 台账，不自动同步**（注释声明"三库同步由编排层执行"）。
- `classifier_pkulaw_verify.py`：**自含闭环**（核验→同步归属表→回写五源）。
- `consolidate_timeliness.py`：基线台账重放 → "统一·全量"清单。
- classifier 侧 Gate2 读 `recall_audit/verification_state.mirror.json`（N-5 镜像，单向下发）。

**结论**：核验→同步**非全自动**：verify_missing/single 只写 state，中间必须人工跑 `consolidate + sync_three_modules`；`apply_timeliness_to_cleaned.py`（清洗重跑后补偿回写）也不在编排器内。

### 2.2 方案（全自动变更传播链，进入 orchestrator 统一阶段）
```
触发：orchestrator timeliness verify --source X 完成（或新 automation）
  → mark_checked 写 verification_state.json（唯一权威写位）
  → changed_from_last=True 的变更集进入变更队列（jsonl）
  → 自动依次执行（幂等 + 签名断点）：
     ① clean 回写：apply_timeliness_to_cleaned（jsonl+csv 双轨）+ clean_index 重建 + S-4/S-3 门禁
     ② classifier：sync_to_classifier(归属表时效列) → mirror.json 同步
                    → sync_all_layers.py --apply（rebuild_index/check_rfn_sync/diff_timeliness/eff_status 传播/base 重建）
     ③ drafter：verify_regulatory_citations 引用门禁（信息级）
  → 变更台账 + 执行报告落 reports/
```
- 固化入口：`orchestrator timeliness verify|sync|consolidate|report`，verify 后**自动**衔接 sync（无人工步），保留 `--dry-run/--no-propagate` 逃生口。
- 单一写位纪律：**verification_state.json 为唯一权威写位**；cleaned 时效列/归属表列/mirror/base eff_status/全量清单均为派生；禁止双路直写（现行 sync_to_classifier 与 diff_timeliness 双路写曾需 SSOT 校正，新仓只允许经 orchestrator 单路）。

**仍分散/不统一点**：

2. 各源自带 `safe_filename` 包装（3+ 副本）；

### 3.2 方案
- 共享库统一到 `std_lib/scraper_std`（新仓单副本），internal_policy_base 与五源**一律只 import 共享库**：
  - OCR：统一 `get_ocr()`（PaddleOCR→Tesseract 降级，PaddleOCR editable venv 指向工作区 `D:\WorkBuddy\PaddleOCR-3.7.0` 已在 venv 固化，随迁保留）；Tesseract 路径改 config 声明（`config/ocr.yaml`），消除硬编码；

- internal_policy_base `ocr/parser` 层 = 编排共享库能力的薄适配（不复制实现），`config/ocr.yaml` 统一引擎路径与参数；
- 门禁：`gate_no_duplicate_libs` 检测重名 `sniff_kind/safe_filename/extract_document_text` 再定义即 FAIL。

## 4. 专项④：clean/raw 的 CSV 行错位修复与 raw 是否需要 CSV

### 4.1 现状事实（实测）
- **raw 形态**：gov/mof/nfra/pbc = json + **csv 双出**；supp = **仅 json**。
- raw csv 生成：gov `scraper.write_outputs`（默认 quoting，**csv 不含 full_text/attachment_text**）；nfra 已对 summary/attachment_text replace `\n→空格`、content 不入 csv；mof `save_csv` QUOTE_ALL；**pbc `save_outputs` 的 content/summary 不做换行预处理，风险最高**。
- clean 层：`pipeline.write_cleaned` 用 `csv.DictWriter`（默认 quoting，含换行字段会被引号包裹——**语法合法**，但 LF 类读器会把引号内换行误判为记录结束/行错位）；**仅 supp** 在落盘后跑 `sanitize_newlines.py`（字段内 \r\n/\n→空格），gov/mof/nfra/pbc 的 run_clean_pipeline **均无 sanitize 调用** → 同类行错位风险存在（body_text/attachment_content/split_sentences/table_raw_text 等长字段）。
- **raw csv 消费**：未发现下游读取（仅 `_ops/full_refresh_4src.py` 作 artifacts 校验）；clean 管道只读 raw JSON。clean 双轨被消费：CSV 供 clean_index/timeliness/classifier scanner，JSONL 供 effort_precheck/classifier_pkulaw_verify/apply_timeliness_to_cleaned。

### 4.2 方案
1. **raw 层只保留 json**（统一 supp 现状）：raw csv 无下游消费、且多一份错位面，删除 raw csv 生成（写入方收敛 `save_json`；csv 不再输出）。
2. **clean 层错行修复统一化**：
   - `sanitize_newlines` 从 supp 独有提升为 `scraper_std.pipeline` **内置后处理步骤**（`write_cleaned` 落盘后对所有源执行字段内换行归一：CSV 字段内 `\r\n/\n→空格`，JSONL 保真原始串则无需替换——视契约定，建议 JSONL 保留 \n 语义、CSV 归一），即五源一致消除行错位；
   - 或更稳妥：clean CSV **始终走单行安全编码**（换行占位符统一），门禁 `check_pipeline_contract` 增加"行数 = 记录数"校验（现已有双轨记录数一致校验，补充行尾扫描）。
3. 结论（评估项）：**raw 无需 csv，仅 json 合理**；clean 的 csv/jsonl 双轨**保留**（各自有消费者），但必须统一 sanitize。

## 7. 专项⑦：各阶段输出数据结构冗余/缺失/类型统一

### 7.3 缺失（需补）
1. 归属表 8 列缺 **source_url / dedup_key**（无法溯源，专项二 Q1=A 已以独立桥表补）；

4. base 缺主题字段（主题在主题归属表）→ 维持拆分（已定 SSOT），但 base 记录增加 `theme` 只读视图引用。

### 7.4 类型统一（规范性）
1. `real_year`(int) vs `year_reported`(str) → 统一 str YYYY，或 int 并 schema 约束；
2. `publish_date/effective_date` ''空串 vs None vs 'N/A' → **契约统一：无值即 ''**（v3 纪律），schema 校验；
