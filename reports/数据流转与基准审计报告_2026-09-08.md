## 一、数据流转链（当前已代码固化段）

```
五源 collectors(拍平单层) → data/raw → clean/run_clean_pipeline(+sanitize) → data/cleaned(csv+jsonl, 快照日期)
  → clean_index(索引, 单一事实源)
  → recall: run_retrieval_after_checks(四门禁, 签名幂等) → scanner→build_outputs→report → recall_audit/output/
  → reconcile_clean_drift → rfn_clean_bridge + rfn_drift_state → gate_rfn_drift
  → registry/归属表(8列) → 主题归属表(3列, THEME_MAP 单源) → rfn 索引 → 40底座(base→cluster→final)/11明细/upper/clause_graph
  → report_builders(主题报告×11 + 全景/主题分类) → docs/reports/
timeliness: verification_state(SSOT) → mirror → Gate2(validity) → 底座 eff_status(归属表权威, gate_timeliness_ssot 三段断言)
internal: scan→extract→index(107)→align(T0-T10)→merged(×RFN)→drafter/gate_citations
```

断点与节点影响结论（问题 8/14/16）：
- **变化即触发（8）**：clean 快照/内容变化 → run_retrieval clean gate 签名失配自动 rerun（实证 rerun_success）；
  快照日期推进 → gate_rfn_drift FAIL 阻断并提示 reconcile（automation 每周二执行 reconcile）。时效变化 →
  state/mirror 更新 → validity 签名变化 rerun。**非仅时效触发**——clean 与索引变化均触发，链路已闭环。
- **唯一事实源影响（14）**：clean→scan_records（每次全量重建，无累加漂移）；归属表为 classifier 侧单源，
  registry 唯一写者；底座/明细/upper 均由归属表派生（幂等重建），report_builders 读底座（THEME_MAP 驱动）。
  bridge 由 reconcile 重建。节点变化不互相覆盖（reconcile C1/C2 分治，不自动覆写归属表）。
- **统一基准（16）**：各阶段均有"结果态"基准 = 归属表 1059 / 底座 40(final 1050) / 明细 11 / rfn 索引(1059) /
  recall output/（scan 4042 与 _stats/报告含 0907 快照与运行时间）/ internal index 107（sha256 游标幂等）/
  merged 107×47 RFN。**不存在仅有增量过程而无结果态**；recall 每日 rerun 与底座重建均覆盖式更新。
  建议（二期）：root `BENCHMARK.md` 登记各基准最近构建时间/快照日期（本报告先作登记依据）。
