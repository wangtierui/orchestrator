## 二、W-AH：设计、实证与诚实结论

### 1. 设计（`win_station.py`，质量优先的取舍逐条标注）
| 决策 | 取舍说明 |
|---|---|
| **用"桌面继承"而非显式 `lpDesktop`** | `STARTUPINFO.lpDesktop=NULL` 时子进程**继承父进程窗口站/桌面** ⇒ 只需助手自建站+桌面并 `SetProcessWindowStation/SetThreadDesktop`，再用普通 `subprocess` 启 LO。省去 `CreateProcessW` 手写 `STARTF_USESTDHANDLES`/句柄继承（出错面更小 ✓），代价仅一个**短命助手进程**（毫秒级）。 |
| **隔离只在短命助手里做** | `SetProcessWindowStation/SetThreadDesktop` 是**进程级/线程级** ⇒ 在长命采集进程内调用会让它**自己离开 WinSta0**（危险 ✗）⇒ 助手内隔离、调用方零影响 ✓。 |
| **fail-safe：隔离不成立就**不转换** | 非 Windows/无权限/`SetThreadDesktop` 失败 ⇒ 助手返回 `RC_NO_ISOLATION(125)`，`doc_to_docx` **放弃转换**（宁少解析 legacy 表格，绝不清空用户剪贴板 ✓）。 |
| **超时归助手所有** | 助手对子进程加 `timeout`（超时先 kill 再退出，返回 124）；父侧只兜底"助手自身卡死"（+30s）⇒ 不留孤儿、不误杀 ✓。 |
| **唯一站名 + 隐藏窗口 + 低优先级** | 每次调用独立站（零跨次状态）；沿用既有纪律（`CREATE_NO_WINDOW`+`SW_HIDE`+`BELOW_NORMAL`）✓。 |
| **可自证** | `--selftest`：助手内 `EmptyClipboard()` ⇒ 全局剪贴板序列号必须不变 ✓。 |

### 2. 实证一：窗口站隔离**对普通剪贴板操作有效** ✓
```
python -m std_lib.scraper_std.win_station --selftest
{"ok": true, "isolated": true, "winsta": "rco_lo_ws_27496_25175",
 "out": "seq_before 18180 / seq_after 18180", "delta": 0}
⇒ 私有站内清空剪贴板 ⇒ **全局 Δ=0** ✓✓（基线：无隔离时确定性 Δ≥1 ✗）
```

### 3. 实证二（**关键诚实结论**）：**LibreOffice 会自行挂回 `WinSta0`** ✗
真实 `.doc` 转换在**同一隔离**下：
```
转换输出 = True（28KB docx ✓）｜ 用时 9.4s ｜ 全局剪贴板 Δ=1 ✗
（补强护栏后复测：Δ=6 —— LO 单次转换竟清空 6 次）
```
归因：`selftest`（纯 `EmptyClipboard` 子进程）Δ=0 ✓ 而 LO 转换 Δ≠0 ✗ ⇒ **差异只在 LO 自身**：
其 VCL 层在 Windows 上做桌面/剪贴板初始化，**不受父进程窗口站约束** ✗。
⇒ **结论：窗口站是必要的第一道（隔离面），但对 LO 单独不足** ⇒ 按用户"质量优先"要求补第二道机制 ✓。

### 4. 实证三：**剪贴板保全护栏 ⇒ 用户内容永不丢失** ✓✓
新模块 `clipboard_guard.py`（设计取舍）：
| 决策 | 取舍说明 |
|---|---|
| **只保全 `CF_UNICODETEXT`/`CF_TEXT`/`CF_HDROP`** | 位图/HTML/RTF/自定义格式常为**延迟渲染**，`GetClipboardData` 会**反向请求持有者渲染**（可能唤起其 GUI/阻塞 ✗）；上述三种可确定性取字节，且覆盖办公最高频的"文字/文件"复制 ✓ |
| **未保全格式在日志明示** | 绝不静默丢 ✓（`describe()` 输出"保全 […]；未保全格式：…"） |
| **失败绝不抛出** | 护栏不可成为故障源 ✓；快照为空则不恢复（不把"空"当内容写回 ✓） |
| **异常路径同样恢复** | `except` 与 `finally` 双路径都恢复 ⇒ 护栏闭环 ✓ |
| **可关闭** | `RCO_DISABLE_CLIPBOARD_GUARD=1` ✓ |

**验收（`reports/_tmp/be1_accept.py`，自身零净影响：先保全用户剪贴板、测后恢复）**：
```
接线：窗口站 ✓ ｜ 护栏 ✓
金丝雀 RCO-CANARY-… 放入 → 真实转换（5.5s，产出 docx ✓）→ 读回
⇒ 原始 Δ=6（LO 行为，已知）｜ **护栏恢复 = True**｜**金丝雀原样存活 = True** ✓✓
```

### 5. 与用户指定方案的差异（如实说明）
用户指定 `CreateWindowStation` + **`lpDesktop`** 显式指定；本实现采用**等价且更稳的"桌面继承"路径**
（`lpDesktop=NULL` ⇒ 子进程继承父窗口站），理由见 §2.1 的取舍表。
若需**显式 `lpDesktop`**（例如未来把目标进程直接从 `WinSta0` 启到私有站），
`win_station.py` 已把站/桌创建与目标启动分成两个函数（`_helper_main` / `_spawn_isolated`），
只需在 `_spawn_isolated` 内改用 `CreateProcessW` 并填 `STARTUPINFO.lpDesktop="<站>\\<桌>"` 即可（改动面已隔离 ✓）。
