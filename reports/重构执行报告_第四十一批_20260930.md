## 二、**结论修正**：第四十批的 K5 判定过严

| | 第四十批（我的判定） | 本批（复核后） |
|---|---|---|
| 依据 | **Docker 路线**阻断（引擎未运行 + registry 不可达）→ 判"服务侧双重阻断" | 侦察指出并**实测证明**：docreader 是**纯 Python gRPC 服务**（非 Go），**支持进程内/子进程调用** → **Docker 不是唯一路线** |
| 权重 | 推测需模型权重 → 受 HF LFS 阻断影响 | **零模型权重**：全仓 grep `from_pretrained\|huggingface\|modelscope` = **0 命中** → **HF 阻断对它毫无影响** |
| 结论 | ⚠️ 部分完成 | ✅ **源码模式部署成功并已入链** |

**教训（写入本报告，供后续复用）**：「**部署受阻**」必须分清是**工具本身不可得**还是**某一种交付形态不可得** ——
Docker 拉不动 ≠ 工具不可用。否则会把"换一条路就能成"的事判成"做不了"（正是本仓"不得据网络状况把增强层整体判为不可用"的同款纪律）。

## 三、W1/W2：部署（**跨解释器隔离**）

| 项 | 决策 | 依据 |
|---|---|---|
| **解释器** | 用 `install_binary` 装 **Python 3.11.9** 建独立 venv | docreader 要求 `>=3.10.18`；其 `textract==1.5.0` **只有 sdist**（2016 年包）；3.11 贴近官方 Docker 基线（`python:3.10.18-bookworm`）。**主环境 3.13 不装它**（numpy/pandas pin 会与 torch/hanlp 拉扯） |
| **安装方式** | **只装依赖**（22 项），**不安装包本身** | ⚠️ **上游真实缺陷**：`docreader/pyproject.toml` **无 `[build-system]` / `[tool.setuptools]`**，而包目录是 **flat-layout 多顶层包**（`proto/client/models/parser/splitter/testdata`）→ `pip install -e .` 在 *Getting requirements to build editable* 阶段**必然失败**（实测：`Multiple top-level packages discovered in a flat-layout`）。上游正规用法即 **`PYTHONPATH=<WeKnora 根>` 直接 `python -m docreader.*`**（其 Dockerfile 亦如此） |
| **硬约束修正** | `grpcio` 系列下限 由上游 `>=1.78.0` **抬高到 `>=1.80.0`** | 已提交的 stub **硬编码** `GRPC_GENERATED_VERSION='1.80.0'`（`proto/docreader_pb2_grpc.py:8`）→ 版本不足会在 **import 期** RuntimeError |
| **实测结果** | ✅ `textract==1.5.0` **构建成功**（wheel 21802B）；✅ 自检 `import docreader.parser` 成功、**grpcio=1.84.0**（≥1.80 ✓） | —— |

**运行期约束（已入清单，避免下次踩）**：缺 **Java 11+** → `opendataloader` 引擎不可用（默认 `builtin` 不受影响）；
未装 `playwright` webkit → **URL 模式**不可用（本地文件解析正常）；pypdfium2 非线程安全 → 并发 PDF **实际串行**；
WeKnora 实际用 `DOCREADER_ADDR`/`DOCREADER_TRANSPORT`（本仓原登记的 `DOCREADER_ENDPOINT` 是**自有别名**）。

## 四、W3：**真实解析与增量度量**（20 份真实文档）

`python -m tools.docreader_extract --limit 20`（真实语料 `data/corpus/dept_policies/**`）：

| 指标 | docreader | 既有 6 态（`crawler_common.extract_document_text`） |

## 五、W4：接入主链（**真实调用点**，非纸面接线）

| 件 | 路径 | 职责 |
|---|---|---|
| **调用桥** | `std_lib/common_lib/docreader_bridge.py` | `available()` / `self_test()` / `parse_file()`；**跨解释器子进程**（无端口、无长驻、异常即非零退出 → **降级可观测**）。放 `std_lib/` 因有**两个消费方**（链步骤 + 将来抽取层），避免 mypy 双名解析 |
| **解析驱动** | `tools/docreader_parse_driver.py` | **仅标准库**；由 **venv 解释器**执行；把结果归一为稳定 JSON（含 `traceback_tail`，跨进程不吞错） |
| **链步骤** | `tools/docreader_extract.py`（`docreader:extract`） | 遍历语料 → 逐份解析 + **对照组（既有 6 态）** → 落**分析视图** `reports/docreader/`（路径硬校验，**绝不写事实源**） |
| **主链** | `tools/run_production_refresh.py` | `STEP_ORDER` 增 `docreader:extract`（**阶段 2.8**，紧随 `semantic:assist`）+ `_run` 调用点（**非阻断**） |
| **绑定修正** | `tools/gen_flow_map.py:MODEL_BINDINGS` | `weknora_docreader`：`step` 由 `clean`（**无该调用点** = 纸面接线）→ **`docreader:extract`**，`wired=True`，`gate=自检通过`；降级链表述同步更新（"未装" → "**已部署（源码模式 + 独立 venv）**"） |
| **清单** | `config/schema/semantic_tools.json` | `weknora_docreader` 改为 `source_tree` 探测（venv+源码+驱动齐备即可用）+ `bridge` 路径段 + `deploy`/`weights`/`runtime_constraints`/`docker_route_blocked` 如实记载；许可 `pending → verified` |

**顺带修复（我上一批的遗漏）**：`semantic:assist` 的 **PURPOSE / STEP_FAILURE 当时未真正写入**
（"是否已存在"的判断被 `MODEL_BINDINGS` 里的同名字符串**误判为已存在**而跳过）→ 本批一并补齐
（两条皆标为「**只读分析视图**」语义）。

## 七、遗留风险

| 编号 | 事项 | 建议 |
|---|---|---|
| **R-1** | docreader **未替换**既有抽取事实源 | 有意为之：docreader 只提供定位/版面增量；**替换须先度量**（本批已给出字符量与定位条数的对照基线，可直接扩展为 P/R 评估） |
| **R-2** | **Java 缺失** → `opendataloader` 引擎不可用 | 如确需该引擎（更强版面分析）须装 Java 11+（可离线解压 JDK） |
| **R-3** | **URL 模式**不可用（未装 playwright webkit） | 仅本地文件解析需要 → 非阻塞；需要时 `playwright install webkit`（约 100MB） |
| **R-4** | venv 位于 `external/`（git-ignored）→ **不随仓分发** | 换机需按 `semantic_tools.json:tools.weknora_docreader.deploy.how` 重建（venv 由 `install_binary` 提供解释器） |
| **R-5** | 并发 PDF **实际串行**（pypdfium2 全局锁） | 大批量须分批；如需并行可多进程（每进程独立 venv 调用） |
| **R-6** | 40 批的**权重通道阻断**（DeepKE/HanLP）仍未解 | 与本批**无关**（docreader 零权重）；解封路径见第四十批 §四 |
